# Программирование Проверка практической работы

Набор построен по 30 урокам вкладки «Программирование.Уроки» и заданию
практической. Оба переданных дампа содержат одинаковые исходники заготовки;
они не считаются эталоном выполненной работы. Матрица требований находится
в [requirements.md](requirements.md), полный список связей уроков и тестов —
в `requirements.json`.

## Что проверяется

Обязательная приёмка включает **320 проверок**: 179 структурных, 140
поведенческих и одну проверку трассы ошибочного диапазона. Ключ `--optional`
добавляет 6 проверок X07: 2 структурные и 4 поведенческие.

| Часть | Проверяемое поведение |
|---|---|
| Лекции | Модель исходных объектов, 7 неизменяемых методов, серверные аннотации, получение констант, время и приветствие, полная и частичная отгрузка, счёт из заказа, поступление денег из счёта |
| P01 | Выделенный метод ФИО, его вызов из ПередЗаписью, сокращение телефона и почты |
| P02 | Два переключения из обоих состояний в семи формах, согласованный текст команды, сохранение номера и даты |
| P03 | Все семь заголовков; новизна отделена от наличия номера |
| P04 | Обе ветви архивирования сделки и заказа; фактическая запись в тестовое хранилище и сохранение остальных данных |
| P05 | Получение данных компании через сервер; текст компании; все семь дней с обоими значениями рабочести; границы приветствий |
| P06 | Включительные границы, один день, две недели, високосная дата, переход года, все/ни одного рабочего дня, обратный период и кнопка расчёта |
| P07 | Заказ из сделки; расход из счёта, включая правильный перенос Контрагент → Клиент и пустой ТипОплаты |
| P08 | Только отмеченные строки, пустые и дробные данные, сохранение повторов, сумма поля Сумма; использование выделенного метода |
| P09 | Серверное создание части, реальные аргументы открытия формы, три показателя; выполнение обеих ветвей YAML-источника таблицы |
| P10 | Области видимости, аннотации и переиспользование |
| X07 | Дополнительное поступление товаров из отгрузки |

Проверки исполнения запускают **оригинальные методы студента** в Script
executor 10.0.2-1 с совместимостью 9.0. Изоляция, фиксированные часы,
типизированные тестовые ссылки и модели форм используют существующий движок.
Числовые ожидаемые результаты заданы независимо в `cases.py`;
бизнес-алгоритмы студента в Python не переводятся. Сравнение возвращённых
значений, состояний и снимков хранилища выполняется SBSL-движком.
Структурные требования и порядок вызовов проверяет отдельный валидатор.

Методы получения констант, переноса строк, создания части и три существующих
обработчика оснований защищены по последовательности токенов сигнатуры и
инструкций. Комментарии и пробелы игнорируются. Методы, которые расширяются
по заданию, проверяются по поведению и связям, без сравнения текста их тел
с эталоном.

## Запуск приёмки

### Через общий CLI и HTTP-сервис

Соберите критерии и синтетический эталон из корня репозитория.

```bash
python tools/ci/package_programming.py
```

Полный набор проверок задаётся файлом
`output/programming/Критерии_Программирование.yaml` или одноимённым ZIP
(внутри ZIP `assignment.yaml` находится в корне). Он включает все 320
обязательных проверок. Вариант `_с_дополнительным` включает 326 проверок.
Для сервиса отправляются два файла: дамп студента и этот файл критериев.
Используйте режим `isolated`.

```bash
bin/element-test test --project '/путь/к/работе.xdump' \
  --assignment 'output/programming/Критерии_Программирование.yaml' \
  --output result/programming-student
```

`result.json`, `grading.json`, `execution-plans.json`, `runtime-evidence.json`
используют стандартный транспорт сервиса. В полном профиле каждый критерий
имеет один балл, сравнение и начисление всех баллов выполняет SBSL.
Обязательная приёмка: `passed`, `score=320`, `maxScore=320`,
`unavailablePoints=0`. Структурные наблюдения явно помечены
`observationKind: structural`, проверка трассы — `trace`.

В YAML находятся критерии, ожидаемые результаты и правила разрешения имён.
Описание формата есть в [инструкции по интеграции](../../docs/autocheck-integration.md).
При ручной карте имён добавьте `executionOptions.aliases` со структурой из
`aliases.example.json`. Карта сохраняется в техническом артефакте плана.
Ранее выпущенные ZIP с `profile` продолжают работать.
Сервер выполняет runtime-проверки последовательно, по 30 секунд максимум
каждая, в пределах общего ограничения времени одной работы.

### Отдельный диагностический запуск

Из корня репозитория движка:

```bash
.venv/bin/python assignments/programming-practice/check.py \
  --project '/путь/к/работе.xdump' \
  --output result/programming-student
```

Для выполненного дополнительного пункта добавьте `--optional`.

Результаты:

- `report.html` — общий отчёт с точными ID требований, expected и actual;
- `result.json` — статусы всех проверок и хэши исходников;
- `runtime-evidence.json` — входы, фактические результаты и трассы;
- `resolved-aliases.json` — применённая карта имён;
- `source-adaptations.json` — журнал технической адаптации перегрузок.

`status: passed` требует прохождения **всех** проверок выбранного охвата.
При недоступном Docker или неподдержанной конструкции получается
`incomplete`, а не успешная приёмка. Отсутствующий обязательный метод —
`FAIL / required_method_missing`, без утверждения, что его код исполнялся.
Коды завершения: 0 — приёмка пройдена; 1 — работа не соответствует;
2 — неполный запуск или недоступное исполнение.

`--only 'P06|P08'` полезен для исправления отдельных блоков. Любой такой
запуск помечается `partial: true` и не даёт полного `passed`.

Нужны зависимости этого репозитория, Java 17, локальный дистрибутив Script,
запущенный Docker и образ из `config/runtimes.json`. Приёмка не выполняет
деплой, не открывает учебное приложение и не изменяет исходный архив.
Одновременно выполняются два тестовых контейнера.

## Имена и допустимые варианты решения

Однозначные формы распознаются по `ФормаОбъекта<Документ.Объект>`, некоторые
чистые методы — по сигнатуре. Имена локальных переменных не оцениваются.
Для других переименований используйте `--aliases aliases.json`.
Пример карты находится в `aliases.example.json`.

`owners` сопоставляет полное имя канонического модуля/формы с фактическим.
`names` задаёт соответствия методов, новых свойств и компонентов внутри
канонического модуля. Карта не правит исходники. Разные назначения нельзя
объединять в одно имя; поля `expected`, веса и ответы в карте запрещены.
Исходные имена объектов данных и реквизитов курса сохраняются.
Форматы выводимых строк опубликованы в задании, поэтому у студента нет
скрытых требований к пробелам, ключам и подписям.

В лекционной заготовке есть локальная перегрузка метода времени по числу
параметров. Перед исполнением такой случай технически понижается в отдельные
имена в **копии** исходников; тела, условия, литералы и аргументы сохраняются.
Журнал содержит диапазоны, старые/новые имена и SHA-256. Перегрузки одинаковой
арности, callbacks и динамическое разрешение перегрузок этот адаптер не
поддерживает; они честно остаются `UNSUPPORTED`. Неразрешённое имя не
подменяется готовой реализацией.

## Эталон для преподавателя

`tests/corpus/programming/reference/` — отдельное решение, собранное поверх
лекционной заготовки по требованиям задания. Для части методов использованы
уже имеющиеся локальные примеры проекта; добавления следующих тем исключены.
Эталон предназначен для проверки тестов и не является требованием к тексту
студенческого кода. Входные хэши и состав решения записаны в `provenance.json`.

```bash
.venv/bin/python assignments/programming-practice/check.py \
  --project tests/corpus/programming/reference \
  --output result/programming-acceptance --optional

ELEMENT_TEST_DOCKER_TESTS=1 .venv/bin/python -m unittest discover \
  -s tests -p 'test_programming_practice.py' -v
```

Самопроверка подтверждает принятие переименованных методов и формы,
отсутствие expected в сгенерированном коде, защиту карты имён и обнаружение
восьми компилируемых ошибок: пересчёт суммы через цену, подсчёт количества
вместо строк, исключение конечной даты, игнорирование настроек дней, отсутствие
сокращения телефона, потеря основания, неверный перенос суммы и отсутствие
записи при архивировании.

`assignment.yaml` материализует поведенческие сценарии для просмотра и
стандартного движка. Отдельный запуск этого YAML не выполняет все структурные
проверки, разрешение имён и проверку трассы. Полный вход — встроенный профиль
выше либо диагностический `check.py`. ZIP `Тесты_Программирование.zip`
предназначен для разработчика; для загрузки в сервис используется ZIP
`Критерии_Программирование.zip`.

## Практические границы

Проверяются данные и код в ограниченных адаптерах Script. Настоящий DOM,
внешний вид, публикация в IDE и использование отладчика студентом не
подтверждаются этим набором. P11 требует демонстрации преподавателю.
Платформенная автонумерация и весь жизненный цикл UI не эмулируются.
Запись и открытие форм проверяются через объявленные эффекты и снимки
тестового хранилища, без обращения к рабочим данным пользователя.

Неизменённая исходная заготовка ожидаемо не проходит практическую. В её
диагностическом прогоне отдельно отмечена граница адаптера для старой команды
закрытия формы; она не превращена в PASS. Итоговый вариант практической,
согласно уточнённому заданию, оставляет форму открытой после архивирования.
