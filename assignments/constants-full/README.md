Тесты проверяют соответствие конфигурации предоставленному дампу. Ожидания

У всех трёх объектов проверяются вид `НаборКонстант`, пространство имён
`Администрирование`, видимость `ВПодсистеме` и присутствие соответствующего
модуля. Проверки полей используют именно `collection: Константы`:
перенос объявлений в `Реквизиты` не засчитывается.

Девять значений `Ложь` проверяются отдельно от существования константы:
удаление явного значения, подмена на `Истина` или число `0` не соответствует
эталону. Для дней недели не добавляются предположения о пятидневке:
в переданном дампе все семь значений по умолчанию ложные.

## Строгое соответствие

Шесть дополнительных проверок сравнивают проект, подсистемы, объекты,
модули, служебные YAML и диагностику модели. Проверяется также отсутствие
лишних объектов, полей, констант, колонок, значений перечислений, настроек
и исполняемого кода в исходно пустых модулях. Дубликаты именованных
объявлений не теряются при сравнении.

UUID `Ид`, комментарии, пробельное оформление модулей и порядок именованных
деклараций не учитываются. Порядок и повторы обычных списков (`Импорт`,
`Использование`, `СерииНумерации`) сравниваются с эталоном.

По согласованному охвату интерфейс исключён: нет браузерных сценариев;
свойства `Интерфейс` исключены из критериев и строгого сравнения.
В дампе нет исполняемых методов, запросов и регистров. Поэтому покрытие
структурное: оно не подтверждает исполнение ограничений платформой,
сохранение значений констант в работающем приложении или поведение его
пользовательских данных. Ветвевое runtime-покрытие здесь неприменимо.

## Запуск

Из корня репозитория:

```bash
.venv/bin/python assignments/constants-full/check_full.py \
  --project '/path/to/dump_practice.xdump' \
  --output result/constants-full
```

Для другой работы замените `--project`. Поддерживаются XDUMP, архив и
каталог; при необходимости добавьте `--project-name Движок::Движок`.

- `result/constants-full/report.html` — общий отчёт;
- `result/constants-full/full-result.json` — итог и строгие расхождения;
- `result/constants-full/structural/` — баллы и стандартные артефакты движка.

Полный успех — только `status: passed` в `full-result.json`. Одних 272/272
недостаточно: лишняя константа сохраняет положительные критерии, но
проваливает строгое сравнение. Строгие разделы баллов не добавляют.
Коды завершения: 0 — успех; 1 — расхождения; 2 — ошибка входа или
недоступное исполнение. Исходный дамп не изменяется.

Обычный `bin/element-test test --assignment assignments/constants-full`
выполняет только структурные критерии. Для полного соответствия используйте
`check_full.py`. Нужны зависимости репозитория, Java 17, Script executor
и общий модуль `assignments/catalogs-full/check_full.py`. Docker не нужен.

## Проверка тестов

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_constants_full.py' -v
.venv/bin/python -m unittest discover -s tests -p 'test_table_sections_full.py' -v
```

Новый набор наследует общие проверки из `tests/test_table_sections_full.py`.
Проверены все 456 скалярных ожиданий, удаление каждого свойства/элемента,
лишние настройки, дубликаты, типы, nullable, различие булевых и чисел,
допустимые изменения UUID/порядка/комментариев, исключение интерфейса,
отчёты, коды завершения и сохранность входного проекта.

В реальном SBSL-движке проверены **350 изолированных мутаций**: по одной
ошибке для каждого из 272 критериев и 78 ошибок вложенных настроек.
Каждая получила `FAIL` и ноль баллов. Отдельные сквозные сценарии проверяют
лишнюю константу и отсутствие явного значения по умолчанию.

Результат предоставленного дампа: **272/272**, все шесть строгих разделов
`PASS`, недоступных критериев нет. Самопроверка нового набора: **14/14**.
