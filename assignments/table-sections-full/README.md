режим совместимости **9.0**. SHA-256 исходного файла:
`c3fbc3c4a866305fc819f6862384cc568183d849e8ac0423a817032c9776e295`.

Это проверка соответствия конфигурации переданному дампу. Отдельного ТЗ на

критерии — в `assignment.yaml`; при запуске на другой работе они не создаются
и не обновляются из проверяемых исходников.

## Строгое соответствие и исключения

Шесть проверок охватывают проект, подсистемы, объекты, модули, служебные
YAML и диагностику модели. Они обнаруживают также лишние объекты,
реквизиты, табличные части, колонки, значения перечислений, настройки,
повторы именованных элементов и исполняемый код в исходно пустых модулях.

Не учитываются UUID `Ид`, комментарии и пробельное оформление модулей,
порядок ключей и именованных деклараций. Обычные списки, включая `Импорт`,
`Использование` и `СерииНумерации`, сохраняют порядок и повторы эталона.
Отсутствие свойства отличается от явно заданного значения; булево отличается
от числа.

По запросу пользователя **интерфейс не проверяется**: нет браузерных тестов,
проверок отображения или навигации; свойства `Интерфейс` исключены и из
структурных критериев, и из строгого сравнения.

В дампе нет исполняемых методов, обработчиков проведения, запросов и регистров.
Runtime-сценарии и процент покрытия ветвей к нему неприменимы. Проверяются
декларации ограничений, а не их исполнение платформой. Пользовательские данные,
учётные записи и служебные данные архива не входят в тестирование конфигурации.
Проверка не подтверждает работу платформенной автонумерации или расчёт
`Количество × Цена`: такой бизнес-логики в исходниках нет.

## Запуск

Из корня этого репозитория:

```bash
.venv/bin/python assignments/table-sections-full/check_full.py \
  --project '/path/to/dump_practice.xdump' \
  --output result/table-sections-full
```

Для другой работы замените `--project`; принимаются XDUMP, архив или каталог.
При необходимости добавьте `--project-name Движок::Движок`.

Результаты:

- `result/table-sections-full/report.html` — общий отчёт;
- `result/table-sections-full/full-result.json` — итог и строгие расхождения;
- `result/table-sections-full/structural/` — баллы и стандартные артефакты движка.

Полный успех — `status: passed` в `full-result.json`. Одних **241/241**
недостаточно: например, лишняя колонка оставляет все положительные критерии
выполненными, но проваливает строгое сравнение. Строгие проверки баллов
не добавляют. Коды завершения: 0 — успех; 1 — расхождения;
2 — некорректный вход или недоступное исполнение.

Исходный дамп не изменяется, приложение не разворачивается. Нужны зависимости
этого репозитория, Java 17 и локальный Script executor. Docker для этих
структурных проверок не требуется. Общий код сравнения используется из
`assignments/catalogs-full/check_full.py`; сохраните его вместе с заданием.

Обычный запуск `bin/element-test test --assignment assignments/table-sections-full`
выполняет только 241 структурный критерий. Для полного соответствия, в том
числе обнаружения лишних элементов, запускайте **`check_full.py`**.
