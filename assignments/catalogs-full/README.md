# Справочники — полное соответствие

Эталон: `03. Справочники/dump_practice.xdump`, проект `Движок`,
режим совместимости 9.0. Требования зафиксированы в `assignment.yaml`
и `reference.json`: при проверке другой работы эталон заново не строится.

## Что проверяется

51 структурный критерий на 51 балл:

- Корневой модуль проекта и модули всех шести справочников.
- Наличие справочников в нужных подсистемах и их область видимости `ВПодсистеме`.
- Иерархия `Контрагенты` и `Номенклатура`.
- Все 18 явно объявленных реквизитов, их типы и все заданные свойства.

| Справочник | Реквизиты и настройки эталона |
|---|---|
| `CRM::Контрагенты` | `Наименование`; `ИНН`: Число, 10 целых разрядов; `КПП`: Число, 9 целых разрядов; `ТипКонтрагента`: Строка |
| `CRM::ФизическиеЛица` | `Фамилия` и `Имя`: Строка, незаполненное значение `ЗапретитьВсегда`; `Отчество`: Строка, незаполненное значение `Разрешить`; `Телефон` и `Почта`: Строка |
| `Товары::ЕдиницыИзмерения` | `Наименование`; `ТипЕдиницыИзмерения`: Строка |
| `Товары::Номенклатура` | `Наименование`; `Цена`: Число, 10 целых и 2 дробных разряда, минимум 0, максимум 1 000 000 000, значение по умолчанию 0; `ЕдиницаИзмерения`: `ЕдиницыИзмерения.Ссылка?`, незаполненное значение `ЗапретитьВсегда` |
| `Товары::Склады` | `Наименование`; `АдресСклада`: Строка |
| `Финансы::БанковскийСчет` | `Наименование`; `НомерСчета`: Число, 20 целых разрядов |

Для `Наименование` тип не задан в YAML эталона; критерий проверяет наличие
стандартного реквизита. Для `ФизическиеЛица` в эталоне `Наименование`
не объявлено. Обязательность заполнения ссылки проверяется отдельно
от nullable-типа: оба свойства сохранены как в дампе.

Ещё шесть строгих проверок сравнивают:

1. Все метаданные `Проект.yaml`, включая имя и поставщика `Движок`, версию,
   представления, языки и режим совместимости.
2. Точный состав подсистем `CRM`, `Товары`, `Финансы` и их метаданные.
3. Точный состав объектов, реквизитов и всех свойств: лишние объекты,
   реквизиты, табличные части или настройки дают `FAIL`.
4. Точный состав семи модулей и отсутствие исполняемого кода:
   в эталоне модули пустые или содержат только комментарии.
5. Отсутствие дополнительных служебных YAML метаданных.
6. Отсутствие диагностик модели.

UUID (`Ид`), порядок ключей, объектов и реквизитов, отступы и комментарии
в модулях не учитываются. Остальные явно заданные метаданные сравниваются
строго; отсутствие настройки и явно записанное значение различаются.
Пустые файлы `Подсистема.yaml` принимаются, как в эталоне и загрузчике движка.

Проверяется конфигурация из дампа. Данные приложения, запуск приложения,
ввод через браузер и платформенное поведение не проверяются.
В дампе нет реализованной бизнес-логики для runtime-проверок.

## Полная проверка

Из корня репозитория:

```bash
.venv/bin/python assignments/catalogs-full/check_full.py \
  --project '/path/to/dump_practice.xdump' \
  --output result/catalogs-full
```

Для другой работы замените `--project`. При неоднозначном выборе проекта
можно передать `--project-name Поставщик::Имя`.

- `result/catalogs-full/report.html` — общий отчёт со строгими расхождениями.
- `result/catalogs-full/full-result.json` — общий машиночитаемый результат.
- `result/catalogs-full/structural/` — обычные отчёты и пакет оценки движка.

Полное соответствие подтверждается только при `status: passed` в
`full-result.json`. Структурные баллы отдельно не означают полного
соответствия: например, лишний реквизит оставляет 51/51, но строгая
проверка отклоняет работу. Строгие проверки не добавляют баллов.
Код завершения: 0 — полное соответствие, 1 — расхождения,
2 — ошибка входа или недоступное исполнение.

## Только критерии стандартного движка

```bash
ELEMENT_TEST_PYTHON=.venv/bin/python bin/element-test test \
  --project '/путь/к/работе.xdump' \
  --assignment assignments/catalogs-full \
  --output result/catalogs-structural
```

Этот вариант проверяет 51 критерий и совместим с обычным форматом заданий
движка. Проверка `reference.json` запускается только через `check_full.py`;
обычный движок и его сервис автоматически её не выполняют.

## Проверка самих тестов

```bash
.venv/bin/python -m unittest discover -s tests -p test_catalogs_full.py -v
```

Регрессия проверяет каждый из 51 критериев на отдельной ошибке, строгое
сравнение всех листовых значений эталона, лишние/пропущенные сущности и
допустимые отличия UUID, порядка объявления и комментариев.
