# E03 и E04 — фильтры регистров и типизированная генерация

Реализовано 14 октября 2026 года. Исходный XBSL исполняется в Script
10.0.2-1; Python строит типизированные входы и адаптеры. Независимое отношение
и решение PASS/FAIL остаются в `src/ДвижокТестирования.sbsl`.

## E03: явный предикат регистра

Для независимого РС поддержаны `ПериодВходитВОсновнойФильтр: Истина`,
именованные подмножества полей, прямое чтение/присваивание полей фильтра и
явное `Фильтр.Установить()` для всей таблицы. Период имеет тип из метаданных:
Дата для День, ДатаВремя для Секунда и Момент для Момент. Чтение последних
двух периодичностей сохраняет требование `storage.lifecycle: true`.

```xbsl
знч Набор = новый История.НаборЗаписей()
Набор.Фильтр.Установить(Период = новый Дата(2026, 10, 14))
Набор.Фильтр.Товар = Товар
Набор.Фильтр.Поставщик = Неопределено
Набор.Прочитать()
```

`Установить` заменяет предикат целиком. Прямое присваивание добавляет или
заменяет одно ограничение; явно заданный NULL сохраняется в маске. Значения
фиксируются снимком при установке; чтение ссылки из фильтра даёт отдельную
копию. Доступ через доказанный локальный псевдоним фильтра также поддержан.
Чтение ещё не заданного поля отклоняется. Составные присваивания `+=`/`??=`
пока недоступны. Это зафиксированные правила адаптера: новая native семантика
прямых полей не заявляется; версионная справка фильтра оказалась недоступна.

Фильтр никогда не устанавливается автоматически. Без `Установить` или
прямого присваивания чтение/запись отказывают. Неизвестные поля, повторные
аргументы и доказанно неверные типы отклоняются при планировании. Пустой
teacher-фильтр задаётся явно как `storage.initialRegisters[].filter: {}`;
отсутствующее/неверное описание не превращается в очистку всей таблицы.

Физические группы по-прежнему используют все измерения, идентичность строки —
все измерения и период. Период в предикате не становится частью ключа группы.
Чтение проверяет предикат по общей истории; замещение сохраняет строки вне
него; добавление сохраняет прежние строки и проверяет полные ключи. Отказ
обработчика после записи откатывает всю операцию. РН сохраняет полный фильтр
регистратора; прямое присваивание регистратора поддержано, пустой фильтр РН
отклоняется. Подчинённый регистратору РС остаётся отдельной задачей E10.

## E04: домены, преобразование, уменьшение и replay

Прежний целочисленный вход и SplitMix64 сохранены. Расширения схемы v1:

```yaml
domains:
  - {type: Число, min: {decimal: '-0.05'}, max: {decimal: '1.25'}, scale: 2}
  - {type: Дата, min: '2024-02-28', max: '2024-03-02'}
  - {type: ДатаВремя, min: '2026-12-31T23:59:59', max: '2027-01-01T00:00:01'}
  - {type: Момент, values: ['2026-10-14T00:00:00.123Z']}
  - {type: Учет::Статус, values: [Открыт, Закрыт]}
  - type: Учет::Товар.Ссылка?
    values: [null, {Идентификатор: '12345678-1234-4234-8234-123456789abc'}]
  - type: Учет::Карточка.Объект
    fields:
      Количество: {type: Число, min: 0, max: 10, scale: 2}
      Дата: {type: Дата, min: '2026-10-01', max: '2026-10-14'}
```

Число ограничено ±1000000. Диапазон с `scale: 0..12` задаёт целочисленную
сетку десятичных долей; без scale сохраняется шаг 1. Границы должны лежать
на сетке. `values` допускает обычные JSON-дроби и `{decimal: '...'}` до
24 знаков после точки. Последняя форма нужна для точного авторского числа:
дробные результаты и вложенные снимки передаются таким же тегом, без
промежуточного Python float. Объект с единственным полем `decimal` зарезервирован
этим транспортом. SBSL независимо восстанавливает Число перед сравнением.

Дата использует `YYYY-MM-DD`, ДатаВремя — `YYYY-MM-DDTHH:MM:SS` без зоны,
Момент — UTC с `Z` и максимум тремя знаками миллисекунд (проверено Script).
Диапазоны дат имеют шаг день, времени — секунду с одинаковой миллисекундной
частью границ. Проверяются календарная корректность, порядок, тип и сетка.
Для сравнения дат по значению в отношении применяются унарные `date`,
`dateTime`, `instant`; затем работают `equal/notEqual` и все четыре сравнения.
Прямое сравнение строк сохраняет сравнение их сериализованной формы.

Enum и nominal-ссылки используют `values`; составной проектный тип — `values`
или рекурсивные `fields`. Поля и типы сверяются с метаданными, все значения
проверяются до первого исполнения, включая не выбранные seed. Неизвестный
владелец, неверный enum, чужое поле и несовпадение с сигнатурой дают
`invalid_test`. Nullable, массивы и вложенные объекты комбинируются в пределах
прежнего бюджета глубины/размера.

В `transform` добавлены `get`, `at`, `set` (объект, имя существующего поля,
новое значение), `dateAddDays` и `dateAddSeconds`. Арифметика использует точные
десятичные значения. Преобразование создаёт отдельные копии и проверяет
результат по исходному домену. Эти же операции, а также `number`, доступны
в независимом SBSL-отношении. Секундный сдвиг Дата недопустим.

Числа уменьшаются по сетке к допустимому нулю; даты — к нижней границе,
с промежуточными соседями; поля объекта уменьшаются рекурсивно. `values`
уменьшается по объявленному порядку. Каждый кандидат и его transform остаются
в домене. Решение о сохранении FAIL принимает SBSL; сохраняются seed,
sourceHash, исходный/уменьшенный случай, бюджет и готовый replayCheck.
Недоступное или неполное исполнение не получает PASS. Последовательности
операций и генеративный PostgreSQL остаются E05.

## Проверки

`tests/test_engine_e03_e04.py` содержит переносимые исходники с разными
namespace, проверки NULL/пропуска, периода, явного пустого фильтра,
замещения/добавления/очистки, истории и отката, а также seed/replay,
точных дробей, дат, enum, ссылок, объектов и независимого SBSL-отношения.
Backend-проверка использует memory и PostgreSQL; отдельный SELECT
`PostgresSession.audit` сравнивается с авторскими строками.

```sh
python3 -m unittest discover -s tests -p test_engine_e03_e04.py -v
ELEMENT_TEST_DOCKER_TESTS=1 python3 -m unittest discover -s tests \
  -p test_engine_e03_e04.py -k ExtendedBackendTest -v
```

Проверяются затронутые контракты №52/53, record sets, generated types и
E01/E02. Полная регрессия остановлена по просьбе пользователя; её результат
не заявляется.
