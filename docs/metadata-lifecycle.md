# Метаданные и lifecycle записи — контракт №50

Реализован общий адаптер для `runtime` и `runtime.interface`. Вычисления
обработчиков выполняются исходным Script-кодом. Структурные `element`/`field`
проверки деклараций сохраняют отдельный смысл: совпадение YAML не доказывает
исполнение ограничения при записи.

## Включение

```yaml
type: runtime
target: {module: Operations, namespace: Data, method: Save}
args: [one, 5]
storage:
  backend: memory
  lifecycle: true
  registers: [Data::Balances, Data::History]
captureException: true
```

`storage.lifecycle` — строгое Булево, по умолчанию `false`. Полная
[схема storage v1](storage-options-v1.schema.json) проверяется общим валидатором.
Режим без флага сохраняет прежние правила хранения. Объявленные YAML
`ПараметрыЗаписи: [{Имя, Тип, ...}]` теперь порождают тип параметров и в прежнем
режиме. `Записать()` создаёт новый экземпляр параметров для каждого вызова;
`Записать(новый Owner.ПараметрыЗаписи(...))` передаёт один экземпляр обоим
исходным обработчикам. Неизвестные поля и неверные типы входа — ошибка задания.

Идентичность поля определяется owner/namespace/исходным YAML, включая коллизии
кратких имён. `metadataLifecycle` в IR содержит sourceHash, путь и диапазон
декларации ограничения, объявленные параметры, порядок и границу адаптера.
Ожидаемого ответа в плане нет. Подготовка/генерация не объявляются исполнением
этого исходника; `execution` остаётся `not-checked` без отдельного свидетельства.

## Порядок и ограничения

Запись справочника/документа: сохранить снимок всей сессии → получить независимый
`До` → исходный `ПередЗаписью` → заполнить пустой код/номер → нормализовать и
проверить реквизиты и строки ТЧ → сохранить объект → исходный `ПослеЗаписи` →
завершить запись. Для создания `До` содержит значения объекта до вызова
обработчика; для обновления — прежние сохранённые значения. Табличные части
десериализуются заново и не разделяют изменяемые строки с текущим объектом.
Оба обработчика получают один `До` и одни параметры. Изменение текущего
объекта после сохранения само по себе не вызывает повторную запись.
Основание базового контракта `До`: [официальная справка объекта](https://1cmycloud.com/console/help/esb/9.1/docs/stdlib/esb/xbsl/DeveloperName/ProjectName/SubsystemName/CatalogName.Object_ru/).
Профиль исходников остаётся 9.0; точный порядок нормализации/нумерации ниже
является явно объявленным адаптером, без заявления о полной native эквивалентности.

| Декларация | Поведение адаптера |
|---|---|
| `НезаполненноеЗначение: ЗапретитьВсегда` | Запрещает NULL, пустую строку и пустую ссылку (пустой string-ID или нулевой UUID). Значения 0/false и допустимый enum остаются значениями своего типа |
| Минимальное/МаксимальноеЗначение | Включительные числовые границы после округления |
| ДлинаДробнойЧасти | Native `Округлить(scale)`, 0..38; лишние разряды округляются |
| ДлинаЦелойЧасти | 0..38; после округления запрещает абсолютное значение ≥ 10^precision |
| Длина/МаксимальнаяДлина | Максимум символов строки, 1..1000000; противоречащие декларации недоступны |
| Уникальность | Объявленный реквизит объекта Строка/Число; сравнение с сохранёнными объектами того же owner, исключая собственный ID; NULL не участвует |
| Enum/nullable/scalar union | Общие номинальные типы, объявленные варианты и defaults; вход `{type, value}` для неоднозначного union. Nullable union записывается как `Число\|Строка\|?` |
| ТЧ, измерения и ресурсы | Те же поддержанные скалярные ограничения по YAML; набор проверяется до сохранения |

Отказ ограничения наблюдается как `ИсключениеНедопустимоеСостояние` с сообщением
`metadata:<поле>:<правило>`. В обычном runtime `captureException` сохраняет
прежнюю оболочку `{result, exception}`. Неподдержанная декларация/API остаётся
`UNSUPPORTED`; инфраструктурные ошибки не становятся ожидаемым отказом.
Сравнение и баллы выполняются SBSL по независимому авторскому `expected`.

## Нумерация

Поддержаны явно объявленные `Автонумерация` у `Код`/`Номер` типов Строка/Число:
`Использовать`, `ДлинаНумерации` (1..38), фиксированные Префикс/Постфикс,
Формат.ДлинаПрефикса/ДлинаПостфикса (-1 или точная длина), разделители.
Строковый номер заполняется нулями до ширины числовой части.
Непустой номер сохраняется. Следующее значение получается из фактических
сохранённых номеров подходящего формата, включая начальные fixtures.
Переполнение ширины даёт наблюдаемый отказ.

Непериодический/Год/Месяц/День используют объявленную `Дата: Дата|ДатаВремя`.
Для периода сравниваются соответствующие календарные части; уникальность
номера учитывает этот период. Сквозная серия и серии Префикс/Постфикс работают
с фиксированными значениями формата; серия Владелец сравнивает сериализованную
объявленную ссылку. Настройка серии без владельца недоступна.
После отказа счётчик не расходуется: вычисление зависит от сохранённого состояния.
Это последовательная изолированная модель, без конкурентного выделения номеров.
Динамические префиксы/постфиксы через параметры и произвольный контроль формата
требуют отдельного расширения. Необъявленные системные defaults не достраиваются.

## Атомарность, регистры и константы

Снимок каждой записи включает всю сессию. Отказ в любом обработчике восстанавливает
объект, вложенные записи объектов, регистры и константы. Снимки вложенных записей
независимы. Публикация SQL из внутреннего source commit откладывается, пока
выполняется запись. Мутации живого экземпляра сохраняются как состояние попытки;
откат относится к хранилищу. Свежая загрузка снова читает сохранённый снимок.
Внешняя `storage.transaction` для обычного runtime сохраняет свою прежнюю границу.

Накопительные регистры заменяют/дописывают реальные строки по полному фильтру
регистратора. Информационные — по всем измерениям; комбинации измерений
изолированы. `Записать(Ложь)` дописывает историю, `Записать()` замещает набор,
пустой набор очищает выбранный фильтр. Ключ включает все измерения и период.
Дубликат запрещён после нормализации; снимок возвращает прежнее состояние.
`Прочитать()` поддерживает Непериодический, День (`Дата`), Секунда (`ДатаВремя`)
и Момент (`Момент`) и возвращает свежие строки. Тип регистратора- union продолжает
восстанавливаться по полному типизированному фильтру.

Цикл объект → регистр → ссылка регистратора допустим для metadata lifecycle.
Генератор объединяет циклические metadata-модули Script, добавляя технический
префикс владельца к типам/менеджерам; исходные символы, строки, свойства и
публичные type identities сохраняются. `metadataCompilation` фиксирует
компоновку. Циклы собственных проектных модулей сохраняют прежний отказ.

Запись формы констант использует общий `ТестСессия` вместо отдельного файла UI:
проверка ограничений → сохранение → независимые snapshots/constants/storage.
Тот же снимок публикуется в PostgreSQL и читается доверенным SQL-аудитом.
Начальные `storage.initial`/`initialRegisters` и `constants` остаются fixtures
преподавателя, не запуском исходного lifecycle; `queryActions.write` также
задаёт fixture-состояние. Эти входы нельзя выдавать за native запись объекта.

## Декларативная форма

`runtime.interface` + `storage.lifecycle: true` + `formEffects.write: true`
позволяет `writeInterface` без исходного метода формы, с подготовкой полного
замыкания исходных объектных hooks. Для объекта обязателен `idType: Ууид` и
прежний `lifecycle.isNew`; существующий context совпадает с начальным storage.

Каждое `writeInterface` имеет outcome applied/blocked/rejected.
`observation.exception` равно NULL при успешной записи или содержит type/message
при подтверждённом бизнес-отказе. Следующее действие может наблюдать прежнее
сохранение и текущее несохранённое значение. Эта оболочка включается только
с новым lifecycle-флагом. Внешняя transaction для interface пока недоступна.

## Остаток и проверка

Расширения: [частичные фильтры независимого РС, №53](partial-information-register-filters.md)
и [тегированное хранение ссылочных union, №54](tagged-reference-union-storage.md).

Обработчики самого набора реализованы в [E02](engine-extensions-e01-e02.md).

За границей: пустые фильтры набора,
подчинённый РС 10.0, произвольные объектные union, динамический формат номера,
native блокировки/конкурентность, удаление объектов и полная платформенная
валидация всех YAML-свойств. Неподдержанные ограничения получают точный отказ
подготовки, без частичного PASS.

Проверки механизма: `tests/test_metadata_lifecycle.py`. Они используют небольшие
переносимые исходники с независимыми ожиданиями, не задания финального дампа.
[Отчёт №50](tasks/050-metadata-lifecycle-and-storage.md),
[измерения](test-type-stage-050-measurements.json).

```bash
ELEMENT_TEST_DOCKER_TESTS=1 ELEMENT_TEST_INTEGRATION_TESTS=1 \
  PYTHONPATH=tests python3 -m unittest test_metadata_lifecycle -v
```

PostgreSQL одноразовый, credentials создаются только в окружении теста.
Полная регрессия, массовый discovery/бизнес-сценарии дампа и прежние validate
остаются nightly; расписание CI и исходные архивы не меняются.
