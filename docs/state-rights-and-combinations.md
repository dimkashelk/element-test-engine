# Предикаты, состояние, доступ и сочетания — №45

Реализовано расширение общего pipeline XBQL → типизированный AST → Script →
storage → SBSL. Python строит типы и код, а не вычисляет строки запросов.
Ни названия проектов, ни готовые query rows/expected не определяют исполнение.
Полный контракт каталога ещё не закрыт: платформенные ограничения сохраняются
как UNSUPPORTED и недоступные баллы, а не как успешные проверки.

## Исполняемый контракт

- `МЕЖДУ` включает обе границы; обратный диапазон пуст. Используются общие
  сравнения и трёхзначная логика JOIN/NULL. Поддержаны списки, массивы и
  некоррелированные подзапросы `В/НЕ В`, включая UNION.
- `ПОДОБНО/НЕ ПОДОБНО`: сравнение без учёта регистра, `%`, `_`, непустые
  классы `[]/[^]`, экранирование и `СПЕЦСИМВОЛ`. Шаблон/спецсимвол —
  константы или типизированные параметры. Проверка некорректного шаблона
  выполняется и при пустом источнике. В Script используется конечный
  алгоритм с массивами достижимости; поведение не зависит от Python/SQL regex.
- `ОТЛИЧАЕТСЯ ОТ/НЕ ОТЛИЧАЕТСЯ ОТ` — двухзначное сравнение NULL и обычных
  значений, включая разные типы литералов. Nullable-поля используют прежнее
  различие между отсутствующей строкой JOIN (`NULL`) и `Неопределено`.
- `СУЩЕСТВУЕТ/НЕ СУЩЕСТВУЕТ` проверяет наличие строк, включая UNION и
  безымянную числовую проекцию во внутреннем cardinality-запросе. Корреляция
  разрешается по явному внешнему псевдониму и точным типам. Внешние поля
  передаются из текущей комбинации строк в момент исполнения подзапроса.
  Внутренние параметры не становятся XBSL-входами основного запроса;
  затенение внутренним псевдонимом и совпадение имён параметров защищены.
- `В ИЕРАРХИИ/НЕ В ИЕРАРХИИ` для обычного иерархического справочника
  использует объявленное `Иерархический: Истина` и системный `Родитель`.
  Проверяются сам элемент и все предки; посещённые ID завершают цикл.
  История читается из текущего storage. Для типа без таблицы иерархии
  справка определяет проверку самого значения. Дополнительные/явно выбранные
  таблицы иерархий, union типов и nullable `Неопределено` пока недоступны.
- `ВСТАВИТЬ` во временную таблицу принимает значения или SELECT с
  позиционным сопоставлением полей. Типы, обязательные и nullable-поля,
  повторяющиеся имена проверяются до исполнения. `ИЗМЕНИТЬ/УДАЛИТЬ`
  используют условия и возвращают строку `КоличествоЗаписей`.
  Присваивания вычисляются по исходной строке и только при выполнении условия.
  Дубликаты остаются отдельными строками. Контекст временных таблиц создаётся
  заново при каждом `Выполнить`; DML не пишет объектные таблицы платформы.
- `queryAccess: {mode: executor-fixture, sources: ...}` задаёт права чтения
  точного владельца и видимые ID. Неуказанный источник запрещён. Фильтрация
  выполняется при загрузке источника до JOIN/UNION/агрегатов; аудит сохраняет
  полное состояние. Эта явная модель не исполняет native КонтрольДоступа,
  аутентификацию, выдачу ключей или RLS-обработчики.

Сочетания проверяют срезы, JOIN/NULL, GROUP/HAVING, UNION, вложенные источники,
временные таблицы, QueryResult, свежие снимки, доступ и rollback. Native курсор
и транзакционная конкуренция платформенной базы не заявляются.

## Версии и точность доказательств

Прочитана первичная справка Элемента **9.3** в авторизованном браузере.
[Ссылки и границы](../tests/corpus/state-rights/reference-9.3.json) сохранены.
Script **10.0.2-1** работает в режиме `current`; исходные проекты/архивы
**9.0** сохранены. Native-пробы подтверждают используемые операции Script
и отказ native литерала XBQL; они не подтверждают платформенные права.

До реализации заморожены **161** выбранная запись, исходные диапазоны,
sourceHash и причины недоступности. Обновлена только эта выборка:
**66 parsed**, **9 planned/executed/independentlyAssessed**. Девять оценок —
два прямых литерала неизменённого Demo-SRM и семь точных review templates
с исполнимыми переносимыми проектами. Каждая связана с sourceHash/range,
прямым критерием и свежим runtime. Прежние свидетельства выбранных записей
сохранены в `historyBefore045`; остальные записи каталога не изменены.

Исторические шаблоны `state` и `rights` — описания на английском, а не
исполняемые исходники. Их семантика проверяется отдельными новыми критериями;
точная independentlyAssessed-оценка этим описаниям не приписывается.
Custom data sources, native ACL, дополнительные иерархии, nullable/многоуровневые
внешние корреляции, коррелированный IN, joined DML и defaults временных
таблиц требуют дальнейших контрактов. Также остаются другие точные реальные
корни без независимо составленных критериев. Parsed/trace не заменяют оценку.

## Приёмка

**34 различных целевых теста успешны:** 20 новых и 14 затронутых прежних.
[Измерения](query-stage-045-measurements.json) содержат первичные отказы,
отдельные успешные повторы и SHA-256
артефактов и архивов. Шесть бизнес-мутаций получили **SBSL FAIL**,
корректная альтернативная реализация — PASS; инфраструктурный ERROR
восстановился в PASS. Публичные test/run — **2/2** каждый;
контроль **FAIL → UNSUPPORTED → PASS**, unavailablePoints **1**.
Два свежих изолированных batch — **3/0/3**, cacheHit false.
**46** артефактов прошли JSON Schema. Новые YAML: **28** файлов,
ноль ошибок и четыре предупреждения о контейнерах проектов.

Memory и шесть PostgreSQL-сценариев проверяют источники, снимки, изменения/rollback,
независимый SQL-аудит и cleanup; source:commit отсутствует. Чистые граничные
предикаты не дублируются в SQL. В исходном окружении отсутствовали оба
закреплённых Docker-образа и jsonschema: точные официальные образы восстановлены,
пакет проверки установлен только во временный каталог. Версии и лимиты не менялись.

Полный discovery, 303 формы, 44 прежних корня, четыре архивные validate
и полная регрессия оставлены nightly. Расписание CI и прежние expected
не изменены; ночное выполнение новых тестов не заявляется.
