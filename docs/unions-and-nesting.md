# Объединения, вложения и временные таблицы — №42

Реализован общий типизированный адаптер `storage-unions-nesting-v1`:
XBQL → AST → Script → текущая storage-сессия → независимая SBSL-оценка.
Планировщик не содержит ветвей по именам проектов или методов, а expected
не входит в IR. Исходные диапазоны сохраняются на всех уровнях вложения.

## Исполняемый контракт

- `ОБЪЕДИНИТЬ`/`ОБЪЕДИНИТЬ РАЗЛИЧНЫЕ` удаляет повторы всего накопленного
  результата; `ОБЪЕДИНИТЬ ВСЕ` сохраняет кратность. Ветви сопоставляются
  позиционно, имена колонок берутся из первой ветви. Проверяются ширина,
  номинальные типы, nullable-совместимость и тип результата ЗАПОЛНИТЬ.
  Общая сортировка использует имена выходных колонок первой ветви.
- Вложенные источники в `ИЗ`, в том числе многоуровневые, UNION, JOIN,
  вычисления, агрегаты и ЗАПОЛНИТЬ, используют тот же AST и renderer.
  Псевдоним вложенного источника необязателен. SQL NULL сохраняется отдельным
  внутренним флагом, поэтому вложение не смешивает его с Неопределено
  существующей nullable-ссылки. Служебные имена обходят коллизии с колонками.
- Одноколоночные некоррелированные `В`/`НЕ В` в ГДЕ поддерживают кратность
  внешних строк и трёхзначную логику, включая пустую выборку и NULL внутри
  неё. Подзапрос может читать временную таблицу текущего пакета.
- Пакет выполняет операторы последовательно и возвращает результат
  последнего оператора. Промежуточная выборка тоже выполняется.
  `ПОМЕСТИТЬ` сохраняет выбранные строки, включая флаги NULL;
  `СОЗДАТЬ ВРЕМЕННУЮ ТАБЛИЦУ` задаёт пустую таблицу с типизированными
  полями (расширенные определения добавлены 5 октября ниже); `ОБРЕЗАТЬ` очищает строки, `УНИЧТОЖИТЬ` удаляет таблицу.
  Повторное использование имени после удаления допустимо.
- `ИНДЕКСИРОВАТЬ ПО` и `СОЗДАТЬ ИНДЕКС … ДЛЯ … (…) ДОПОЛНИТЕЛЬНО ПО (…)`
  проверяют существование таблицы, выбранных полей и единственность индекса.
  Это логические подсказки: адаптер не создаёт физических индексов и не
  подтверждает их производительность или порядок обхода.

Контекст временных таблиц создаётся заново внутри каждого `Выполнить` и
передаётся дочерним запросам. Между вызовами и работами batch он не сохраняется.
Captured-параметры вычисляются при создании запроса в порядке исходных диапазонов;
повторный `%Имя` использует один slot, разные `%{выражение}` — разные.
Захваченные ссылки копируются по идентификатору. Повторное `Выполнить` видит
текущее staging-хранение: проверены снимки до изменения, после изменения и
после rollback с единственным вычислением captured-параметра.

## Реальный источник и версии

Прямо вызван неизменённый
`ХранилищеНастроек::Подразделения.ТекущееПодразделение` из
`Prakticheskie-primery-2026-09-30-15-20.xdump`. Пять авторских критериев проверяют
подразделение сотрудника, основное подразделение при отсутствии сотрудника,
дубликат обеих ветвей, пустой результат и Неопределено в ссылке сотрудника.
Данные задаются через storage; готовые строки запроса не подставляются.

Для этого корня введён явный `queryContext.currentUser` с полем
`Идентификатор` типа Ууид. Он предоставляет только идентификатор captured
`Пользователи.ТекущийПользователь`. Аутентификация, поиск пользователей,
права и фильтрация платформы этим контрактом не моделируются. Проектное или
локальное затенение системного имени отклоняется. Затенение источников и
типов ЗАПОЛНИТЬ проверяется также внутри вложений и промежуточных операторов.

Основание синтаксиса — официальная справка Элемента **9.3** по UNION,
вложенным источникам, ПОМЕСТИТЬ, созданию временной таблицы/индекса, удалению
и пакетам. Точные ссылки сохранены в
[карте](query-stage-042-coverage.json). Установленный Script **10.0.2-1**
использует `current`, включая профиль проекта `9.3`; версии исходников
архивов 9.0/9.3 сохраняются. Native-проба подтвердила порядок вычисления
аргументов, массивы и `ПервыйИлиНеопределено`. Native XBQL в standalone
Script недоступен; платформенная компиляция и native временные таблицы
не подтверждены. Исполнение запросов доказано для объявленного адаптера.

## Доказательства и остаток

[Baseline](query-stage-042-baseline.json) сохранён до реализации: 46 точных
записей с contractId, sourceHash/range и исходными причинами недоступности.
Свежая scoped-карта подтверждает 6 parsed/planned/executed/independentlyAssessed:
один реальный литерал и пять точных review templates (`distinct`, `union`,
`union-all`, `nested`, `compound`) в исполнимом проекте. Все привязки проверены
по hash/диапазону/критерию. Остальные 40 записей имеют явный остаток;
инвентаризация документации не считается исполняемым критерием.

В двух переносимых проектах проверены 56 сценариев, семь пустых случаев,
шесть дополнительных граничных случаев, пять review templates и один
реальный корень с пятью критериями. Независимые ожидаемые ответы зафиксированы
в авторском fixture-коде до запуска источников. Семь исполнимых бизнес-мутаций
получили SBSL FAIL; альтернативное вычисление `Q.Value + Q.Value` прошло.
Проверены ошибочные данные, timeout, неподдержанный источник, инфраструктурный
отказ и последующее успешное исполнение.

49 различных тестовых методов успешны после отдельных исправлений:
16 новых и 33 прежних. Публичные `test`/`run` реального корня дали по **5/5**,
контроль — **FAIL → UNSUPPORTED → PASS**, unavailablePoints = 1.
Два свежих изолированных batch дали **3/0/3**, все cacheHit = false.
46 артефактов прошли JSON Schema. Восемь PostgreSQL-сценариев проверяют
реальный корень и выбранные сочетания временных таблиц/JOIN/IN/повторных
снимков; SQL-аудит и cleanup успешны, rollback не оставляет source commit.

Полная регрессия, 303 формы, полный набор 44 прежних корней и четыре validate
не запускались; nightly не заявляется. Отклонение локального набора:
при выборе всего `FillPlanTest` по ошибке запущены два дополнительных теста,
включая один read-only проход полного `build_catalog`. Он не использован как
доказательство исполнения. Сохранённый каталог обновлён только по 46 baseline
записям; отдельный повтор использует точные методы.

Первичные ошибки и успешные повторы сохранены раздельно в
`result/unions-nesting/`; SHA-256 журналов и артефактов включены в
[измерения](query-stage-042-measurements.json). Исправлены начальные ошибки
типизации nullable-вложений, зависимости именованного ЗАПОЛНИТЬ,
YAML aliases авторских заданий, мутации batch и имён native-пробы.

## Дополнение 5 октября 2026 года

По [справке 9.3](https://1cmycloud.com/console/help/element/9.3/docs/topics/create-temporary-table-statement/)
поддержаны `Число(p,s)`, `Строка(n)` (0 означает отсутствие ограничения),
`ПО УМОЛЧАНИЮ выражение`, `ВЫЧИСЛЯЕТСЯ КАК выражение` и `АвтоНомерЗаписи`.
Значение по умолчанию вычисляется при вставке после приведения используемых
полей; явное значение его заменяет. Вычисляемое поле вычисляется при чтении,
поэтому UPDATE исходного поля меняет его, сохраняя ранее записанный default.
INSERT VALUES/SELECT используют общий AST, а captured-параметр, использованный
несколькими default-выражениями, сохраняет один исходный slot.

АвтоНомерЗаписи — последовательный счётчик локального контекста адаптера,
начинающийся с 1. DELETE/ОБРЕЗАТЬ не сбрасывают его; УНИЧТОЖИТЬ/создание и новое
Выполнить создают новый счётчик. Это явно заданная семантика эмуляции:
платформенная генерация номера/порядок конкурентных вставок не проверялись.
Изменение computed/auto поля, циклы определений, параметры/агрегаты/Ууид
в defaults/computed и индекс computed-поля отклоняются. Default, прямо или
косвенно зависящий от auto-поля, отклоняется: порядок такой вставки требует
платформенного подтверждения. Union-типы временных полей остаются UNSUPPORTED.

Новые [измерения](query-stage-040-042-completion-measurements.json),
[карта](query-stage-042-completion-coverage.json) и
[корпус](../tests/corpus/query-040-042-completion/README.md) сохраняют отдельные
проверки расширенных полей и свежие проверки прежнего UNION/nesting-контракта.
Логические подсказки индекса не превращаются в физические индексы.
