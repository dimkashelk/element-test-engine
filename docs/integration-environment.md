# Интеграционное окружение: PostgreSQL SQL smoke

> История этапа №9. Этап №10 добавляет ограниченный адаптер отгрузки и
> раздельные пароли admin/роли; актуальный контракт — [shipment-storage.md](shipment-storage.md).
> По уточнению пользователя платформенный эталон не требуется: приложения студентов недоступны.

Решение от 27.09.2026: одноразовый PostgreSQL 17 в Docker и доверенный Script
executor. SQL выполняется из SBSL через штатный SQL API; сравнение и баллы —
прежним `ДвижокТестирования.sbsl`. Это SQL smoke, не исполнение XBQL и не
реализация объектного API Элемента.

## Основания выбора

| Вариант | Возможности | Требования и подтверждённое состояние |
|---|---|---|
| Приложение Элемента | Реальные документы, ссылки, регистры, транзакции, обработчики и XBQL | Нужны отдельное приложение/БД, учётная запись, права, API, загрузка fixture, очистка и автоматизация. Такое окружение не настроено и не проверено. Рабочее приложение не используется. |
| PostgreSQL + адаптер | Воспроизводимые локальные запись, выборка и изменение | Доступен Docker 29.8.0, загружен PostgreSQL 17. Executor 10.0.2-1 содержит SQL API и `postgresql-42.7.11-7.jar` с `org/postgresql/Driver.class`. Реальные SQL-операции подтверждены из Скрипта с `-c 9.0`. Платформенный API и XBQL требуют отдельного адаптера. |

Установленный `psql` не служит основанием подключаться к локальной БД:
прототип не принимает адрес внешнего сервера. Образы фиксированы digest;
программа использует `--pull never`, загрузка — отдельная явная команда.

Проверены официальные описания:
[СоединениеSql](https://1cmycloud.com/console/help/lang/docs/stdlib/Std/Database/Sql/SqlConnection_ru/),
[ЗапросSql](https://1cmycloud.com/console/help/lang/docs/stdlib/Std/Database/Sql/SqlQuery_ru/),
[ЗапросSqlБезВыборки](https://1cmycloud.com/console/help/lang/docs/stdlib/Std/Database/Sql/SqlQueryWithoutSelect_ru/),
[ЗапросSqlСВыборкой](https://1cmycloud.com/console/help/lang/docs/stdlib/Std/Database/Sql/SqlQueryWithSelect_ru/),
[РезультатВыборкиSql](https://1cmycloud.com/console/help/lang/docs/stdlib/Std/Database/Sql/SqlSelectResult_ru/).
Применены JDBC-конструктор, фабрики запросов соединения, именованные параметры,
`Выполнить`, `Следующий`, `Получить`, закрываемые ресурсы. Точная совместимость
этого подмножества подтверждена установленным executor в режиме 9.0:
публичные страницы обновлялись в разное время и не заменяют эксперимент.
Пробный доверенный скрипт без БД также скомпилировал `СоединениеSql` и получил
`Std::Database::Sql::SqlException` при подключении к закрытому порту.
Импорт пространств имён в Script executor не поддержан; SQL-типы доступны без него.

## Оригинальный сценарий и необходимый API

Исходники прочитаны через `tarfile`, без запуска или изменения `Движок.tar`.
`Проект.yaml` задаёт совместимость 9.0. `РегистрТовары` содержит измерения
`Номенклатура: Номенклатура.Ссылка?`, `Склад: Склады.Ссылка?`, ресурс
`Количество: Число` и регистратор
`Отгрузка.Ссылка|ПоступлениеТоваров.Ссылка|?`.

| Часть сценария | Необходимый контракт | Текущее состояние |
|---|---|---|
| Документ | Объект/Данные, Дата, Ссылка, Склад, упорядоченная ТЧ; загрузка по типизированной ссылке и запись | Генерируемые типы и fake-загрузка, реального хранения нет |
| ПередЗаписью(До, ПараметрыЗаписи) | Литерал Запрос, один массив ссылок через `%{…}`, Выполнить, типизированные строки и ВСоответствие | Подставные строки, без XBQL |
| ПослеЗаписи(До, ПараметрыЗаписи) | `новый РегистрТовары.НаборЗаписей()` и `Фильтр.Установить(Регистратор = Ссылка)` | Наблюдаемые mocks, без хранения |
| Движение | ДобавитьЗапись с Период=Дата, ВидЗаписи=Расход, Номенклатура, Склад, Количество | Нужны постоянные записи, ДатаВремя, вид движения, ссылки, точное количество |
| Запись набора | Оригинальный вызов `Записать()`; замещение по регистратору и подтверждённые умолчания | Mocks фиксируют Замещать=true; SQL smoke этого контракта не реализует |
| Остатки | РегистрТовары.Остатки, КоличествоОстаток, `Номенклатура В (…)` | Smoke использует собственную SQL-таблицу smoke.stock, без виртуальных таблиц |

Оригинальный запрос **не фильтрует склад**. Smoke проверяет собственную
SQL-фильтрацию по складу, но не семантику исходного запроса. Несколько складов,
дубли товаров, пустой список и разворот виртуальной таблицы требуют отдельного
решения без изменения бизнес-логики. У `ПоступлениеТоваров` есть
`ПриСозданииНаОсновании`, но нет `ПослеЗаписи`.

После авторизации пользователя в консоли проверена официальная документация
9.1 (обновление 20.07.2026); сигнатуры добавления записи, установки фильтра и
обработчиков явно отмечены как применимые с версии 9.0. Подтверждены:

- [Набор регистра](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/AccumulationRegisterName.RecordSet_ru/):
  конструктор без аргументов создаёт пустой активный набор с неинициализированным
  фильтром. Добавление требует именованных периода `ДатаВремя`, вида движения
  и полей; вид движения доступен у регистра остатков. Запись имеет перегрузки
  `Записать(Замещать: Булево = Истина)` и с `ПараметрыЗаписи`.
  Истина удаляет прежние записи по фильтру, Ложь дописывает и очищает набор.
  Неинициализированный фильтр, несоответствующие ему записи и повторное включение
  одного экземпляра записи приводят к ошибкам. Записи имеют индекс в регистраторе.
- [Фильтр](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/AccumulationRegisterName.RecordSet.Filter_ru/):
  `Установить(Регистратор: ТипРегистратора)` задаёт единственный элемент фильтра.
  Поэтому union-типы регистратора должны сохранять тип документа.
- [Объект документа](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/DocumentName.Object_ru/):
  `Записать()` и перегрузка с параметрами записи. Оба обработчика принимают
  `До: Документ.Данные` и `ПараметрыЗаписи: Документ.ПараметрыЗаписи`, выполняются
  в транзакции; для нового объекта До отражает текущее состояние.
- [Ссылка документа](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/DocumentName.Reference_ru/):
  `ЗагрузитьОбъект(Заблокировать: Булево = Ложь): Документ.Объект?` возвращает
  Неопределено при отсутствии объекта. Блокировка действует до конца транзакции;
  запрос блокировки вне активной транзакции вызывает исключение.
- [Виртуальная таблица Остатки](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbql/Std/AccumulationRegisterName/AccumulationRegisterName.Balance_ru/):
  ресурсы собираются по всем измерениям из активных записей; результат строится
  при запросе. Необязательный `Период: ДатаВремя?` исключает саму границу периода;
  без него вычисляются актуальные остатки. Фильтр параметра ограничивает исходные
  записи. Поля измерений сохраняют типы, ресурс имеет суффикс Остаток и тип Число.

Документация подтверждает контракты, но полного приложения для экспериментальной
проверки этих гарантий ещё нет. Полная переносимость между версиями и
транзакционная реализация будущего адаптера требуют отдельного платформенного
эталона. Сигнатуры не выводятся из классической 1С или соседних продуктов.

## Контракт режима и жизненный цикл

Включение: `element-test test … --integration`. Проверка остаётся `type: runtime`:

```yaml
integration:
  backend: postgres
  operation: sql-smoke
```

Поддержан только фиксированный доверенный `src/SqlSmoke.sbsl`. Поля `target`,
`args`, `context`, `mocks`, `runtimeDateTime` отвергаются. Свой SQL, URL или
студенческий модуль передать нельзя. Ожидания задаёт преподаватель; фактические
данные возвращает executor; PASS/FAIL определяет SBSL. `run_pure` также отклоняет
integration-контракт, исключая обход через mocks.

Конфигурация: `config/integration.json` (только backend/image), переопределение
`ELEMENT_TEST_INTEGRATION_CONFIG`. Runtime выбирается из `config/runtimes.json`
по совместимости проекта; сохранены `ELEMENT_TEST_RUNTIMES`, `ELEMENT_SCRIPT_HOME`.
Нужен `ELEMENT_TEST_INTEGRATION_PASSWORD` из окружения. Пароль не принимается
из задания/конфига и не попадает в Git или отчёты. В этом доверенном прототипе
он используется при создании admin и отдельной роли smoke; студенческому коду
не передаётся. Перед подключением студентов необходимо разделить пароли.

Каждая проверка создаёт UUID, отдельную сеть `--internal`, PostgreSQL без
опубликованных портов и данных на хосте (PGDATA в tmpfs), таблицу, роль `smoke`
с SELECT/INSERT/UPDATE/DELETE и отдельный executor. У роли нет
SUPERUSER/CREATEDB/CREATEROLE и прав создания схем. Bootstrap выполняет доверенный
Python через `docker exec psql`; smoke пишет и читает через `СоединениеSql`.
Executor получает только доверенный скрипт и временный файл подключения;
на хосте каталог закрыт правами 0700, mount в контейнере только для чтения.
Docker/driver diagnostics не экспортируются: ошибки получают фиксированные
безопасные сообщения. Владелец Docker сохраняет обычный доступ к inspection;
это окружение не предназначено для долговременных секретов.

В `finally` удаляются executor, PostgreSQL и сеть, затем проверяется их отсутствие.
Временный файл подключения удаляется после контейнеров. Отчёт содержит backend,
operation, runId, cleanup, без JDBC-строки. Ошибка очистки → ERROR, никогда EXECUTED.
SIGKILL требует ручной очистки ресурсов конкретного runId; глобального удаления нет.

Preflight до создания ресурсов проверяет opt-in, контракт, конфигурацию,
совместимость, SQL API, класс драйвера, секрет, Docker daemon и локальные образы.
Отсутствующее окружение/драйвер и неподдержанная операция → UNSUPPORTED с причиной.
Ошибка SQL после подготовки → ERROR. Эти состояния не создают подставные строки
или PASS и не прерывают следующие проверки.

Студенческий код выполняется только прежним `run_pure` в Docker с `--network none`,
read-only, непривилегированным пользователем и лимитами. Интеграционный executor
имеет те же ограничения и свою закрытую сеть; студентов в неё этот этап не запускает.

## Воспроизведение

```bash
docker pull postgres:17@sha256:d74eeac9a635390a49bc21bd49fccd973de707e2a53a76ac49b552b8712ec46f
# Java-образ из config/runtimes.json также должен быть локально.
export ELEMENT_TEST_INTEGRATION_PASSWORD="$(python3 -c 'import secrets; print(secrets.token_hex(24))')"
bin/element-test test --project Движок.tar \
  --assignment assignments/poc-integration-environment \
  --integration --output result/poc-integration-environment
unset ELEMENT_TEST_INTEGRATION_PASSWORD

ELEMENT_TEST_DOCKER_TESTS=1 ELEMENT_TEST_INTEGRATION_TESTS=1 \
  python3 -m unittest discover -s tests -v \
  > result/poc-integration-environment/tests.log 2>&1
```

Интеграционный unittest сам создаёт временный секрет в окружении, проверяя его
URI/SQL-экранирование; `.env` и реальные пароли не нужны. Без флагов opt-in
Docker/integration-тесты пропускаются. CLI без `--integration` сохраняет два
UNSUPPORTED и возвращает код 2 (incomplete).

Два положительных запуска используют разные runId/БД: начальный общий COUNT=0;
два набора и два склада; дроби 1.25, 2.5, 7.125, 99.75; изменение только первой
строки до 3.375; второй набор не изменился; DELETE=4; конечный общий COUNT=0.
Проверены реальные привилегии роли. Отрицательный набор: неверная дробь → FAIL
в SBSL; ошибка запроса после committed-вставок → ERROR и удаление БД;
XBQL и недоступная конфигурация → UNSUPPORTED; затем успешные smoke-запуски.
Unittest независимо опрашивает Docker после нормального и аварийного запуска:
контейнеров/сетей конкретного runId нет. Архив побайтно неизменен.

Артефакты: `result/poc-integration-environment/result.json`, `report.html`,
`negative.json`, `negative.html`, `tests.log`, `preflight-tests.log`.
Полная регрессия с Docker/интеграцией: 66/66, без пропусков, 203.896 секунды
(`tests.log`): прежние 49, уже существовавшие 10 проверок xdump и 7 новых
проверок интеграции. Первоначальный запуск выявил только ошибку тестовой проверки
канонического пути macOS (`/var` против `/private/var`); она исправлена,
полный набор повторно прошёл. Дополнительные журналы: `integration-tests.log`,
`without-opt-in.log` и `without-opt-in/result.json`/`report.html`.
Отдельный итоговый интеграционный набор также прошёл 7/7 за 30.981 секунды
(`integration-tests.log`).
Публичная CLI с `--integration` проверена отдельно: 2/2 PASS, код выхода 0;
`cli.log`, `cli/result.json` и `cli/report.html`.

## Оставшиеся ограничения

Не реализованы сохранение документов, реальные ссылки, регистратор/замещение,
движения, пересчёт остатков, XBQL, транзакции Элемента и повторное проведение.
Полный SQL-адаптер значительно дороже smoke: контракты типов, жизненный цикл
документов, атомарность обработчиков/записи, трансляция подмножества запросов,
платформенный эталон. Следующая итерация — `docs/next-task.md`.
