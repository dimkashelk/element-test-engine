# Соединения и NULL — контракт №40

Реализованы INNER/LEFT/RIGHT/FULL JOIN, ЗаменитьNull, ЕСТЬ [НЕ] NULL,
nullable проекции и сочетания с именованным ЗАПОЛНИТЬ. Источники читаются
через существующие адаптеры хранения, соединение и оценка выражений выполняются
в установленном Script, результат проверяет SBSL. В AST нет готовых строк запроса
или авторских ответов; ветвей по названию проекта/метода нет.

Пользователь выбрал Элемент 9.3 и актуальный установленный Script. Используются
официальные разделы 9.3: [источники и соединения](https://1cmycloud.com/console/help/element/9.3/docs/topics/select-from/),
[ЗаменитьNull](https://1cmycloud.com/console/help/element/9.3/docs/topics/replace-null-function/),
[ЕСТЬ NULL](https://1cmycloud.com/console/help/element/9.3/docs/topics/is-null-expression/).
Установлен Script **10.0.2-1** (`script_u_10.0.2_1`). Его CLI отвергает `-c 9.3`;
профиль `9.3` в `config/runtimes.json` задаёт `executionCompatibilityVersion: current`
и `elementReferenceVersion: 9.3`. Новый критерий выбирает его через
`runtimeProfile: "9.3"`. Версии исходных архивов и прежний профиль 9.0 сохраняются;
план и runtime evidence отдельно показывают исходную и исполнительную версии.
Это не свидетельство платформенной компиляции на Элементе 9.3.

## Исполняемая семантика

- Источники: обычные справочники/документы и ранее поддержанный дневной
  СрезПоследних регистра сведений. Псевдонимы, namespace, видимость, владельцы
  ссылок и полей проверяются до генерации. Одинаковый UUID разных владельцев
  не делает ссылки совместимыми. Неуточнённое неоднозначное поле отвергается.
- Соединения сохраняют кратность: для двух строк слева и двух справа с одинаковым
  ключом получаются четыре пары. Поддержана последовательность соединений слева
  направо, несколько источников, self join, пустые стороны, условия ON/WHERE.
  RIGHT/FULL добавляют каждую несовпавшую строку правого источника один раз.
- SQL NULL обозначает отсутствующую строку внешнего соединения. Неопределено
  в существующей строке остаётся отдельным значением. ЕСТЬ NULL проверяет первое;
  ЗаменитьNull заменяет только его. Сравнение с NULL даёт неизвестность;
  НЕ/И/ИЛИ используют трёхзначную логику, ON и WHERE принимают только Истина.
- Nullable подъём применяется к проекциям отсутствующей стороны. Для ЗАПОЛНИТЬ
  проверяются номинальный тип структуры, типы/имена её полей, обязательные
  параметры и диапазоны исходника. ЗаменитьNull может снять подъём NULL, но
  сохраняет возможность исходного Неопределено. Подтверждённые значения
  безаргументного ЗаменитьNull: Число, Строка, Булево и nullable типы.
- Параметры вычисляются при создании запроса в порядке исходных диапазонов;
  простой повторный параметр занимает один slot. Ссылки копируются, граница
  среза фиксируется при создании. Каждый Выполнить читает текущий снимок хранения.
  Повторные результаты, структуры и ссылки отделены от предыдущих результатов.
- Порядок стадий: соединения → WHERE → сортировка → ПЕРВЫЕ → проекции.
  Сортировка поддержана для не-NULL Число/Строка/Дата, включая параметризованный
  ЗаменитьNull. Фильтры включают равенство/неравенство скаляров и ссылок;
  упорядоченное сравнение требует не-nullable Число/Строка/Дата.

В транспортном результате SQL NULL и Неопределено представлены JSON null /
nullable Script значением. Различие сохраняется внутри одного relational AST
при фильтрации и замене NULL; отдельный нативный объект Null для последующей
обработки результата за пределами запроса не эмулируется.

Режим сравнения `query-rows-unordered` сопоставляет верхний массив строк как
мультимножество и учитывает количество дублей. Аудит хранения независим от
порядка. Для критериев с обязательным порядком применяется прежний
`record-sets-unordered`: порядок массива результата проверяется точно.
Существующие режимы сравнения не изменены.

## Проверка

Авторские fixtures/expected зафиксированы в `tests/join_fixtures.py` и новых
assignments до выполнения источников. Прямые корни:

| Архив / метод | Независимые случаи | Свежая оценка |
|---|---|---|
| Demo-SRM / Общие::КурсыВалют::КурсыВалют.ПолучитьКурсыВалют | несколько валют, отсутствующий курс, пустой каталог, только базовая валюта, отсутствие истории, дневная граница | test/run по 4/4 PASS, memory и PostgreSQL |
| autocheck / Проверка::Кейсы.ПолучитьДоступныеКейсы | действующий/черновик, дубли, отсутствующая связь, сортировка, пустое хранилище | test/run по 2/2 PASS, memory и PostgreSQL |

Два переносимых проекта проверяют все четыре вида соединений, три источника,
различие NULL/Неопределено, таблицы истинности, альтернативную правильную запись,
повторное исполнение, изменения внутри транзакции и rollback. Проверены Булево,
Дата, Ууид, перечисление и ссылки с разными владельцами. SQL-аудит выполняется
отдельным чтением, шесть сценариев заканчиваются cleanup, исходник не commit.

**51 различный целевой тест успешно проверен** несколькими ограниченными прогонами:
16 новых и 35 реально затронутых прежних. Все первичные сбои сохранены отдельно
от успешных повторов. Один старый self-join теперь поддержан: прежнее ожидание
UNSUPPORTED в тесте заменено независимым ответом; прежний assignment/expected
не переписывался. Контрольный неподдержанный IN остаётся UNSUPPORTED.

11 исполнимых бизнес-мутаций получили SBSL FAIL: вид соединения, ON, ресурс,
fallback, базовая валюта, граница даты, RIGHT/FULL, проверка NULL, статус,
порядок. Восстановление после мутации и инфраструктурного отказа подтверждено.
Ошибочные fixture, timeout и неподдержанный запрос получают отдельные статусы.
Публичный контроль: FAIL → UNSUPPORTED → PASS, unavailablePoints=1.
Два изолированных batch: 6 → 3 → 6 баллов, cacheHit=false.
JSON Schema проверены для **66 артефактов** пакетов/batch/events.

## Остаток

Baseline №40 содержит 73 записи, в том числе 64 исходных кандидата и девять
семейств документации. Обновлены только эти сохранённые записи; fresh-040
привязан к двум исходным литералам с exact projectSourceHash/sourceHash/range
и прямыми независимыми критериями. Для обоих P/L/E/A=1. Остальные сочетания
имеют явную причину отказа: наличие JOIN само по себе не подтверждает весь запрос.

Группированные источники, вложенные запросы, UNION, агрегаты/вычисления,
другие виртуальные таблицы, временные таблицы, системные источники/права,
полный API запросов и остальные формы ЗАПОЛНИТЬ закреплены за №41–45.
Standalone Script не исполняет нативный литерал Запрос; соответствующий отказ
сохранён в native probes. Native XBQL, платформенная компиляция и browser UI
не объявляются проверенными.

Полный discovery, 303 формы, прежние 44 корня, четыре validate и полный набор
тестов локально не запускались. Расписание CI, архивы, прежние expected и лимиты
не менялись. Новые тесты обнаруживаются существующим nightly; его выполнение
в рамках этой приёмки не заявляется. Следующее задание — №41.
