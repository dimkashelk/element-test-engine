# Ветви и генеративные проверки: контракт №52

Два расширения существующего `type: runtime`: `branches: true` и
`generative`. Общий путь `test`/`run`/`batch`, новых YAML типов нет.
Реализация: `element_test.branches`, `element_test.generative`, независимое
сравнение в `src/ДвижокТестирования.sbsl`.
[Схема входа](generative-options-v1.schema.json) описывает форму; встроенная
валидация дополнительно проверяет типы, арность, ограничения и совместимость
с сигнатурой метода. Полный внешний JSON Schema валидатор необязателен.

## Инструментализация

```yaml
checks:
  - id: boundaries
    type: runtime
    target: {module: Algorithms, method: Clamp}
    args: [-1]
    expected: 0
    branches: true
```

Поддержаны исходные условия `если`, `иначеесли`/`иначе если`, `пока` и
тернарного выражения; вход, итерации и выходы `для`/`пока`; выбранные ветки
`выбор`, включая `иначе`, и завершение без совпадения. Исходное выражение
условия передаётся в булев probe один раз. `и`/`или` и тернарные операнды
сохраняют native ленивое вычисление; выражение коллекции/границ `для`
не вычисляется повторно. Probe не заменяет бизнес-операцию или результат.
Для циклов `вконце` сохраняет наблюдение при возврате и исключении.
Отдельно записываются `zero`, `nonzero`, `exhausted`, `break-exit`,
`abrupt-exit`, `break` и `continue`. Лексический ближайший цикл разрешается
до вставок; вложенные циклы имеют собственные идентичности и счётчики.

`execution-plan.json` содержит инвентарь подготовленного исходного замыкания.
Каждая идентичность учитывает provider/project/version, namespace, owner,
метод, файл, SHA-256 файла и проекта, диапазон UTF-8 текста без BOM,
строку/колонку от единицы, конструкцию и набор исходов. Вставки выполняются
по оригинальным позициям вместе с адаптацией типов и вызовов. Смена исходника,
позиции или владельца меняет идентичность. Одинаковый текст не объединяется.

В `runtime-evidence.json` есть `trace` и `branchCoverage`. Для memory и
metadata-storage/PostgreSQL method entry используется один механизм.
`trace: true` сохраняет прежние события входа/выхода метода; эти события
сами по себе не повышают число пройденных исходов условий.

## Знаменатели и исходная карта

`totalOutcomes` = два исхода каждого подготовленного условия, включая
условие `пока`. `coveredOutcomes` считает только наблюдавшиеся true/false.
Ветки `выбор` и границы циклов имеют собственные записи/счётчики и не
прибавляются к этому знаменателю. Это не покрытие комбинаций подусловий,
MC/DC или всех путей. Методы, запросы, bindings, эффекты и готовность
адаптера продолжают иметь отдельные знаменатели. Технические наблюдения
не создают дополнительных баллов.

Полный статический инвентарь проекта строится отдельно:

```bash
python3 -m element_test.branches --project Dvizhok-final.xdump \
  --output result/final-branches.json
```

`--evidence result/run/runtime-evidence.json` добавляет только записи с
совпадающими идентичностью, hashes, owner и диапазоном. Другой sourceHash
отбрасывается. `blockedMethods` и `completeDenominator` сохраняют пробелы
парсинга; они не выдаются за полное покрытие. Файл инвентаря нельзя записать
во входной проект; SHA-256 входного архива сверяется после чтения.

[Статический инвентарь финального дампа](dvizhok-final-branch-inventory.json):
58 методов, 37 условий (74 исхода), 9 циклов. Нет бизнес-исполнения,
поэтому измеренное покрытие равно **0/74**, execution — `not-checked`.
Этот отчёт не импортирует исполнение предыдущего Dvizhok.

Неисполненный исход не объявляется недостижимым: `unreachable` остаётся
пустым без отдельного авторского доказательства. Отсутствие сценария,
неподдержанный синтаксис и недоступный backend различаются через инвентарь,
readiness и существующие `reasonCode`/`unavailablePoints`.

## Генеративный вход и независимое отношение

```yaml
checks:
  - id: scale-invariant
    type: runtime
    points: 1
    target: {module: Algorithms, method: Double}
    generative:
      schemaVersion: 1
      seed: 73
      cases: 12
      domains:
        - {type: Число, min: -8, max: 8}
      relation:
        op: equal
        args:
          - {result: true}
          - {op: multiply, args: [{arg: 0}, {literal: 2}]}
      maxShrinks: 32
```

Автор задаёт отношение до исполнения исходника. Генератор получает только
типизированные домены, seed и ограничения; он не читает ответ метода.
План не содержит отношение/expected. Python поставляет фактические входы
и снимки; каждое сравнение, включая решения при shrinking, выполняет SBSL.
Правильная альтернативная реализация принимается по тому же отношению.
Неверное отношение — ответственность автора; инфраструктура не выводит
бизнес-истину из исследуемого решения.

Генератор `v1-splitmix64`: фиксированные 64-битные операции SplitMix64
в исходном модуле, равномерный выбор по rejection sampling. Он не зависит
от версий Python `random`.
Первые три входа включают минимумы, максимумы и числовой ноль, ограниченный
доменом; остальные создаются по seed. Строки используют объявленный алфавит,
массивы — рекурсивный домен items. Сохраняются все фактические входы,
версия генератора, seed, sourceHash и число исполнений.

Поддержаны:

- `Булево`; целое `Число` с `min/max` в пределах ±1000000;
- `Строка` с `alphabet`, `minLength/maxLength` 0..32;
- `Массив<T>` с такими же ограничениями длины и `items`;
- nullable `T?`; упорядоченный `values` из 1..64 допустимых значений.

Ограничения: 1..8 аргументов, 1..64 случаев, 0..64 shrink попыток,
глубина домена до 4, бюджет размера доменов 4096. Типы должны совпадать
с сигнатурой метода; вложенные элементы, длины, диапазоны и explicit values
проверяются до запуска. Неизвестные ключи и превышения границ недоступны
с причиной `invalid_test`.

Отношение — ограниченное дерево глубиной до 8: `arg`, `result`,
`pairedResult`, скалярный `literal`, операторы `equal/notEqual`, числовые
сравнения и `add/subtract/multiply`, ленивые `and/or`, `not`, `length`,
`sum`, `get` поля снимка, `at` индекс массива и `reverse`. Результат должен
быть Булево; ошибка типов/индекса/поля — `invalid_test`, без FAIL студента.
Здесь нет исполнения произвольного Python, Script или строкового eval.

## Метаморфное отношение, изоляция и уменьшение

Опциональный `transform` содержит по одному выражению на аргумент:
`arg/literal`, числовую арифметику или `reverse` строки/массива.
Каждый преобразованный вход должен оставаться в исходном домене. Второй
исходный вызов даёт `pairedResult`, например `result + pairedResult = 16`
для `Double(X)` и `Double(8-X)` на домене 0..8. Можно проверять сохранение
суммы при перестановке массива. Отношение не передаётся в student executor.

Каждый исходный/преобразованный/shrink вход использует свежий ограниченный
Docker executor, новый context и memory storage. Часы и callbacks используют
явные контракты №48; initial fixtures не переходят между случаями.
Доступ к снимкам объекта/хранилища выражается через `get/at`.

При FAIL сокращается первый нарушающий вход: число приближается к
допустимому нулю, строка/массив сокращается до допустимого минимума и
поэлементно, Булево уменьшается к Ложь, nullable — к null, values — к
более раннему значению. Принимаются только сохраняющие FAIL кандидаты;
домены и transform остаются допустимыми. Все решения принимает SBSL.

`generative.counterexample` сохраняет исходный и уменьшенный случай,
`caseIndex`, попытки и `minimality`. `local-under-declared-reductions`
означает отсутствие уменьшающего FAIL соседа под этими редукциями;
это не доказательство глобально наименьшего контрпримера.
`budget-exhausted` явно сохраняет незавершённое уменьшение.
`replayCheck` — готовая проверка с `replayInputs`, исходным отношением,
transform и `replaySourceHash`; другой исходник не подменяет replay.

Любой недоступный случай/ошибка backend/таймаут прерывает проверку с исходным
статусом и причиной. Неполный набор не даёт PASS. Итоговое независимое
отношение использует обычный вес критерия; техническое покрытие/shrinking
не создаёт отдельных критериев и не повышает баллы.

## Границы реализации

Генеративный вход сейчас ограничен source method и memory runtime.
`args`, `expected`, `comparison`, `sequence`, интеграционный и самостоятельные
query/UI/report/navigation/panel входы с ним несовместимы. Домены объектов,
ссылок, дат, дробных чисел, native enum, произвольные предикаты домена,
state-machine sequences и генеративный PostgreSQL — точный остаток.
`branches` не инструментирует формулы отчётов или декларативные surfaces.
Native платформенная семантика и браузерное поведение не подтверждаются
результатом Script adapter. Совместимость исходника 9.0 сохранена; профиль
9.3/current отдельно определяет установленный executor.

Проверки №52 — технические fixtures механизма, без заданий финального дампа.
[Измерения](test-type-stage-052-measurements.json) фиксируют локальную приёмку;
полная регрессия остаётся существующему nightly, его расписание не менялось.
