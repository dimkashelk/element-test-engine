# E07 и E08 — транзакция сценария и сортировка union-полей

Реализовано 14 октября 2026 года. Записи, откат, исходные обработчики и
сравнение значений выполняет Script. Python разрешает типы и генерирует драйвер;
ожидания и оценки остаются в SBSL.

## E07: общая граница interface/panel

```yaml
interface: {schemaVersion: 1, form: {name: Editor, namespace: Data}}
storage: {backend: memory, idType: Ууид, lifecycle: true, transaction: true}
formEffects: {write: true}
sequence:
  - {writeInterface: true}
  - input: {selector: {name: Amount}, value: -1}
  - {writeInterface: true}
```

Тот же `storage.transaction: true` доступен для `panel` с `panelActions`.
Граница начинается **после** создания сессии, загрузки `initial`,
`initialRegisters` и начальных констант, инициализации формы, привязок и очереди
таймеров. Для панели первое чтение виджетов уже входит в транзакцию. Она
охватывает все действия сценария, записи объектов, связанных наборов регистров,
констант и эффекты исходных lifecycle hooks и timer callbacks.

На обычном завершении публикуется весь снимок. Бизнес-исключение, покинувшее
исходный обработчик или запись, останавливает оставшиеся действия и восстанавливает
начальный снимок сессии. Поддержаны `ИсключениеНедопустимоеСостояние` и уже
подключённое `ИсключениеВалидации`. Перехваченное самим исходником исключение
сохраняет прежнюю семантику: при нормальном выходе сценарий фиксируется.

При декларативном `writeInterface` с lifecycle сохраняется снимок действия
`outcome: rejected`, затем исходное исключение вызывает общий откат. Успешные
ранние действия также остаются в `actions` как независимые наблюдения состояния
на тот момент; они могут содержать ещё не зафиксированные данные. Неудавшееся
обычное действие/обработчик панели не добавляет законченный снимок.

Только при включённой общей транзакции в `actual.result` появляется:

```json
{"transaction": {"outcome": "rolledBack", "exception": {"type": "...", "message": "..."}}}
```

При успехе `outcome: committed`, `exception: null`. Финальный `actual.storage`
содержит состояние после commit/rollback. `storageTrace` и `storageDiagnostics`
показывают границу driver, отсутствие активной транзакции и освобождение блокировок.
Технические ошибки, SQL/файловый сбой и неизвестный API откатывают сессию и
передаются прежней классификации ERROR/UNSUPPORTED; они не становятся бизнес-отказом
с успешным исполнением. Timeout/прерывание не дают EXECUTED и не имеют общего
финального результата; изоляция и очистка выполняются инфраструктурой.

Константы интерфейса при `transaction: true` используют общую сессию даже без
`lifecycle: true`. Атомарная запись объекта по-прежнему требует свой прежний
контракт; `transaction` сам по себе не подключает hooks или новые API записи.
Граница восстановления охватывает сохранённые данные, а состояние объектов формы,
UI-компонентов, часов, очереди таймеров и уже снятые наблюдения не восстанавливается.
Очередь закрывается прежним finally, в том числе при отказе.

Memory и PostgreSQL используют один снимок driver. Fixtures публикуются в SQL
до начала сценария; исходные транзакции внутри driver не публикуют промежуточные
изменения. Commit публикует весь снимок в настоящем SQL BEGIN/COMMIT; после отката
независимый SELECT видит только начальное состояние. Прежние изолированные
каталоги, сессии и одноразовые БД сохраняются для каждого check/submission batch.
Без `transaction` прежний контракт и структура actual сохраняются. Обычный
методный runtime и report/query entry сохраняют свои существующие границы.

## E08: явный порядок типизированных значений

Сортировка остаётся стабильной, по последовательности сортируемых полей макета.
Сравниваются типизированные значения **до** сериализации. При возрастании:

1. `Неопределено`.
2. `Булево`, `Число`, `Строка`, `Дата`, `Время`, `ДатаВремя`, `Момент`, `Ууид`.
3. Enum: полный owner по строковому порядку, затем объявленный порядок элементов.
4. Ссылка: полный owner `.Ссылка` по строковому порядку, затем идентификатор.

При убывании порядок типов и значений обращается, NULL оказывается последним.
Порядок полных owner определяется кодовыми точками Unicode с учётом регистра,
без локали и технических alias сгенерированных типов.
Равенство всех сортируемых ключей сохраняет исходный порядок строк в обоих
направлениях. Второе поле разрешает равенство первого, включая два NULL.
`Булево`: Ложь перед Истина; UUID и UUID ссылок сравниваются по native
`ВСтроку()`, строковые идентификаторы — напрямую. Дроби сравниваются как Число,
даты/время/моменты — собственным оператором Script. Порядок членов union в YAML
не определяет порядок значений. Разные владельцы с одним ID остаются различными.

Поддержаны union ссылок (включая nullable) и смешанные поддержанные скаляры/enum,
в том числе результаты `ЕСЛИ`. Объекты/коллекции, универсальный Объект и смешанное
хранение нескольких ссылок со скалярами не расширяют прежний codec-контракт.
Неизвестный сортируемый тип остаётся UNSUPPORTED. Правило записывается в
`execution-plan.report.sortingContract` и в зависимости отчётов панели;
выходной layout сохраняет прежнюю структуру.

Это порядок модели по типу и идентификатору, без загрузки представления ссылки.
Native pivot, представления и браузерная отрисовка остаются внешним контуром.

## Приёмка

`tests/test_engine_e07_e08.py` проверяет переносимые namespace, несколько записей
и исходные hooks с регистрами, общий откат и commit, константы без lifecycle,
декларативный отказ записи, чтение панели по таймеру, независимые ранние снимки,
свежую сессию, NULL, одинаковые ID разных владельцев, оба направления, стабильные
равенства и вторичный ключ. Интеграционные проверки независимо читают PostgreSQL, включая константы
без lifecycle и откат после недоступного UI-действия. Публичная приёмка
проверяет PASS/FAIL/UNSUPPORTED и отдельные сессии для checks и двух работ batch.

```sh
python3 -m unittest discover -s tests -p test_engine_e07_e08.py -v
ELEMENT_TEST_DOCKER_TESTS=1 python3 -m unittest discover -s tests \
  -p test_engine_e07_e08.py -v
```

Новая приёмка: **13 проверок прошли полностью**. Затронутая регрессия:
**57 прошли**, 6 прежних PostgreSQL-проверок пропущены без своего opt-in.
Всего **70 уникальных успешных проверок**. Полная регрессия проекта не запускалась.
