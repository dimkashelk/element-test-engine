# E05 и E06 — последовательности операций и флаги ячеек

Реализовано 14 октября 2026 года. Исходные методы и выражения исполняет
Script; отношения и PASS/FAIL вычисляет существующий SBSL-движок.

## E05: генерация завершённых сценариев

Вместо `generative.domains` можно задать `generative.sequence`:

```yaml
target: {module: Flow, namespace: Data, method: Create}
storage: {backend: memory, idType: Ууид, lifecycle: true}
captureException: true
timeout: 15s
generative:
  schemaVersion: 1
  seed: 73
  cases: 12
  maxShrinks: 16
  sequence:
    initialState: empty
    finalState: done
    minLength: 4
    maxLength: 8
    operations:
      - name: create
        method: Create
        from: empty
        to: created
        domains: [{type: Число, min: 1, max: 4}]
      - name: update
        method: Update
        from: created
        to: saved
        domains: [{type: Число, values: [6]}]
      - name: rewrite
        method: Update
        from: saved
        to: saved
        domains: [{type: Число, values: [6]}]
      - name: reject
        method: Update
        from: saved
        to: failed
        domains: [{type: Число, min: -5, max: -1}]
      - name: read
        method: Read
        from: failed
        to: done
        domains: []
  relation:
    op: equal
    args:
      - op: get
        args:
          - op: get
            args:
              - op: at
                args:
                  - {op: get, args: [{result: true}, {literal: storage}]}
                  - {literal: 0}
              - {literal: value}
          - {literal: Amount}
      - {literal: 6}
```

Автор задаёт состояния и ожидаемое отношение независимо от реализации.
`from/to` — предусловие/переход авторской модели, а не вычисленный результат
исходного метода. Метод с отказом может перейти в следующее состояние сценария,
если отказ наблюдается через `captureException`. Атомарная запись обработчиков
требует существующего `storage.lifecycle: true`; транзакции сохраняют прежний
контракт. Состояния не заменяют проверки фактических данных и исключений.

Все операции относятся к одному выбранному исходному модулю. `target.method`
при последовательности заменяется первым фактически выбранным методом.
До исполнения проверяются сигнатуры, проектные типы и все объявленные значения
каждой операции, включая не выбранные seed. Замыкание ветвей включает все
операции модели; отсутствующий метод не получает PASS.

Ограничения: 1..32 операции, 0..8 аргументов на операцию, длина 1..40,
1..64 случаев, прежние границы доменов и бюджет размера 4096. Требуются
начальное и конечное состояния. Генератор выбирает только длины и переходы,
позволяющие дойти до конечного состояния ровно за оставшееся число шагов.
Первые случаи используют минимальную/максимальную/минимальную допустимые длины;
остальные длины и переходы определяет прежний SplitMix64 с seed.

`inputs` каждого случая — один аргумент: массив `{operation, args}`;
`arg: 0` в отношении даёт этот массив. `result` — прежний снимок runtime
последовательности (`actions`, а с storage — `result.actions` и `storage`).
Снимки действий сериализуются сразу после исполнения и не меняются задним числом.

Shrinking удаляет непрерывные фрагменты и уменьшает аргументы по их доменам.
Кандидат допускается только при сохранении всех переходов, конечного состояния,
границ длины и типов. Решение о сохранении FAIL принимает SBSL. Replay сохраняет
фактическую последовательность, seed, конфигурацию и sourceHash. `maxShrinks`
ограничивает число исполнений; локальная минимальность не означает глобальную.

## PostgreSQL и изоляция

Генеративные методы с прежним `domains` и новые последовательности поддерживают:

```yaml
storage: {backend: postgres, idType: Ууид, lifecycle: true}
integration: {backend: postgres, operation: metadata-storage}
```

Требуется прежний opt-in `--integration` и окружение интеграционного backend.
Каждый generated/replay/shrink случай и каждая пара `transform` получают новый
временный каталог, executor, закрытую сеть и одноразовую БД. Независимый SELECT
`PostgresSession.audit` поставляет `result.storage`; runtime не задаёт SQL-ожидание.
Дробные результаты и SQL-аудит сохраняют точный десятичный транспорт E04.
`generative.backendRuns` содержит уникальные runId и результаты очистки.

Ошибка любого случая или очистки прерывает проверку с исходным недоступным
статусом; неполный набор не получает PASS. Самостоятельные UI/query/report/
navigation/panel/integration-smoke входы не добавлены. Верхнеуровневый `sequence`
и `args` по-прежнему не смешиваются с генеративным входом. `transform` доступен
для обычных доменов; преобразование целой машины состояний не определено.

## E06: действие над текущей ячейкой

Для `input` в колонку с явным `row` флаги `Видимость`, `Доступность` и
`ТолькоЧтение` могут ссылаться на `RowData` ближайшей таблицы. Перед действием
проверяется текущая граница массива, затем строка по индексу связывается с
типизированным контекстом gate. Выражение флага вычисляет Script. Индекс вне
массива остаётся недоступной операцией; данные не меняются.

Gate заново вычисляется перед каждым вводом: изменение поля, перемещение или
удаление строки не оставляет старый контекст. Флаги предков и живые флаги
именованных компонентов сохраняются. Отказ gate возвращает `outcome: blocked`
и не записывает значение; независимые снимки сохраняют раннее состояние.
`RowData` вне колонки или неизвестное поле остаются ошибкой декларации.
Это модель интерфейса; native отрисовка и доставка событий браузера не проверяются.

## Приёмка

`tests/test_engine_e05_e06.py`: переносимые namespace, seed, завершённость,
тупиковые переходы, допустимые сокращения, создание/повторная запись/отказ после
записи/чтение, отсутствие утечки между случаями, независимое отношение, неверный
expected, replay и sourceHash, PASS/FAIL/UNSUPPORTED через публичный `run_test`,
точные дроби и SQL-аудит. Для ячеек проверяются все три флага, две строки,
изменение, перемещение, запрет родителя, границы и независимые снимки.

```sh
python3 -m unittest discover -s tests -p test_engine_e05_e06.py -v
ELEMENT_TEST_DOCKER_TESTS=1 python3 -m unittest discover -s tests \
  -p test_engine_e05_e06.py -k StatefulBackendTest -v
```

проверок пропущены в запусках без нужного opt-in или внешнего jsonschema.
