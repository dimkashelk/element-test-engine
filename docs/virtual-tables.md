# Виртуальные таблицы и прочие источники — №43

Реализованы источники, выводимые из метаданных, в общем типизированном
адаптере: XBQL → AST → Script → текущая storage-сессия → независимая
SBSL-оценка. Данные и expected задаются автором отдельно. Планировщик и
renderer не вычисляют строки в Python и не выбирают поведение по имени проекта.

## Исполняемый контракт

- `СрезПервых` и `СрезПоследних` для регистров сведений с периодичностью
  День/Секунда. Первый выбирает минимальный период `>=` границы, последний —
  максимальный `<=`; группировка использует все измерения. Без границы первый
  берёт начало истории, последний фиксирует текущую дату/время UTC при создании
  запроса. `ГДЕ` применяется после выбора среза. Граница обязана соответствовать
  типу периода, union-измерения остаются недоступны.
- Исходные периодические/непериодические регистры сведений и записи регистров
  накопления. Исходные движения содержат также неактивные строки; доступны
  Период, Активность, Индекс, НомерСтроки и ВидЗаписи у регистра Остатки.
- `Остатки`: активные движения строго до границы, все измерения и числовые
  ресурсы, приход минус расход. Нулевой по всем ресурсам остаток не выводится;
  отрицательные и положительные части имеют отдельные поля.
- `Обороты`: обе границы включены; у регистра Остатки — знаковый оборот,
  отдельные приход/расход, у регистра Обороты — сумма ресурса. Группы с нулевым
  оборотом сохраняются. Пропущенные границы не ограничивают период.
- `ОстаткиИОбороты` с периодичностью итогов по умолчанию Период: начальный
  остаток строго до начала, конечный — включая конец, обороты внутри интервала.
  Неявная группировка сохраняет все измерения даже без их вывода в SELECT.
- Табличные части справочников/документов: реквизиты строки, Владелец, Индекс
  от нуля, НомерСтроки от единицы. Реквизиты `Массив<T>` с поддержанным скалярным/ссылочным типом дают
  Владелец, Индекс, Элемент с исходным типом. Повторы элементов сохраняются.
- Непериодические наборы констант используют текущую сессию; сохранённая
  ВиртуальнаяТаблица разрешается по своему YAML/XBQL, namespace и imports.
  Поддержаны определения без параметров и SQL NULL в результате; циклы
  отклоняются, hash/range определения входят в AST.
- `Пользователи` использует явный `queryContext.users`: Ссылка, Представление,
  Администратор, БылУспешныйВход, ЗапрещенВход, РазрешенДоступПоТокену.
  Проверяются полные типизированные записи и уникальность ссылок. Это fixture
  идентичности, аутентификация и права приложения не исполняются.
- Источники сочетаются с ранее реализованными JOIN/NULL, агрегатами, вложениями
  и UNION. Один captured параметр `В (%K)` может быть скаляром или массивом;
  массив копируется при создании запроса. Повторное выполнение читает свежую
  storage-сессию; возвращённые строки не меняют прежний снимок.

Типы, владельцы и диапазоны проверяются общим resolver. Затенённые источники,
несовместимые поля/периоды, отсутствующий `storage.registers` и неподтверждённые
операции дают UNSUPPORTED. Мутация допустимой бизнес-логики исполняется и
оценивается FAIL. Инфраструктурная ошибка сохраняет ERROR.

## Версии и платформенный остаток

Состав параметров/полей и ограничения записаны в
[инвентаризации справки 9.3](../tests/corpus/virtual-tables/reference-9.3.json),
прочитанной в авторизованном браузере. Установленный Script **10.0.2-1**
исполняет профиль `9.3` в режиме **current**; исходные версии архивов сохранены.
Native-пробы подтвердили сравнения дат, минимальную дату и кратность массива.
Native XBQL standalone Script не компилирует. Поддержка первого среза явно
отмечена как расширение адаптера: в прочитанной справке 9.3 описан последний.

Фильтр внутри аргументов виртуального источника, явное/автоматическое
разворачивание периодов, периодические константы и параметризованные сохранённые
источники остаются UNSUPPORTED. Три точных внешних XBQL используют `&`-параметры:
их связывание требует Query API этапа №44; исходники не переписывались.

`Изменения` означает регистрацию обмена платформой, а не разность движений.
Планы обмена, НеудаленныеОбъекты, хранилища настроек, локали пользователей и
проверка прав требуют native lifecycle и не подменяются авторскими строками.
Таблицы контрактов сущностей исключены по версии: удалены после платформы 7.0.
Полное исполнение query-каталога и платформенная компиляция не заявлены.

## Приёмка

[Baseline](query-stage-043-baseline.json) сохранён до реализации: **27** записей,
точные contractId/sourceHash/range и прежние причины. Scoped-обновление
[каталога](query-stage-043-coverage.json) даёт **5/5/5/5**
parsed/planned/executed/independentlyAssessed: прямой литерал Dvizhok и четыре
точных review templates (slice-last, slice-first, balances, turnovers).
Остальные 22 записи сохраняют явные причины; documentation-index не считается
исполнимым критерием даже при наличии переносимых тестов семейства.

Два переносимых проекта дали 46 основных сценариев; отдельно проверены девять
пустых, шесть граничных и семь случаев captured параметров/нескольких
измерений/ресурсов/исходных неактивных строк. Dvizhok исполняется прямо из
неизменённого архива. Авторские expected зафиксированы до исполнения;
шесть допустимых бизнес-мутаций получили **SBSL FAIL**, альтернативный агрегат
`СУММА(Q.TotalОборот + 0)` — PASS.

**39** различных тестов прошли: 14 новых, 25 затронутых прежних. Публичные
`test`/`run` дали по **2/2**, контроль — FAIL → UNSUPPORTED → PASS,
unavailablePoints = 1. Два свежих batch — **3/0/3**, все cacheHit = false;
**46** артефактов прошли JSON Schema. **Девять PostgreSQL-сценариев** проверили
выбранные переносимые источники, повторные снимки/rollback и прямой реальный
корень; независимый SQL-аудит и cleanup успешны.

YAML 36 файлов новых проектов проверен xbsl-validate: ошибок нет, девять
предупреждений относятся к контейнерам проекта/подсистем. Первичные ошибки
и отдельные успешные повторы сохранены в `result/virtual-tables/`, SHA-256
свидетельств включены в [измерения](query-stage-043-measurements.json).
Исправлены начальные ошибки структуры native-пробы, генерации констант,
транзакционного fixture, nullable-регистратора, маршрутизации captured helper
и вызова batch API. Дополнительный отказ при смешивании scalar/array
параметров одного имени исправлен привязкой inference к текущему методу. Отдельно сохранены синтаксическая ошибка при правке и два
ошибочных имени селектора прежних тестов; точные методы прошли повторно.

У прежних отрицательных probes поменялся только неподдержанный исходник:
первый срез теперь допустим, поэтому используется Changes; числовой IN теперь
допустим, поэтому используется несовместимая строка. Прежние expected,
четыре архива и SHA-256, лимиты, CI/nightly и чужие workspace outputs сохранены.
Полный discovery, 303 формы, все 44 прежних корня, четыре validate и полная
регрессия локально не запускались. Следующее — [№44](tasks/044-result-and-resources.md).
Воспроизведение — [README корпуса](../tests/corpus/virtual-tables/README.md).
