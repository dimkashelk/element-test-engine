# E01 и E02 — коллекции, пары и обработчики наборов

Реализовано 14 октября 2026 года. Контракт исполняет исходный XBSL в Script
10.0.2-1; Python разрешает типы и генерирует адаптеры. Тела исходных методов
сохраняются, expected не участвует в генерации и исполнении.

## E01

`ЧитаемаяКоллекция<T>` и `Коллекция<T>` принимают JSON-массивы. В Script
создаётся отдельный типизированный `Массив<T>`, реализующий оба интерфейса,
включая пустой вход. `КлючИЗначение<K,V>` принимает объект с ровно двумя
полями `Ключ` и `Значение`; ключ может иметь любой поддержанный тип.
Свойства самой пары остаются readonly, вложенное значение сохраняет свой тип.

Разрешение рекурсивное: вложенные коллекции/пары, nullable и номинальные
ссылки с полным владельцем. Некорректная арность и teacher-значения отклоняются.
Номинальные ссылочные union используют прежний тег `{type, value}` №54,
в том числе внутри пары. Одинаковые ID разных владельцев не смешиваются.

Native JSON Script не умеет сериализовать `КлючИЗначение`. Поэтому известные
типизированные границы результата, аргументов, trace и полей используют
рекурсивный транспорт `{Ключ, Значение}`; коллекции передаются массивами.
Пары не заменяются fake-структурами. Непрозрачный `Объект` с динамически
вложенной парой требует явного типизированного контракта.

Каждое sequence-действие материализует свои аргументы заново; сохранённые
снимки предыдущего действия не меняются. Массив и Соответствие сохраняют
прежние входы и поведение; ограничение fixture Соответствия строковыми
ключами этим расширением не меняется.

## E02

При доказанном исходном вызове записи набора план добавляет его
`ПередЗаписью` и `ПослеЗаписи` как дополнительные корни, включая их исходные
зависимости и методы экземпляра. Чтение и начальные teacher-данные сами по
себе не делают обработчики достижимыми. Ошибочные сигнатуры отклоняются.

Семантика сверена по справке **Элемента 9.3** через авторизованный браузер:
[набор РС](https://1cmycloud.com/console/help/element/9.3/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/InformationRegisterName.RecordSet_ru/)
и [набор РН](https://1cmycloud.com/console/help/element/9.3/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/AccumulationRegisterName.RecordSet_ru/).
РС описывает однопараметрические hooks; РН — hooks с `Замещать: Булево`
и объявленными `ПараметрыЗаписи`. Адаптер поддерживает обе сигнатуры без
результата и передаёт один экземпляр параметров до/после записи.

Порядок: начало границы записи → ПередЗаписью → проверки и сохранение строк →
ПослеЗаписи → завершение границы. Изменённые в ПередЗаписью строки участвуют
в сохранении; ПослеЗаписи видит уже сохранённое состояние через новый набор.
В режиме дописывания буфер очищается при сохранении согласно прежнему API.

Savepoint охватывает оба hooks и все связанные эффекты в `ТестСессия`,
включая вложенные записи объектов/регистров. Исключение откатывает сохранённый
набор и связанные записи целиком, даже при `storage.lifecycle: false`.
При `lifecycle: true` дополнительно сохраняются проверки метаданных №50.
Откат хранения не отменяет произвольные изменения локальных переменных XBSL.
PostgreSQL публикует состояние после завершения границы; при ошибке публикация
незавершённых эффектов подавляется. Начальные наборы обходят hooks и сохраняют
проверку teacher-данных прежним typed API.

Сопутствующее исправление: captureException/observeFailure теперь передают NULL
при отсутствующем результате метода с nonnullable return type, вместо попытки
привести NULL к этому типу.

Native блокировки, конкурентные записи, подписки `@Подписка`, дополнительные
API фильтра E03 и подчинённый РС E10 этим контрактом не реализуются.
Сохранены существующие причины UNSUPPORTED для неизвестных операций.

## Приёмка и воспроизведение

`tests/test_engine_e01_e02.py` содержит переносимые исходники с изменёнными
именами владельцев, независимые ожидания и оценивание SBSL PASS/FAIL.
Проверены пустые/nullable входы, вложенные пары и равные ID разных владельцев,
отдельные аргументы и снимки sequence, транспорт исходного внешнего модуля,
замещение/дописывание, оба hooks вместе и по отдельности, порядок hooks,
изменение строк, бизнес-отказ до записи и исключение после записи. РС проверен
с lifecycle и без него, РН — с параметрами записи. PostgreSQL имеет отдельный
аудит сохранённой таблицы, который сравнивается с teacher-ожиданием.

```bash
ELEMENT_TEST_DOCKER_TESTS=1 PYTHONPATH=tests \
  python3 -m unittest test_engine_e01_e02 -v
```

Итог: **72 различных теста успешны**, включая восемь новых тестов E01/E02.
Сохранены 26 изолированных исполнений: 16 memory и 10 PostgreSQL с отдельным
SQL-аудитом; 18 независимых правильных expected дали PASS и 18 неверных — FAIL.
После последнего исправления импортов повторены 19 затронутых тестов, все PASS.
