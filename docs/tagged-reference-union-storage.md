# Тегированное хранение ссылочных union — №54

Контракт `tagged-reference-union-v1` хранит конкретный тип ссылки вместе с ID.
Он применяется к union из двух или более номинальных `.Ссылка`, с nullable или
без него, в реквизитах справочника/документа и полях ТЧ. Типы разрешаются по
метаданным, namespace и импортам исходника. Одинаковые короткие имена и одинаковый
UUID у разных владельцев сохраняют разную идентичность.

## Формат и вход

Для `Data::Item.Ссылка|Other::Item.Ссылка|?`:

```json
{"type": "Other::Item.Ссылка", "value": {"Идентификатор": "22222222-2222-4222-8222-222222222222"}}
```

`type` — полный owner метаданных и `.Ссылка`, а ID соответствует `storage.idType`
(`Строка` либо `Ууид`). `null` означает nullable, нулевая ссылка — выбранный тип
с нулевым UUID. Правило `НезаполненноеЗначение: ЗапретитьВсегда` отклоняет оба
неполных значения; для строкового профиля пустой ID — пустая строка.

Неоднозначный JSON без тега отклоняется при подготовке. Неизвестный/чужой тип,
нестроковый тег и неверный ID дают ошибку задания (`invalid_test`), без угадывания
по форме JSON или порядку членов union. Входной тег разрешается тем же механизмом
метаданных, а сохранённый и наблюдаемый тег всегда имеет полный owner.
Nonnullable union требует значения при явном конструировании объекта/строки;
`СоздатьОбъект()` без обязательного union-поля возвращает недоступность вместо
выбора первого варианта.

Одиночные ссылки и скалярные union сохраняют прежнее публичное представление.
Для составного объекта меняются только поля, содержащие ссылочный union.
В IR `referenceCodec` публикует версию хранения, `observationContract:
nominal-reference-union-v1`, варианты полей и nullable. Отдельные новые публичные
YAML-типы и флаги не добавлены; прежние expected массово не переписывались.

## Сквозное применение

Python генерирует адаптеры по разрешённым типам. Сериализацию, восстановление
номинального значения и копирование выполняет Script. Общий codec используется
для начальных fixtures, записи/загрузки, `До`, результатов/контекста формы,
`snapshotArgs`, trace, query DTO, данных и формул отчётов. Он обходит структуры и
массивы ТЧ, сохраняет порядок, повторы и nullable. Копии строк и ссылок независимы.

`ЗагрузитьОбъект()` использует owner конкретного варианта и читает свежее
сохранённое значение. Native сравнение ссылок одного владельца с одним ID даёт
равенство; разные владельцы с тем же ID различимы.

Регистраторы сохраняют прежний JSON строки; их тип находится в полном
типизированном ключе фильтра. Codec ключа использует тот же полный owner,
запросы принимают также прежнее имя типа регистратора. При чтении набора каждая
строка получает свежую номинальную ссылку из фильтра. Остальные union-поля строки
регистра используют обычный тегированный формат.

Отказ `ПослеЗаписи` откатывает сохранённый объект, ID и связанные движения
вместе. Свежая загрузка видит прежний вариант. Живой объект остаётся попыткой
записи по существующему lifecycle-контракту. Memory и PostgreSQL публикуют
эквивалентные нормализованные снимки. SQL JSON содержит полный тег; доверенный
SELECT-аудит проверяется относительно независимого ожидаемого состояния.

## Проверка и границы

[Тесты](../tests/test_tagged_reference_unions.py) проверяют A → B → NULL → A,
одинаковые ID, нулевой UUID/NULL, обязательность, nonnullable, несколько строк
ТЧ с повторными ссылками, независимый `До`, trace и загрузку свежих данных,
ошибку hook и откат движений, query/report, запись формы справочника и union-ресурс
регистра. [Два переносимых набора](../tests/corpus/tagged-reference-unions/README.md)
исполняются с другими namespace/владельцами/полями. Импорты и обратный порядок
вариантов проверяются отдельно. [Измерения](test-type-stage-054-measurements.json)
разделяют исполнение fixtures и подготовку финального архива.

```bash
ELEMENT_TEST_DOCKER_TESTS=1 PYTHONPATH=.:tests \
  python3 -m unittest test_tagged_reference_unions -v

bin/element-test test --project tests/corpus/tagged-reference-unions/ordinary \
  --assignment assignments/tagged-reference-unions/assignment.yaml \
  --output result/reference54-public
```

Публичный пример намеренно содержит независимый неверный expected и недоступный
сценарий: PASS/FAIL/UNSUPPORTED, 2/4 балла и 3 недоступных балла; exit code 1.
Batch дополнительно запускает исходную мутацию движения и получает FAIL.

Исходный режим 9.0 сохранён. Проверены Script 10.0.2-1 с исполнением 9.0 и
профилем 9.3/current, оба типа ID. Точный `Dvizhok-final.xdump` проходит свежие план
и генерацию декларативной записи `ПоступлениеДенежныхСредствФормаОбъекта` для
memory/PostgreSQL с `storage.lifecycle: true`, без изменения архива. Бизнес-методы
денег ещё не принимаются: это №56 после независимой матрицы №55.

За границей: произвольные объектные union и смесь нескольких ссылок со скалярами
(точный отказ подготовки), миграция production SQL, native права,
конкурентность и удаление ссылочных объектов. Полная репозиторная регрессия и
бизнес-набор финального дампа остаются отдельными этапами.
