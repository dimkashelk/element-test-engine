# E09–E11: подробные итоги, подчинённый РС и условия навигации

Реализовано 14 октября 2026 года. Python разрешает декларации, типы и ссылки;
движения, чтение, условия и откат исполняются в Script. Оценивание остаётся
в SBSL. [Измерения и журналы](engine-extensions-e09-e11-measurements.json).

## E09: ОстаткиИОбороты по регистратору и записи

Поддержаны периодичности `Регистратор`, `Запись` и `Авто` с полями
`Регистратор`, `Индекс`, `НомерСтроки`, `ПериодЗаписи`, включая несколько
номинальных типов регистратора. Измерения сохраняются в группировке, даже
когда SELECT их не выводит. По записи группировка сохраняет регистратор и
индекс, включая повторные движения с одинаковыми измерениями и временем.
По регистратору такие движения суммируются.

```xbsl
Запрос{
    ВЫБРАТЬ Период, Регистратор, Индекс, НомерСтроки,
        AmountНачальныйОстаток, AmountОборот,
        AmountПриход, AmountРасход, AmountКонечныйОстаток
    ИЗ Ledger.ОстаткиИОбороты(%S, %E,
        ПериодичностьИтоговРегистраНакопления.Запись,
        СпособДополненияПериодовРегистраНакопления.ЗаписиИГраницыПериода)
}
```

Начальный остаток группы включает предшествующие движения; конечный
дополнительно включает движения группы. Оборот равен приходу минус расходу.
Положительные/отрицательные части вычисляются отдельно. Неактивные записи
исключаются. Сумма оборотов подробных строк совпадает с оборотом за интервал;
остатки разных временных точек не являются суммируемыми ресурсами.

Порядок **модели**: время движения, строковое сравнение JSON номинального
ключа регистратора (тип и идентификатор), индекс строки внутри сохранённого
набора. Порядок выдачи SELECT задаётся ORDER BY. Полный тип в ключе различает
одинаковые ID разных документов. Порядок native БД при совпадении времени
этим правилом не проверяется.

`ЗаписиИГраницыПериода` добавляет отдельные строки на явно заданных границах
для измерений с активной историей до конца интервала. На начальной границе
остаток считается строго до неё; на конечной — включая движения в этот момент.
Граничные строки имеют нулевые обороты, одинаковые начальный/конечный остатки,
`Регистратор: Неопределено`, `Индекс: Неопределено`, `НомерСтроки: Неопределено`.
Они сохраняются при совпадении времени с движением и при отсутствии движений
внутри интервала. `Записи` выводит группы движений. Пропущенная граница не
ограничивает историю и не создаёт искусственную граничную строку. Обратный
интервал и пустая история дают пустой результат.

Поля и типы сверены по [справке Элемента 9.3](https://1cmycloud.com/console/help/element/9.3/docs/stdlib/element/xbql/Std/AccumulationRegisterName/AccumulationRegisterName.BalanceAndTurnovers_ru/).
Каждое исполнение ранее созданного запроса заново читает текущую сессию:
перезапись меняет результат, откат восстанавливает его, старые результаты
остаются независимыми снимками. Memory и PostgreSQL используют один расчёт Script.

## E10: подчинённый регистратору РС 10.0

Добавлен отдельный runtime-профиль `10.0` с установленным Script 10.0.2-1
и режимом исполнения `current`. Конфигурации 9.0/9.3 и режимы исходных проектов
сохранены. Объект с `РежимЗаписи: ПодчинениеРегистратору` требует исходный
профиль 10.0 или выше; старый проект с таким режимом получает UNSUPPORTED.

```yaml
ВидЭлемента: РегистрСведений
Имя: History
РежимЗаписи: ПодчинениеРегистратору
Периодичность: День
Измерения:
  - {Имя: Key, Тип: Строка}
Ресурсы:
  - {Имя: Amount, Тип: Число}
Реквизиты:
  - {Имя: Регистратор, Тип: "Act.Ссылка|Other.Ссылка|?"}
```

Регистратор должен быть номинальной ссылкой документа; допускаются nullable
и union ссылок. Фильтр содержит только `Регистратор` и требует явного значения,
включая явно заданное `Неопределено`. Фильтр по измерению, пустой вызов
Установить и ведущие измерения остаются вне контракта подчинённого РС.

```xbsl
знч R = новый History.НаборЗаписей()
R.Фильтр.Установить(Регистратор = DocumentRef)
R.ДобавитьЗапись(Период = D, Key = "first", Amount = 9)
R.Записать()
R.Прочитать()
```

Добавление требует инициализированный фильтр и копирует его регистратор в
новую строку. Измерения, ресурсы и обычные реквизиты передаются именованными
параметрами. Строки имеют системную `Активность` (по умолчанию Истина);
поддержаны явный параметр Активность и `УстановитьАктивность` для строк набора.
Чтение набора включает неактивные записи; срезы учитывают только активные.

Замещение удаляет строки своего номинального регистратора; пустой набор
реализует отмену. `Замещать = Ложь` сохраняет прежние строки и очищает
записанный набор. Уникальность проверяется по полному набору **измерений и
периоду**, в том числе между разными регистраторами. Конфликт или несоответствие
фильтру выявляется до публикации таблицы. Общая транзакция, metadata validation
и исходные hooks используют прежние границы отката. Tagged codec сохраняет
owner при одинаковых ID; независимый РС сохраняет свои фильтры и историю.
Периодичности: прежние Непериодический/День; Секунда/Момент — в ранее
опубликованных границах lifecycle.

Сверены [набор](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/SubordinatedInformationRegisterName.RecordSet_ru/),
[фильтр](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/SubordinatedInformationRegisterName.RecordSet.Filter_ru/)
и [ключ записи](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/SubordinatedInformationRegisterName.RecordKey_ru/).
Обмен, права и дополнительные API ключей остаются за пределами storage-модели.

## E11: условия над живым контекстом

Видимость/Доступность групп и команд компилируются через типизированный AST
и вычисляются в Script на каждом resolve/open. Родительские условия наследуются;
скрытые дочерние декларации также проходят проверку типов/API. Поддержаны поля
и вложенные структуры/ссылки, литералы, скобки, `и`/`или`/`не`, арифметика,
сравнения совместимых скаляров и условное выражение. Чтение объявленных констант:
`Settings.Получить().Limit`. Неизвестные методы и небулевый результат получают
UNSUPPORTED. Произвольные вызовы и implicit narrowing nullable-значений не добавлены.

```yaml
navigation: {schemaVersion: 1, navigation: {name: Menu, namespace: Data}}
navigationContext:
  Show: true
  State: {type: "Data::State", value: {Ready: true, Amount: 2}}
constants: {"Data::Settings": {Limit: 3}}
navigationActions:
  - {operation: resolve}
  - {operation: open, selector: {caption: Entries}}
  - {operation: set, path: State.Amount, value: 4}
  - {operation: open, selector: {caption: Entries}}
  - {operation: setConstant, owner: "Data::Settings", path: Limit, value: 5}
  - {operation: open, selector: {caption: Entries}}
```

В исходном YAML команды: `Видимость: '=Show и State.Ready'`,
`Доступность: '=State.Amount >= Settings.Получить().Limit'`.
Для примера результаты открытий: blocked → opened-model → blocked.

Простые входы сохраняют прежнюю форму и выводят типы Булево/Число/Строка;
прочие входы задаются через type/value и проходят общий номинальный resolver.
`set` и `setConstant` — явные fixture-действия с проверкой пути/типа.
Каждый action сохраняет независимый снимок. Константы заново читаются при
вычислении условия и инициализируются заново в каждой сессии. План сохраняет
исходные позиции, условия и зависимости контекстных типов/констант;
вычисляемые флаги плана имеют значение null до исполнения. Прежние статические
флаги плана сохраняются.

Результат по-прежнему описывает открытие модели. DOM, обработчики открываемой
формы, права и native поверхности остаются внешним контуром.

## Приёмка

`tests/test_engine_e09_e11.py`: независимые истории и ожидания для двух namespace,
одинаковых ID разных типов, повторных движений, обеих границ, неактивных строк,
свежих запросов и rollback. PostgreSQL-проверки читают таблицы отдельным SELECT.
Публичные проверки для каждой задачи проверяют PASS, неверное ожидание FAIL,
UNSUPPORTED с недоступными баллами и два изолированных submission в batch.
Ожидания бизнеса не берутся из первого запуска; для навигации из плана
используется только техническая идентичность маршрута.

Новая приёмка: **13 тестов прошли**, включая Script/PostgreSQL, публичный batch
и дополнительную проверку импортированных одноимённых документов.
Затронутая регрессия: **40 прошли**, одна старая инфраструктурная проверка
пропущена за своим opt-in. Всего **53 уникальные успешные проверки**.
Точные результаты записаны в [измерениях](engine-extensions-e09-e11-measurements.json).

```sh
python3 -m unittest discover -s tests -p test_engine_e09_e11.py -v
ELEMENT_TEST_DOCKER_TESTS=1 python3 -m unittest discover -s tests \
  -p test_engine_e09_e11.py -v
```

Закреплённые Docker-образы приводятся к `repository@digest` перед использованием:
локальный daemon не разрешал форму tag@digest для уже имеющегося образа.
Digest и содержимое образов сохраняются; автоматическое скачивание выключено.
Полный discovery, исходные архивы и nightly CI этой работой не изменяются.
