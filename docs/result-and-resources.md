# Query API, результат и ресурсы — №44

Задание завершено с **явной эмуляцией платформенных механизмов** по указанию
пользователя. Приложение в 1cmycloud.com для приёмки не требуется.

Реализован общий ограниченный адаптер XBQL → типизированный AST → Script →
storage → независимая SBSL-оценка. Выполнение не зависит от названий проектов,
Python не вычисляет бизнес-строки, expected отсутствуют в плане и renderer.

## Исполняемый контракт

- Литералы запросов сохраняют captured параметры; типизированный
  `ПроизвольныйЗапрос` принимает исходный и вычисляемый текст, именованные
  `&Name`, допускает пустой конструктор и последующую замену `Текст`.
  Конечные семейства исходных строк используют общий типизированный AST;
  текст из параметров и меняющаяся схема колонок разбираются в Script.
  Неверный текст можно сохранить; ошибка возникает при `Выполнить`.
  Исторический `ЗапросСВыборкой(Text)` получил явный эмулятор с тем же API;
  это не подтверждение native-сигнатуры исторического типа.
  `УстановитьПараметр` допускает неизвестные имена и повторную установку.
  Отсутствующее значение и неверный тип проверяются при `Выполнить` в Script.
  Параметры IN могут быть скалярными массивами с доказанным исходным типом.
  Повторное выполнение читает текущее staging-хранилище и создаёт новые строки.
- Receiver разрешается по локальному исходному объявлению запроса/результата
  до адаптации. Проектные модули, структуры, callback и одноимённые методы
  сохраняют свой контракт. Неизменяемые локальные alias запроса/результата
  поддержаны. Переприсваивание и неподтверждённые потоки остаются недоступны. Исходный текст и диапазоны сохраняются; внутреннее
  преобразование `&` в `%` не меняет длину текста и защищает строки/комментарии.
- `РезультатЗапроса<T>` получает конкретный номинальный тип строк. Поддержаны
  один обход, `ВМассив`, `Пусто`, `Первый`, `ПервыйИлиНеопределено`,
  `Единственный`, `ЕдинственныйИлиНеопределено`, идемпотентный `Закрыть`.
  Последняя полученная строка и пустой результат освобождают ресурс автоматически.
  Второй обход и обход после явного закрытия отклоняются. Пустой автоматически
  закрытый результат допускает свой первый пустой обход.
- AST-преобразование `для` сохраняет порядок, continue, break, return и throw;
  доступны переменная результата и непосредственный `Q.Выполнить()` в цикле.
  `исп` доказанного результата закрывается в finally на границе своей области,
  включая вложенные области и досрочный выход. В trace фиксируются open/close.
- `ПОРОДИТЬ Имя` создаёт readonly поля по проекциям, имя и номинальная
  идентичность принадлежат исходному модулю. Публичного конструктора нет.
  Аннотация видимости сохраняется в AST. Доступные порождённые типы можно
  передавать между модулями через квалифицированное имя; недоступное имя и
  попытка публичного конструирования отклоняются.
- `ЗАПОЛНИТЬ` сначала сопоставляет имена, затем позиции. Позиционное заполнение
  использует порядок конструктора; дополнительные обязательные параметры
  отклоняются, умолчания и readonly сохраняются. Общий mapping применяется
  к простым запросам, joins, projections и composites. Поддержана исходная
  скалярная структура с `обз`, `знч`, literal-умолчаниями и конфигурацией
  `@ИменованныеПараметры конструктор`, подтверждённой native-пробой.
  Nullable и `Объект` могут сужаться к типу параметра при чтении строки:
  преобразователь вызывается отложенно, исключение освобождает результат.
  Поддержаны проверенные в установленном Script однострочные конструкторы
  `Дата`, `Время`, `ДатаВремя`, `Момент`, `Ууид`; их валидация выполняется native.
- Динамическая строка поддерживает readonly свойства и доступ `Row["Name"]`.
  Неизвестная колонка вызывает исключение. Сохраняется происхождение строк
  в циклах, `Первый`/`Единственный`, `ВМассив` и локальных alias; повторное
  использование имени в разных областях не смешивает схемы.
- `УстановитьИсточникДанных` принимает массив объявленных структур, допускает
  неиспользованные имена и замену значения. Источник `ИЗ &Name` проходит через
  общий AST/renderer; каждый запуск получает самостоятельный снимок.
- `ПолучитьОписанияКолонок` возвращает имена и native-множества типов,
  доступные также после закрытия результата. Квалификаторы проекций
  `ВЫРАЗИТЬ` сохранены. Для неквалифицированных типов эмулятор явно использует
  число 32/32 и неограниченную строку/байты с длиной 0; это fake-значения,
  которые не заявляются как квалификаторы реальной базы Элемента.

Режим результата включается через `queryResults: true`, доказанное использование
`Закрыть`/`ПолучитьОписанияКолонок`, сигнатуру `РезультатЗапроса<T>` или динамический Query API. Прежние
критерии без этих признаков сохраняют режим materialized-array. Конкретный
режим и действительный rowType отражены в execution plan.

## Основание и ограничения

Справка Элемента **9.3** прочитана в авторизованном браузере, ссылки и контракт
сохранены в [reference-9.3.json](../tests/corpus/result-resources/reference-9.3.json).
Установленный Script **10.0.2-1** запускается в режиме `current`; отдельного
режима `-c 9.3` нет. Исходные версии архивов и переносимых проектов **9.0**
сохранены. Native-пробы подтверждают методы конкретной структуры и конфигурацию
конструктора, сохраняют отказы XBQL, пользовательского generic и наследования
пользовательского ресурса от `Закрываемое`.

В executor результат — материализованные строки с состоянием однократного
обхода. Закрытие, исключения, отложенное заполнение и передачи между методами
проверяются исполнимыми сценариями; native курсор базы не заявляется.
Основание дополнения сохранено в
[completion-reference-9.3.json](../tests/corpus/result-resources/completion-reference-9.3.json).

Вычисляемый текст эмулируется через отдельный runtime AST в Script:
проекции полей с `КАК`, `ПЕРВЫЕ`, обычные скалярные/ссылочные источники и
объявленные массивы, псевдоним источника, параметры и скалярные литералы,
сравнения с `И`, порядок `ВОЗР`/`УБЫВ`, пробелы и строковые комментарии.
Схема и типы проверяются также на пустом наборе. Ошибки схемы и параметров
не превращаются в успешный пустой ответ. Исходные семейства с одной схемой
используют более широкий прежний AST, включая подтверждённые joins/срезы.
Python генерирует загрузчики из метаданных и AST; отбор, сортировка, строки
и ответы выполняются в Script. Аргументы проверки не выбирают специализацию.

Внешние `.xbql` исполняются через объявленные сохранённые источники №43 и
общий AST. Неизвестный API потребления отдельного файла не получает выдуманной
платформенной сигнатуры. Классы и overload конструктора за пределами
объявленных структур и проверенного списка скалярных конструкторов остаются
за границей эмулятора. Rich runtime XBQL, настоящий cursor, platform RLS и
произвольные alias/receiver-потоки не входят в заявленный контракт.
Эти границы описывают эмулятор; ожидание доступа к тестовому приложению снято.

## Приёмка и доказательства

Текущая приёмка: **47 различных целевых методов успешны**, включая весь
прежний набор из 35, одиннадцать новых методов и один дополнительно затронутый
runtime-тест renderer. **17 новых публичных критериев — 17/17**,
unavailablePoints 0; прежние public test/run — 2/2, контроль —
FAIL → UNSUPPORTED → PASS, два независимых batch — 3/0/3.
Десять исполнимых мутаций получили SBSL FAIL, корректные альтернативы и
восстановление после инфраструктурного отказа — PASS. Семь PostgreSQL-сценариев
проверены с независимым SQL-аудитом, rollback/повторными снимками и cleanup.
47 публичных/batch артефактов соответствуют JSON-схемам.

В каталоге обновлены **только девять** доказанных записей: восемь прежних
критериев получили свежие exact sourceHash/range свидетельства; исторический
шаблон `ЗапросСВыборкой(Text)` независимо оценён как явный эмулятор.
Остальные записи сохранены. Для 17 новых критериев также сохранены точные
sourceHash, projectSourceHash, диапазоны методов, планы и runtime evidence.
Это не исполнение всего каталога.

Первичные сбои и отдельные повторы сохранены в
`result/result-resources-completion`. В частности, исправлены обрезка строки
короче квалификатора, затенение native `Объект` в сгенерированной структуре
хранилища и сохранение evidence вычисляемого текста в публичном запуске.
Native-пробы отделены от эмуляции: три дополнительные пробы подтверждают
конструкторы/отложенный callback и сохраняют отказ native XBQL.
SHA-256 четырёх архивов совпадают с baseline. Прежние expected, лимиты и
расписание CI сохранены. Полный discovery, 303 формы, 44 прежних корня,
четыре архивные validate и полная регрессия оставлены nightly.

```bash

ELEMENT_TEST_DOCKER_TESTS=1 PYTHONPATH=tests:. python3 tests/corpus/result-resources/run_completion.py docker
ELEMENT_TEST_DOCKER_TESTS=1 PYTHONPATH=tests:. python3 tests/corpus/result-resources/run_completion.py legacy
ELEMENT_TEST_DOCKER_TESTS=1 PYTHONPATH=tests:. python3 tests/corpus/result-resources/run_completion.py public
ELEMENT_TEST_INTEGRATION_TESTS=1 PYTHONPATH=tests:. python3 tests/corpus/result-resources/run_completion.py sql
PYTHONPATH=tests:. python3 tests/corpus/result-resources/run_completion_native.py
PYTHONPATH=tests:. python3 tests/corpus/result-resources/record_completion.py
```

`record_completion.py` требует установленный `jsonschema`, проверяет уже
сохранённые свидетельства и обновляет только девять доказанных записей,
без повторного discovery и выполнения источников. Первичная приёмка №44
и её отчёты сохранены как историческое основание.
