# Интерфейс без браузера — исполняемый контракт №49

`runtime.interface` v1 добавляет декларативный вход без обязательного
`target.method`. Используется общий planner и Script executor с совместимостью
9.0. Python разрешает селекторы, типы и исходные диапазоны; привязки,
обработчики, изменения массива и таймеры исполняются в Script. Оценка и баллы
остаются в SBSL. Нового YAML `type` нет.

```yaml
type: runtime
interface:
  schemaVersion: 1
  form: {name: Panel, namespace: Alpha}
context:
  Объект: {Name: initial}
lifecycle: {isNew: true} # только для ФормаОбъекта
observe: [Объект.Name, Count]
sequence:
  - input:
      selector: {role: ПолеВвода, binding: Объект.Name}
      value: edited
  - invoke:
      selector: {role: Кнопка}
  - snapshotInterface: true
# expected задаётся автором независимо до исполнения.
```

Схема опций: [interface-options-v1.schema.json](interface-options-v1.schema.json).
Ошибки описания не подменяются результатом работы. Неизвестные API/AST,
циклические привязки и неразрешённые действия дают UNSUPPORTED. Типы входов
проверяются до генерации. Селектор использует существующий контракт
`role/dataType/binding/name/path/within/declaration`; неоднозначность сохраняет
реальные YAML-пути. Имена и порядок обязательны только при явном селекторе.

## Контексты и действия

Поддержаны `Форма`, `ФормаОбъекта<T.Объект>`,
`ФормаЗаписиНабораКонстант<T.Запись>`, `ПроизвольноеКлиентскоеПриложение`,
`СтандартноеКлиентскоеПриложениеСРазделами`. Собственные свойства и поля имеют
объявленные типы, включая enum, nullable, union и ссылки с полным owner.
Для объектной формы обязателен явный lifecycle; номер не определяет новизну.
Декларативной форме не нужен выдуманный исходный метод или XBSL-файл.

| Действие sequence | Контракт |
|---|---|
| `input: {selector, value, row?}` | Поле, флажок либо колонка. Запись типизированного значения в прямую привязку; без привязки — в именованный компонент. Колонка требует индекс `row` от нуля |
| `invoke: {selector, rows?}` | Выбор собственного исходного обработчика и проверка его сигнатуры. Кнопка получает пассивные кнопку/событие; обычная команда — пассивную команду |
| `selectRows: {selector, indices}` | Явные уникальные индексы отмеченных строк; порядок сохраняется, равные строки различаются. Таблица должна разрешать отметки |
| `invoke` с `rows: selected/all` | Команда массива получает текущие живые строки ближайшей таблицы. Одиночная команда получает одну выбранную строку того же полного owner |
| `tableCommand: {selector, command, row?, value?}` | ДобавитьСтроку, Удалить, ПереместитьСтрокуВверх/Вниз. Добавление принимает типизированную строку; удаление без row использует отметки |
| `recalculate: true` | Пересчёт поддержанных привязок в порядке зависимостей |
| `snapshotInterface: true` | Независимый сериализованный снимок |
| `method: NAME, args: [...]` | Явный void-метод текущего экземпляра, например lifecycle открытия приложения |
| `writeInterface: true` | Запись текущего объекта/записи констант при `formEffects.write: true` |
| `advanceTime/timerEvent/closeTimers` | Очередь №48; те же исходные callbacks и экземпляр контекста |

После ввода и каждого действия пересчитываются привязки Значение,
Видимость, Доступность, ТолькоЧтение, Заголовок, Представление, Описание.
Исходные формулы колонок вычисляются по текущему массиву. Зависимости
именованных компонентов сортируются топологически; цикл недоступен.
Вычисляемая привязка доступна для чтения; двусторонний ввод требует прямой
ссылки на поле. Флаги колонки, зависящие от RowData, наблюдаются как
привязки, но пока не допускаются для действий над отдельной ячейкой. Автоматическая доставка произвольных native событий изменения
не моделируется: обработчик вызывается явным `invoke`.

Ввод учитывает объявленные флаги компонента и предков, команды — видимость и
доступность. Запрещённое действие возвращает `outcome: blocked` без изменения.
Команды изменения таблицы также учитывают ТолькоЧтение. При перемещении/удалении
отметки очищаются; добавление сохраняет существующие индексы. Перемещение за
край ничего не меняет. Индекс за пределами текущего массива — явный
UNSUPPORTED, а не выбор случайной строки. Удаление по индексу сохраняет равные
соседние строки ([API массива 9.0](https://1cmycloud.com/console/help/lang/9.0/docs/stdlib/Std/Collections/Array_ru/)).

## Дерево, эффекты и наблюдения

Исходный `новый Надпись(Значение=..., Шрифт=новый АбсолютныйШрифт(...))`
адаптируется к типизированным структурам. Именованная Группа имеет живой
`Содержимое: Массив<Объект?>`; Вставить/Добавить изменяют этот массив в Script.
Начальное содержимое связывает непосредственно вложенные именованные
компоненты с теми же экземплярами из Компоненты. Это ограниченная модель
дерева; безымянные визуальные контейнеры и native компоновка не создаются.

Каждое действие возвращает `{outcome, observation}`. В observation раздельны:
`state` — пути observe/контекст, `bindings` — значения с ключами YAML-путей,
`selection` — индексы по таблицам, `constants` — сохранённые сессионные значения,
`storage` и `openings` — эффекты opt-in, `isNew` — lifecycle объекта.
Таймер добавляет часы, очередь и снимки после каждого callback. Каждый снимок
сериализуется сразу; последующая мутация живой строки его не меняет.
Структурная правильность оценивается прежним `formRequirements`, отдельно от
поведения. План содержит hashes проекта/файла, полный owner, YAML-позиции и
исходные диапазоны обработчиков. Expected отсутствует в IR и драйвере.

Запись объекта переиспользует formEffects/storage, UUID, исходные
ПередЗаписью/ПослеЗаписи и свежий независимый аудит memory/PostgreSQL.
Методный вход включает hooks в исходную closure даже при явном writeInterface.
С `storage.lifecycle: true` запись включает исходные hooks и без метода формы.
Без этого флага прямой вход допускает только owner без hooks.
Открытие из исходного обработчика использует прежний типизированный журнал
formEffects.open и явно разрешённый lifecycle целевой обычной/объектной формы.

Форма констант получает detached Запись из объявленного owner и fixture
`constants`. Ввод меняет текущую запись; только writeInterface сохраняет её в
типизированное хранилище. Последующее Получить() и наблюдение читают
сохранённую запись. С `storage.lifecycle: true` это общее storage с проверкой
ограничений и SQL-аудитом; без флага сохраняется прежний отдельный файл.
Сессия и файловая система контейнера свежие для каждого критерия и batch-работы.

## Точный остаток

Все 19 финальных UI-деклараций принимаются для состояния, поддержанных привязок,
типизированного ввода и генерации драйвера. Это подготовка инфраструктуры,
без исполнения бизнес-методов или оценки дампа. По каждому owner сохранены
[измерения](test-type-stage-049-measurements.json).

Nested собственные компоненты, встроенные поверхности, навигационные ссылки,
команды создания копии/на основании, закрытие native окна, отчёты и панель
остаются декларациями; их эффекты требуют №51 или отдельного native контракта.
Явные tableCommand не исполняют фрагмент навигации. Динамически создаётся только
Надпись с ограниченным шрифтом; произвольные конструкторы/UI API недоступны.
Произвольные обработчики изменения/асинхронные native события не доставляются.
Открытие формы констант с её native lifecycle ещё не реализовано.

Ограничения записи, параметры, общий lifecycle/отказы и хранение констант
реализованы в [контракте №50](metadata-lifecycle.md). Native семантика
сохранения и внешняя storage.transaction здесь остаются недоступны,
чтобы не потерять объявленную атомарность. CaptureException/captureCalls,
моки и probes не смешиваются с новым интерфейсным входом; для них сохраняется
обычный runtime. DOM, отрисовка и настоящая доставка браузерного события не
проверяются. Семантика модели не объявляется доказанной native семантикой 9.0.

## Расширение №50

С `storage.lifecycle: true` декларативная запись включает исходные объектные
hooks без метода формы, общую проверку ограничений и атомарный снимок сессии.
Константы используют то же хранилище и SQL-аудит. writeInterface наблюдает
outcome rejected и observation.exception при бизнес-отказе.
[Полный контракт и остаток](metadata-lifecycle.md). Внешняя storage.transaction
для interface остаётся недоступна; это отдельная граница от атомарности записи.
