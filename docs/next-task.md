# Следующее задание №13: подготовка и доставка результатов в LMS

Основание: этап 9 [плана](roadmap.md), [контракт оценки v1](grading-contract.md)
и завершённый [массовый запуск](tasks/012-batch-runner.md). `batch` уже создаёт
`batch-result.json`, независимые `grading.json` и поток событий. ТЗ требует
передать во внешнюю образовательную систему `student`, `assignment`, `score`,
`feedback` и детали проверок. Конкретная LMS, её API, учётные данные и правила
перезаписи оценок пока не заданы; их нельзя угадывать по структуре проекта.

## Цель и граница этапа

Сделать надёжный локальный контур подготовки и доставки результатов: проверить
пакеты партии, сформировать версионированные сообщения LMS, сохранить их в
устойчивой очереди и испытать доставку на локальном HTTP-приёмнике. Транспорт
должен допускать отдельный адаптер конкретной LMS без изменения оценивания.
Реальную отправку включать только после предоставления API-контракта,
адреса, способа аутентификации и правила обновления оценки. Не внедрять в этом
этапе приём работ из LMS, создание пользователей/заданий или вычисление баллов
в Python.

Предлагаемый CLI:

```bash
bin/element-test lms prepare --batch <output/batch-result.json> --outbox <каталог>
bin/element-test lms deliver --outbox <каталог> --adapter <config.json> --dry-run
bin/element-test lms deliver --outbox <каталог> --adapter <config.json> --send
```

`prepare` работает офлайн. `deliver` без `--send` ничего не отправляет;
`--dry-run` показывает количество готовых, уже доставленных и заблокированных
сообщений без персональных данных. Локальный тестовый HTTP-приёмник разрешён
для проверки `--send`; производственный адрес должен быть явно указан
преподавателем в конфигурации адаптера.

## Подготовка данных

1. Проверять `schemaVersion` и схемы `batch-result.json` и каждого
   `grading.json`. Разрешать ссылки из индекса только внутри каталога партии:
   отклонять абсолютные пути, `..`, символьные ссылки, отсутствующие и
   коллидирующие файлы. Сопоставлять `studentId`, `assignmentId`, `runId`,
   статус и баллы индекса с пакетом оценки. Не читать входные архивы студентов
   и сырые Docker/SQL-журналы.
2. Определить каноническое сообщение v1 и JSON Schema: идентификаторы студента,
   задания и запуска; `score`, `maxScore`, `unavailablePoints`; итоговый статус;
   `feedback` с ID, статусом, баллами и безопасным сообщением по каждому
   критерию. Включать `sourceHash`, режим и версию контракта для аудита.
   Поля `expected`/`actual` передавать только по явно описанной политике
   конфигурации; по умолчанию не отправлять их, так как они могут содержать
   фрагменты работы студента или данные окружения. Не включать локальные пути,
   пароли, connection string, HTML и сырые логи.
3. Не публиковать оценку автоматически для `inputError`, `incomplete` или
   работы с `unavailablePoints > 0`, даже если её итоговый статус `failed`.
   Сохранять её как `needsReview` с причиной и доступными метаданными; отдельный
   `FAIL` при полностью доступных проверках остаётся корректной оценкой SBSL.
   Не пересчитывать баллы, не масштабировать их под LMS без явного правила и не
   подменять `UNSUPPORTED` нулём.
4. Ключ идемпотентности формировать из версии сообщения, назначения,
   `assignmentId`, `studentId` и `runId`; повтор `prepare` не создаёт дубль.
   Новая проверка того же студента имеет новый `runId`: до появления правила
   LMS о замещении предыдущей оценки она остаётся отдельной записью, без
   автоматической перезаписи.

## Очередь и доставка

1. Сохранять сообщения и состояния `ready` / `sending` / `sent` / `retry` /
   `needsReview` атомарно и восстанавливаться после прерывания процесса.
   Фиксировать безопасный журнал действий и квитанцию доставки: время,
   идентификатор сообщения, статус ответа, внешний ID при наличии. Токены и
   тело ошибки сервера не сохранять. Повторный запуск не отправляет `sent`.
2. Отделить преобразование сообщения от транспорта. Для тестов реализовать
   локальный HTTP-адаптер с настраиваемым endpoint и заголовком идемпотентности.
   Производственный адаптер должен соответствовать документированному API
   выбранной LMS; произвольный endpoint из пакета студента запрещён. Секреты
   брать только из переменных окружения или защищённого хранилища; в конфиге,
   отчётах и событиях хранить лишь имена переменных. Для внешнего адреса
   требовать HTTPS и явную allowlist хостов; loopback HTTP разрешить только
   для тестового приёмника.
3. Повторять сетевые сбои, HTTP 408/429/5xx с ограничением попыток,
   экспоненциальной паузой и учётом `Retry-After`. Ошибки 4xx авторизации,
   схемы и сопоставления оставлять `needsReview` без бесконечного повтора.
   Тайм-аут, ошибочный ответ и отказ одного сообщения не останавливают другие.
   Запись `sent` делать только после подтверждённого ответа; предусмотреть
   неопределённый исход при разрыве после приёма и повтор с тем же ключом.

## Проверки и артефакты

- Фикстура партии с `passed`, чистым `failed`, `incomplete`, смешанным
  `failed + unavailablePoints` и `inputError`: только первые два случая готовы
  к отправке; баллы и статусы в сообщениях совпадают с `grading.json`.
- Повреждённая схема, несовпадение ID/баллов, выход ссылки за пределы output,
  символьная ссылка и дубликат пакета отклоняются до отправки.
- Локальный HTTP-приёмник проверяет точное тело, идемпотентность, dry-run,
  успешную отправку, 408/429/5xx, 4xx, обрыв соединения и восстановление после
  SIGINT. Повтор `prepare`/`deliver` не создаёт лишних доставок; ошибка одной
  записи не блокирует остальные.
- Проверить, что секреты, входные пути и сырые данные не попадают в outbox,
  журнал, stdout и HTTP-запрос сверх разрешённых полей. Дать JSON Schema,
  примеры, инструкции настройки и журнал тестового прогона в
  `result/poc-lms-delivery`. Обновить README, roadmap и это задание по фактам.

Критерий готовности локального этапа: сообщения соответствуют схеме, политика
публикации не снижает оценку из-за недоступной проверки, доставка на локальный
приёмник выдерживает повторы и сбои. Реальная LMS-интеграция считается
подтверждённой только после испытания адаптера на её документированном API;
до получения доступа явно отмечать её непроверенной.
