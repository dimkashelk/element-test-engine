# Эффекты форм — контракт №36

Это ограниченный адаптер standalone Script 10.0.2-1 (`-c 9.0`), а не native
клиентский UI. Исходные методы выполняются в Script, сравнение — в SBSL.
Expected не входит в IR, renderer или driver.

Явное разрешение преподавателя на каждый критерий:

```yaml
formEffects:
  write: true
  open: [Товары::ОтгрузкаФормаОбъекта]
  lifecycle:
    Товары::ОтгрузкаФормаОбъекта:
      method: ПослеСоздания
      isNew: true
      observe: [ЗаголовокФормы, ТекстИтоговЧасти, Объект.Товары]
storage:
  backend: memory # либо postgres с --integration
  idType: Ууид
```

Каждое разрешение независимо; отсутствующее разрешение сохраняет UNSUPPORTED.
`write` допускает только неявный `Записать()`/`этот.Записать()` текущей формы,
без аргументов. Проектная декларация и лексическое затенение имеют приоритет.
Смена Объект, параметры записи UI и API пассивных команд не поддержаны.
`open` содержит полные YAML owners. Разрешение учитывает namespace/import alias,
видимость и тип каждого именованного свойства. Только собственные `Свойства`
передаются в запрос; пропущенное свойство отсутствует в журнале.

Запись использует storage №29–33, Ссылка с native Ууид и все YAML поля/таблицы.
Существующий экземпляр обязан иметь Ссылка и совпадающий начальный снимок в
storage.initial; новый с указанной Ссылка не должен иметь начальную запись.
Без Ссылка новый объект получает случайный native Ууид до первого вызова.
Номер не определяет новизну. После успешной записи `ЭтоНовый()` возвращает Ложь.
Выполняются исходные ПередЗаписью/ПослеЗаписи; ПриСозданииНаОсновании не вызывается.
Автонумерация и общая валидация YAML ограничений не реализованы.

Каждая запись имеет собственную границу фиксации, если внешняя транзакция
не активна. Ошибка записи откатывает storage этой операции, сохраняет изменения
клиентского Объект и свойств формы, не вызывает следующий исходный helper и
не сбрасывает новизну. Успешная запись перед последующей ошибкой остаётся
зафиксированной. Внешний storage.transaction откатывает storage действия целиком,
но не восстанавливает клиентские значения и успешно изменённую новизну.
SQL-сбой остаётся ERROR; доверенная инфраструктура читает фактическую БД.

Наблюдение эффекта добавляет `{result, openings, lifecycle, storage}` к результату.
Sequence фиксирует storage и открытия после каждого действия, затем итоговое
storage. PostgreSQL дополнительно возвращает sqlSnapshots: начальную публикацию
и каждый зафиксированный снимок. SQL SELECT строит их из фактической smoke.objects
в той же транзакции, административный аудитор читает после исполнения; SBSL
сравнивает всю последовательность. Это не журнал возвращённых студентом значений.
Порядок открытий — порядок массива. Каждое содержит `{owner, properties}`,
а при явном lifecycle также `context`. Сериализация в момент вызова отделяет
массивы и строки от дальнейших мутаций. Аргументы вызываемого исходного метода дополнительно наблюдаются через
snapshotArgs; свойства каждого запроса открытия сохраняются всегда.
Исходные диапазоны и типы аргументов открытия находятся в IR.

Явный lifecycle создаёт новый целевой контекст из фактических именованных
аргументов запроса и YAML defaults, с отдельным пустым Объект, и запускает
указанный исходный метод. Сам созданный документ не подставляется в Объект.
Табличная YAML привязка не вычисляется. Ни открытие, ни lifecycle не означают
запись документа или движения регистров. Без lifecycle метод не вызывается.

2 октября 2026 проверено обращение к официальным страницам
[ФормаОбъекта](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/esb/xbsl/Std/Interface/Forms/ObjectForm_ru/)
и [типы компонентов](https://1cmycloud.com/console/help/element/9.1/docs/topics/interface-component-types/):
web-инструмент вернул «not accessible». Подтверждения реального клиентского
завершения записи/жизненного цикла через эти страницы нет. Native-пробы и их
выводы сохраняются в result/dvizhok-form-effects/native-probes. Предыдущие
пробы №34 обнаружили отсутствие UI типов в standalone; этот адаптер явно
определяет синхронную границу, не утверждая native клиентскую семантику.

Native-пробы UI.sbsl и Write.sbsl завершились ошибкой компиляции: standalone
не предоставляет Форма/неявный Записать. Snapshot.sbsl подтвердил detached
снимок, независимую типизированную копию целевого контекста и native UUID v4.
Транспорт, браузерное завершение записи и реальные события UI не подтверждены.
События source:begin/commit/rollback в трассе записи формы принадлежат адаптеру,
который переиспользует транзакционные примитивы storage; в исходных двух
АрхивироватьОбработчик транзакционного ресурса нет.
