# Проверка формы по описанию, контракт v1

Преподаватель один раз готовит YAML/JSON `formRequirements` до проверки работ.
`schemaVersion: 1`, `description` — исходный русский текст, `clauses` — пункты
описания с уникальными `id` и `text`, `form` — селектор имени/namespace формы,
`requirements` — критерии с `id`, `clause`, `points`, `kind`, `selector`.
`kind`: `structure` или `binding`. Каждый критерий связан с пунктом описания.
Нормализация сохраняет текст и критерии; она не вызывает языковую модель,
не исполняет студента и не извлекает ожидания из работы. Неописанные параметры
перечисляются в `underdetermined`; они не становятся ограничениями оценки.
CLI `author-form --description TEXT --contract YAML --output YAML` фиксирует
описание и проверяет подготовленную преподавателем нормализацию.

Селектор компонента: `role` (базовый generic-тип), `dataType`, `binding`
(путь поля для семантического сопоставления), `name`, `path`, `within` (селектор
предка), `declaration` (явно требуемые свойства). Имя/путь необязательны.
Без селектора критерий относится к корню Наследует. Неоднозначность сообщает
все реальные пути и делает проверку недоступной. Пути абсолютны от корня YAML,
индексы сохранены. Соседняя таблица не определяет тип RowData.
Роль `СвойствоФормы` выбирает собственное свойство по имени независимо от
его позиции в списке. Семантическая привязка сопоставляется по разрешаемому
пути в AST: `Объект.Caption` и `этот.Объект.Caption + ""` могут соответствовать
одному селектору; самостоятельное runtime ожидание проверяет значение.

Структурный критерий: `assert` с `type`, `properties`, `exists` (true/false),
`handler`, `command`, `order`. `handler: true` проверяет связь и сигнатуру;
`handler: false` запрещает собственный обработчик. Дополнительные компоненты
разрешены по умолчанию;
запрет задаётся отдельным exists:false, порядок только явным order. Типы
канонизируются с учётом namespace/import alias и владельца. Поддержанная
неверная декларация возвращает факты несовпадения; сравнение и баллы — SBSL.
Ссылки на команды проверяются структурно, без запуска их эффектов.

Runtime-критерий `binding`: `property`, `outputType`, `scenarios` — список
независимых fixtures. Сценарий содержит `context`, `steps`, `expected`.
Шаг: `snapshot`, `set: {path, value}` или `call: {method, args}`. Вместо имени
метода допустим `call: {selector, args}`: вызывается фактический исходный
обработчик выбранного компонента, поэтому его переименование разрешено.
`set.path` может адресовать живую строку массива (`Объект.Entries.0.Debit`).
Lifecycle объектной формы при вызове исходных методов задаётся явно через
`lifecycle: {isNew: true/false}`; чистый снимок не запускает lifecycle. Каждый
snapshot вычисляет исходную привязку заново в Script. Для колонки snapshot
проходит текущий источник ближайшей таблицы по порядку, сохраняя повторы.
Для Источник.Данные возвращается весь типизированный массив.
Форма без XBSL не требует target.method или искусственного исходного метода.

AST поддерживает пути полей, литералы, скобки, условие, булевы операторы,
сравнения и арифметику согласованных типов. Имена разрешаются до компиляции;
значения и выбор ветви вычисляются только Script. План хранит sourceFile,
yamlPath, исходное выражение, разрешённые символы и тип результата, не expected.
Ожидания остаются в задании и сравниваются SBSL через обычный runtime-контракт.
Координаты AST относятся к тексту после `=`, не к строкам XBSL. Массивы
сериализуются в момент снимка, поэтому последующее изменение живой строки
не изменяет предыдущее наблюдение. Union-ссылки сохраняют полный тип owner,
даже если варианты имеют одинаковые поля.

ФормаЗаписиНабораКонстант получает detached read-only Запись по Константы
в YAML владельца. Ввод неизвестных полей/неверных типов — invalid_test.
Это не native запись констант. Старые context/observe не меняются.
Ошибки требований — invalid_test; неизвестная AST/API — UNSUPPORTED;
инфраструктурный отказ — ERROR/TIMEOUT. Отсутствующий обязательный компонент
и несовместимый тип — FAIL отдельного структурного критерия. Browser/native UI,
реактивная подписка, двусторонняя запись и пиксельная компоновка не проверяются.

Для явного открытия формы через `formEffects.lifecycle` можно задать список
`bindings: [{id, selector, property, outputType}]`. Наблюдения вычисляются после
указанного исходного lifecycle в реальном контексте открытой формы и входят в
обычное независимое expected. Сохранение объекта этим адаптером не добавляется;
SQL-аудит проверяет состояние storage отдельно от detached контекста формы.

Authoring требует подготовленного преподавателем контракта; свободный русский
текст сам по себе не преобразуется CLI в критерии. Автор фиксирует требования,
fixtures и ответы до приёмки студенческих работ. Пример такого этапа — статичные
контракты `assignments/dvizhok-declarative-bindings/forms`, подготовленные для
16 предоставленных эталонных форм. Генераторы приёмочного корпуса не являются
частью оценивания присланных работ.
