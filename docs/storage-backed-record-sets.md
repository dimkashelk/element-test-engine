# Чтение наборов регистров — контракт №32

`storage-record-set-v1` — общий адаптер для Script executor `-c 9.0`.
Разрешение API, владельцев и исходных диапазонов выполняет Python; чтение,
копирование, обход, формулы, изменение строк и запись выполняет Script.
`test`, `run`, `batch` и PostgreSQL используют один ExecutionPlan и renderer.
Сравнение с ожиданиями и баллы вычисляет SBSL. Имена бизнес-методов и teacher expected
не выбирают реализацию.

## Подтверждённая семантика

2 октября 2026 года проверена официальная документация Элемента 9.1:

- [РегистрСведений.НаборЗаписей](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/Std/InformationRegisters/InformationRegister.RecordSet_ru/): `Прочитать()` заменяет содержимое набора; неинициализированный фильтр вызывает ошибку; обход выдаёт записи набора.
- [Конкретный набор регистра сведений](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/InformationRegisterName.RecordSet_ru/): порядок после записи/чтения не гарантирован; запись проверяет соответствие фильтру и уникальность, замещает либо добавляет; при добавлении набор очищается.
- [Фильтр](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/InformationRegisterName.RecordSet.Filter_ru/): заданное nullable-значение включается в фильтр, пропущенное поле не используется. API версии 9.0 принимает именованные аргументы.
- [Набор регистра накопления](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/AccumulationRegisterName.RecordSet_ru/) и [запись](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/AccumulationRegisterName.Record_ru/): строки имеют типизированный регистратор, активность, период, вид движения, измерения, ресурсы и реквизиты.
- [Свойства регистра сведений](https://1cmycloud.com/console/help/element/9.1/docs/topics/information-register-properties/): периодичности соответствуют разным временным типам; для День используется Дата.

Документация 9.1 отмечает API версии 9.0; она не доказывает наличие API
в standalone executor. Native-пробы `Native.sbsl` и `Accumulation.sbsl`
подтверждают отсутствие соответствующих пространств имён в Script.
`StructureLoop.sbsl` подтверждает, что сгенерированная структура сама не
является Обходимое. `Values.sbsl` подтверждает native Дата, формат JSON,
изменение строки в цикле, сохранение изменения в массиве и независимость
десериализованной строки и вложенной ссылки. Пробы —
[tests/corpus/record-set-reading/native-probes](../tests/corpus/record-set-reading/native-probes),
журналы — `result/record-set-reading/native-probes`.
Это доверенные пробы, отдельные от исполнения исходных работ в Docker.

## Охват адаптера

| Операция | Контракт |
|---|---|
| Владелец | Однозначный metadata РегистрСведений/РегистрНакопления; namespace/import/alias сохраняются |
| Типы | НаборЗаписей, существующий тип адаптера ФильтрНабора, Запись; схема из YAML |
| Фильтр сведений | Все измерения; период не входит в выбранный фильтр, поэтому набор охватывает несколько дат |
| Фильтр накопления | Один типизированный Регистратор, в том числе union ссылок разных документов |
| Nullable-измерение | Явный `Неопределено`/teacher null — полное заданное значение, отличное от пропуска поля |
| Установить | Значения фиксируются при вызове; порядок именованных аргументов не меняет ключ; прежняя позиционная форма адаптера сохранена для совместимости |
| Прочитать | Нет аргументов; актуальное staging-состояние текущей сессии; отсутствие строк даёт пустой набор |
| Повтор Прочитать | Новая коллекция свежих строк; предыдущая коллекция не обновляется вместе со storage |
| Обход | Только доказанный тип набора; AST-диапазон выражения оборачивается в `(выражение).Записи` |
| Изменение строки | Изменяется загруженный объект; сохранение выполняет последующий Записать |
| Очистить/Размер/Пусто | Операции над загруженными строками |
| Замещать=Истина | Замещение текущего полного фильтра; пустая запись сохраняет пустой набор |
| Замещать=Ложь | Добавление к текущим строкам; набор очищается после успешной записи |
| Соответствие фильтру | Проверяется перед сохранением для обоих видов регистра; смена фильтра требует соответствующих новых значений в строках |
| Уникальность сведений | Все измерения плюс период; ошибка не изменяет storage и делает активную транзакцию непригодной до rollback |
| Период сведений | Подтверждённое чтение: Непериодический и День. Дата имеет точность один день; время/часовой пояс не принимаются в teacher-входе |
| Период накопления | Native ДатаВремя; teacher-вход YYYY-MM-DDTHH:MM:SS без часового пояса; копирование не округляет исходное native-значение |
| Движения | Регистратор, Активность=Истина, период, Приход/Расход, измерения и ресурсы сохраняются; остатки не вычисляются |

Ключ bucket — разрешённый полный владелец регистра и JSON полей фильтра
в порядке метаданных. Для union-регистратора ключ дополнительно содержит
конкретный runtime-тип ссылки. Поэтому одинаковые UUID разных типов не
смешиваются. В loaded union-строке конкретный регистратор восстанавливается
по типизированному фильтру; каждая строка получает отдельную ссылку.
Технический nullable-slot union используется только до материализации;
teacher-данные и запись проверяются по исходной схеме и полному фильтру.

Смена фильтра, очистка набора, изменение поля или вложенной ссылки не меняют
storage до Записать. Повторное чтение видит собственные записи исходных
зависимостей и обработчиков объектов до commit. Rollback возвращает связанные
объекты и регистры; ранее завершённые операции сохраняются. Нарушение
уникальности, пойманное исходным catch, не разрешает commit повреждённой
транзакции. Отдельный инфраструктурный `.failed` не очищается rollback.

Чтение не публикует SQL и не вызывает commit. Memory и PostgreSQL читают
один staging-файл и выполняют один алгоритм. PostgreSQL публикует реальные
снимки в `smoke.objects` на прежних границах; отдельный доверенный SELECT
сравнивает опубликованные объекты и наборы. Это не native SQL-чтение набора
и не эмуляция конкурентных сессий.

План сохраняет `recordSets`: исходный символ/диапазон полного вызова и обхода,
metadata-owner, вид/периодичность, типы набора/строки/фильтра, поля, backend,
contract и ограничения. Понижение обхода вставляет скобки и `.Записи` по
проверенным AST-границам; вложенные преобразования импортов/типов сохраняются.
Локальная переменная, параметр и результат исходной зависимости проходят
разрешение типов. Проектный `Прочитать` остаётся исходным методом.

## Teacher-подготовка и сравнение

Дополнение к существующему `storage`:

```yaml
storage:
  idType: Ууид
  registers: [Data::Prices]
  initialRegisters:
    - type: Data::Prices
      filter: {Key: base, Region: EU}
      rows:
        - Период: '2026-09-29'
          Key: base
          Region: EU
          Price: 2.5
          Factor: 10
          Link: {Идентификатор: 12345678-1234-4234-8234-123456789abc}
```

До 100 наборов, до 100 строк в каждом. Требуются все поля схемы и полный
фильтр. Для накопления строки также включают Регистратор и Активность.
Union-ссылка задаётся через `{type: Qualified::Document.Ссылка, value: {...}}`.
Неизвестное измерение, неоднозначный owner, неверный тип, несовпадение
фильтра/строки, неправильная дата и повтор ключа — `UNSUPPORTED` с
`reasonCode=invalid_test` в memory и SQL, согласно прежнему контракту
teacher-ошибок. Они не становятся FAIL студента.

Подготовка пишет typed-строки тем же API до тестируемого вызова и фиксирует
отдельные `teacher:register-setup` в storageTrace. Fixtures не подставляют
ответы Прочитать. Для SQL начальное состояние публикуется до исходного метода.

`comparison: record-sets-unordered` выбирает сравнение в SBSL:
`result` сравнивается обычным способом; `storage` сравнивается по type/id,
а массив значений набора — как мультимножество с учётом повторов и всех полей.
Порядок объектов хранения и строк набора не оценивается. Иные коллекции в
возвращаемом `result` сохраняют прежнее сравнение; сортируйте их в исходном
методе, если порядок должен быть критерием. Обычное comparison по умолчанию
и максимумы существующих заданий не менялись.

## Границы и воспроизведение

Частичный/пустой инициализированный фильтр, фильтр по периоду, прямые поля
элементов фильтра, замена readonly-свойства Фильтр, чтение Момент/Секунда,
обработчики самого набора регистра, непустые параметры записи,
прочие коллекционные API набора и вычисление остатков остаются
UNSUPPORTED. Контракт движений требует Активность=Истина: неактивная
teacher-строка даёт invalid_test, исходная Записать отклоняет неактивную
строку. Обработчики объектов №29–30, mocks.registers, legacy-отгрузка
и запросы №31 сохраняют прежние контракты. `.Записи` — прежнее техническое
представление коллекции адаптера; полного native API набора оно не обещает.

```bash
bin/element-test test --project tests/corpus/record-set-reading/information \
  --assignment assignments/record-sets-information --output result/record-information
bin/element-test test --project tests/corpus/record-set-reading/accumulation \
  --assignment assignments/record-sets-accumulation --output result/record-accumulation
bin/element-test test --project Prakticheskie-primery-2026-09-30-15-20.xdump \
  --assignment assignments/record-sets-real --output result/record-real
ELEMENT_TEST_DOCKER_TESTS=1 ELEMENT_TEST_INTEGRATION_TESTS=1 \
  python3 -m unittest discover -s tests -v
```

SQL-задания имеют суффикс `-sql`, требуют `--integration` и случайный
`ELEMENT_TEST_INTEGRATION_PASSWORD` в окружении. Контрольное задание
`record-sets-control` ожидаемо содержит FAIL, UNSUPPORTED и PASS.
Начальные данные и задания воспроизводимо создаёт
[tests/record_set_fixtures.py](../tests/record_set_fixtures.py);
[приёмочные тесты](../tests/test_record_sets.py) выполняют исходники в Docker.
Реальный архив сохраняется неизменным; исходные сценарии и метаданные
переносимого корпуса находятся в
[tests/corpus/record-set-reading](../tests/corpus/record-set-reading).
