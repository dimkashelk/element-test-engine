# Частичные фильтры регистра сведений — контракт №53

Расширен 14 октября 2026 года: [E03](engine-extensions-e03-e04.md) добавляет
пустой явный фильтр, прямые поля и период в основном фильтре. Ниже — исходный
контракт №53; его прежние границы заменяются указанным расширением.

Расширение `storage-record-set-v1` для независимого регистра сведений, исходников
9.0 и Script executor 10.0.2-1 (`-c 9.0`). Фильтр задаётся непустым именованным
подмножеством измерений. Имена регистра, измерений и namespace берутся из метаданных.
Это контракт адаптера, а не native реализация регистра в standalone Script.

## Семантика и её источник

Основание — справка, исследованная в этапе №32:
[фильтр РС 9.1](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/InformationRegisterName.RecordSet.Filter_ru/)
и [конкретный набор записей 9.1](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/InformationRegisterName.RecordSet_ru/).
Она описывает именованные параметры API версии 9.0, пропуск измерения как отсутствие
ограничения, включение явно переданного nullable-значения, замещение выбранной области,
добавление и очистку набора после добавления. В документации №32 уже зафиксированы эти
правила; прежняя реализация ограничивала их полным фильтром.

Повторная попытка открыть справку 11 октября 2026 года перенаправляет на «Вход в систему»;
версионные страницы 9.0/9.3 не удалось прочитать через web. Это не новая проверка native
семантики. Повторное `Установить` в выбранной модели **заменяет весь предикат**;
значения фиксируются сериализованным снимком в момент вызова. Это явно выбранное
правило адаптера, совместимое с прежним полным фильтром; непроверенное накопление
ограничений при повторном вызове не подразумевается.

| Вызов/состояние | Модель |
|---|---|
| `Установить(Товар = X)` | Все строки товара X при любых остальных измерениях |
| `Установить(Товар = X, Поставщик = Неопределено)` | Только X с NULL в Поставщике |
| Полный именованный фильтр | Прежний полный фильтр; порядок аргументов не влияет на ключ |
| Полный позиционный фильтр | Сохранённая совместимость адаптера; официальный профиль 9.0 использует именованные аргументы |
| Повторное Установить | Сбрасывает прежнюю маску; не читает и не сохраняет строки автоматически |
| Не установлен фильтр | Чтение/запись отказывают, состояние сохраняется |
| `Установить()` | С E03: явно заданный пустой предикат всей таблицы |
| `Прочитать()` | Свежие выбранные строки, новая коллекция и отдельные вложенные ссылки |
| `Записать()` / `Записать(Истина)` | Удаляет прежние выбранные строки и сохраняет новые; пустой набор очищает только выбранную область |
| `Записать(Ложь)` | Сохраняет прежнюю историю, добавляет новые строки; успешная запись очищает набор |
| Строка вне фильтра / дубликат полного ключа | Явный отказ до изменения таблицы |

Профиль исходников 9.3 проверяется отдельно: конфигурация исполнителя использует
`-c current`, результаты сохраняют sourceCompatibilityVersion=9.3 и
executionCompatibilityVersion=current. Это проверка того же адаптера, а не подтверждение
native API Элемента 9.3 или 10.0.

## Хранимая история и атомарность

Предикат содержит только заданные измерения. Физическая область хранения определяется
**полным owner и всеми измерениями**, независимо от предиката. Идентичность строки —
полный owner, все измерения и Период у периодического регистра. Внутри прежнего формата
аудита `storage` строки группируются по всем измерениям, а уникальность периода проверяется
внутри общего результата записи. Частичный фильтр никогда не становится ключом отдельной
копии набора. Сохранены прежние пустые полные группы и формат `type/id/value`.

При записи адаптер читает общую историю, оставляет строки вне замещаемого предиката,
проверяет новые строки и уникальность полного ключа, затем группирует результат по полным
измерениям. Сессия заменяет таблицу одним сохранением файла после всех проверок. Прочие
owners не меняются. Пересечение полных и частичных фильтров не дублирует историю.

Memory и PostgreSQL выполняют один Script алгоритм над staging-файлом. SQL публикует
снимок на существующей границе транзакции. Доверенный `PostgresSession.audit` выполняет
отдельный SELECT из `smoke.objects`; технические тесты дополнительно захватывают результат
этого SELECT и сравнивают его с независимо заданными строками. Ответ runtime не служит
ожиданием SQL-аудита. Это прежняя модель staging/publication; конкурентные SQL-сессии и
native блокировки здесь не моделируются.

`storage.lifecycle: true` включает savepoint объектной записи: отказ ПослеЗаписи после
изменения нескольких регистров откатывает объект и все связанные эффекты. Ошибка SQL
публикации остаётся ERROR и не скрывается исходным catch. Полный фильтр РН и типизированный
union-регистратор используют прежний адаптер без изменения его семантики.

## План и teacher-вход

В `recordSets` сохраняются owner, schema, поддержанная операция, sourceFile/sourceHash,
символ и диапазон полного вызова. Для `Установить` дополнительно нужны:

- `filterMask`: заданные измерения в порядке метаданных;
- `filterValues`: имя, объявленный тип, исходное выражение и его диапазон.

Маска необходима: nullable NULL нельзя использовать как значение по умолчанию для
пропущенного аргумента. Генератор создаёт типизированный метод для каждой фактически
используемой маски и заменяет только AST-токен имени вызова. Исходные файлы сохраняются.
Выражения вычисляет Script. Неверное имя, повтор имени или доказанно неверный тип — ошибка
контракта; смешанная/частичная позиционная форма и пустой фильтр недоступны с точной причиной.

`storage.initialRegisters[].filter` принимает тот же непустой поднабор измерений; каждая
строка всё равно содержит все поля и соответствует фильтру. Повторы полных ключей, в том
числе между пересекающимися teacher-наборами, дают `invalid_test` до исполнения. Для РН
teacher-фильтр по-прежнему полный. Новое поле пользовательской конфигурации не требуется:
существующий `filter` уже содержит имена заданных измерений. JSON-схема допускает такой
объект и остаётся прежней; изменены семантическая проверка и описание, а не форма данных.

## Приёмка и границы

Корпус: [tests/corpus/partial-information-filters](../tests/corpus/partial-information-filters).
Три измерения, nullable-поставщик, период Момент, вложенная ссылка, второй регистр и
исходный обработчик объекта. Переносимая версия использует `Запасы::История` вместо
`Ware::Ledger`. Ожидания определены таблицами teacher-данных в
[partial_filter_fixtures.py](../tests/partial_filter_fixtures.py), проверки —
[test_partial_information_filters.py](../tests/test_partial_information_filters.py).

Публичные задания: `assignments/partial-information-filters` и вариант `-sql`.
Проверки `test/run/batch` подтверждают PASS, независимый неверный expected → SBSL FAIL,
неверный фильтр → UNSUPPORTED, `unavailablePoints` и изоляцию двух работ.
Недоступный Docker не даёт PASS; публикационный отказ SQL проверяется с последующим
восстановительным запуском. Измерения — [test-type-stage-053-measurements.json](test-type-stage-053-measurements.json).

План точного `Товары::ПоступлениеТоваров.Объект.ПослеЗаписи` проходит частичный фильтр.
Старая конфигурация аудита без lifecycle затем упирается в независимую циклическую
зависимость документ↔регистр. С `storage.lifecycle: true` генерация проходит с существующим
объединением циклических metadata-модулей №50. Свежие планы и исходные конфигурации
сохранены в `result/partial-information-filters/`. Исполнение бизнес-поступления и его
оценка относятся к №56; их успешность подготовкой плана не заявляется.

Пустой явный предикат, прямые поля и период в основном фильтре добавлены в E03;
обработчики набора — в E02. Остаются вне контракта: подчинённый РС 10.0,
native блокировки/конкурентность и произвольные новые формы API. Для чтения Момент/Секунда
требуется lifecycle-профиль №50; Непериодический/День сохраняют прежний профиль №32.
Расширение объектного ссылочного union относится к №54.

```sh
ELEMENT_TEST_DOCKER_TESTS=1 ELEMENT_TEST_INTEGRATION_TESTS=1 \
  python3 -m unittest discover -s tests -p test_partial_information_filters.py -v
bin/element-test test --project tests/corpus/partial-information-filters/ordinary \
  --assignment assignments/partial-information-filters --output result/partial-filter-public
```
