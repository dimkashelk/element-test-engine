# Именованное заполнение проектной структуры — №39

ExecutionPlan, ProjectTypes и renderer исполняют `ЗАПОЛНИТЬ` существующую
YAML-структуру через общий staged query adapter. Выбор строк, конструктор,
исходные helper, формула и округление выполняются в Script, независимая оценка
и баллы — в SBSL. Expected и история хранения не входят в query IR.

## Основания и версии

По уточнению пользователя справка Элемента 9.1 используется для проекта
с режимом совместимости 9.0. Версия официального источника сохраняется явно.
Во встроенном браузере 3 октября 2026 года прочитаны
[ЗАПОЛНИТЬ](https://1cmycloud.com/console/help/element/9.1/docs/topics/fill/) и
[литерал запроса](https://1cmycloud.com/console/help/element/9.1/docs/topics/query-literal/),
состав операторов/выражений/таблиц, а также меню версий, включая архивные.
Раздел element/9.0 возвращает 404 и отсутствует в этом меню.
Именованный подбор конструктора сопоставляет псевдонимы колонок с именами
параметров; дополнительные поля используют допустимые умолчания.
Позиционное заполнение документировано, но является отдельной очередью.

[Язык 9.0: структура](https://1cmycloud.com/console/help/lang/9.0/docs/topics/structure/)
и 11 доверенных native-проб дистрибутива Script 10.0.2-1 с `-c 9.0`
подтверждают автоматический конструктор, именованные аргументы, `обз`, `знч`,
скалярные и ссылочные умолчания, widening и округление ±1.005 → ±1.01.
Сохранены первичные отказы имени файла/неверного модификатора и исправленные
пробы. Native Запрос отсутствует: это граница standalone adapter.
Исходники — `tests/corpus/storage-query-fill/native-probes`, журналы —
`result/storage-query-fill/native/results.json`.

Native допускает передачу непустого nullable-значения в не-nullable поле,
но при Неопределено выдаёт runtime отказ. Адаптер №39 выбирает консервативный
статический контракт: T? → T отклоняется до исполнения. ГДЕ и непустой fixture
не являются основанием для narrowing. Также сохранён прежний контракт №31:
простая переменная захватывается один раз, каждое вхождение выражения — отдельно.
Справка 9.1 описывает дедупликацию одинаковых выражений; этот отличающийся
контракт отмечен в каталоге, а поведение прежнего адаптера не изменено.

## Типы и заполнение

YAML `Структура` генерируется лениво с полной номинальной идентичностью.
Сигнатура, исходный новый, helper, массив, подготовка входных значений и
результат ЗАПОЛНИТЬ используют один Script-тип. Коллизии кратких имён получают
стабильные технические имена из полной идентичности; одинаковые UUID владельцев
не объединяют типы. Поля разрешаются в namespace и Импорт самой декларации.

Поддержаны Строка, Число, Булево, Дата, Ууид, ссылки Справочника/Документа,
перечисления существующего генератора и nullable-варианты. Именованное
сопоставление независимо от порядка полей и колонок. Допустимы T → T?, T? → T?.
Пропущенные поля используют native умолчание либо явно заданный скалярный
ЗначениеПоУмолчанию. Обязательное переносится в обз, ТолькоЧтение — в знч.
Входной fixture без обязательного поля — invalid_test.
Неподдержанные свойства/аннотации/окружение/пользовательские модули структуры
отклоняются, сохраняя причину; недостижимая неподдержанная структура не мешает
соседнему поддержанному корню.

`queries[].ast.fill` хранит owner, sourceFile, type, sourceName, диапазон
предложения и имени типа относительно bodyStart, поля/defaultKind/modifiers,
constructorRequired и mapping колонка → параметр с типами и диапазонами.
Неизвестная/повторная колонка, несовместимый owner/тип, недоступная структура,
отсутствующий обязательный параметр и затенение имеют явную причину и диапазон.
Не создаются неизвестные типы; позиционного fallback нет.

## Исполнение и состояние

Обычный Справочник/Документ и дневной СрезПоследних наследуют №31/33:
параметры вычисляются при создании запроса, каждое Выполнить читает текущее
staging; после выбора среза идут ГДЕ, сортировка, ПЕРВЫЕ и заполнение.
Конструктор получает исходные значения колонок, а пропущенные поля создаёт
native. Каждый результат и каждая ссылочная колонка — свежие экземпляры,
включая две проекции одного поля. Результаты без ЗАПОЛНИТЬ сохраняют readonly.

Корпус проверяет старые снимки после записи/изменения нового результата/rollback,
однократный capture и его порядок, повторное исполнение, nullable-поля,
перечисления, helper/массив/новый/teacher args и одинаковые UUID соседних owners.
Альтернативная корректная запись с переставленными проекциями и полным именем
типа проходит те же независимые ответы.
Memory и PostgreSQL исполняют один Script. SQL независимо читает полную историю;
read-only заполнение не публикует SQL и не вызывает commit. Sticky ERROR после
catch, TIMEOUT, invalid_test, UNSUPPORTED и следующий PASS сохраняют контракт.

## Независимая приёмка

`assignments/storage-query-fill-real` содержит 16 независимых критериев
для **двух прямых неизменённых корней ДемоСРМ**: ПолучитьКурсВалюты и
ПересчитатьПоКурсу. История авторская: две валюты, несколько дат, границы,
отсутствующая валюта, ненулевая кратность 2 и нулевая кратность, дробные суммы.
Результат содержит все поля структуры, включая пропущенный Код = "".
`mocks.queries` не используется. Есть SQL-вариант.

Два переносимых проекта ordinary/daily, их memory/SQL-задания и контрольное
FAIL → UNSUPPORTED → PASS используют другие имена и namespace. Девять мутаций
реального запроса/формулы и переносимого default должны дать SBSL FAIL при
успешном исполнении. Отказ компиляции не считается бизнес-FAIL.

Публичные test/run, два свежих batch с correct → mutated → neighbor и
одинаковыми UUID, grading/batch/manifest/events Schema проверяются отдельно.
Scope batch — четыре переносимых критерия ordinary на каждую из трёх работ;
это не утверждение покрытия всего каталога.

## Каталог и очередь

`python3 -m element_test.query_catalog` воспроизводит JSON/Markdown из четырёх
неизменяемых архивов, включая оба проекта autocheck и библиотеку БазаЗнаний.
Каждый из 213 литералов сохраняет собственные contractId/файл/range/sourceHash,
target с сигнатурой, идентичность проекта/библиотеки, AST или причину отказа.
Внешние XBQL и API-кандидаты учитываются отдельно; исходные receivers и видимые
проектные декларации сохраняются. Одноимённый проектный Запрос не признаётся
системным. Строки, комментарии, вложенные скобки и malformed литералы не исчезают.

Документированные семейства имеют версионированный источник, переносимый
review fixture и конкретную очередь. **Review fixture ещё не является
исполняемым критерием.** parsed, planned, executed и independentlyAssessed
различаются; свежие планы/журналы связываются по sourceHash и точному вхождению.
Исторические оценки №31–33 не превращаются в свежую приёмку №39.

## Воспроизведение

```bash
python3 tests/corpus/storage-query-fill/build_fixtures.py
PYTHONPATH=tests:. python3 tests/fill_fixtures.py
python3 tests/corpus/storage-query-fill/run_native.py
python3 -m element_test.query_catalog
bin/element-test test --project Demo-SRM-dev-2026-09-28-21-38.xdump \
  --assignment assignments/storage-query-fill-real --output result/fill-real
ELEMENT_TEST_DOCKER_TESTS=1 ELEMENT_TEST_INTEGRATION_TESTS=1 \
  PYTHONPATH=tests:. python3 -m unittest test_storage_query_fill -v
```

SQL-задания требуют --integration и временный ELEMENT_TEST_INTEGRATION_PASSWORD.
Полный discovery, 303 формы, прежние 44 корня и четыре validate локально не
запускаются. Новые тесты обнаруживаются существующим nightly; расписание CI,
архивы, прежние expected, задания и ресурсные лимиты не меняются.
