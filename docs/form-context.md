# Контекст формы объекта — этап 34

Контекст поддержан для КомпонентИнтерфейса с основанием
`ФормаОбъекта<T.Объект>`. Это ограниченный адаптер состояния в standalone
Script 10.0.2-1 с `-c 9.0`. Клиентский UI не создаётся. Исходные тела методов,
ветки, циклы и helper исполняет Script; сравнение и баллы определяет SBSL.

```yaml
context:
  Объект:
    Номер: '42'
    Архивный: false
  РедактированиеДанных: false
lifecycle:
  isNew: true
observe:
  - ЗаголовокФормы
  - Объект.Номер
  - Компоненты.НадписьИтогиОтмеченных.Значение
```

`context` принимает только Объект, собственные свойства YAML и поддержанные
именованные компоненты из рекурсивного дерева Наследует. Имена и типы не
выводятся из текста обработчика. Поддержано `Надпись.Значение: Строка`;
остальные компоненты перечислены в IR, но их API недоступен. YAML-выражения
учитываются в карте как NOT_CHECKED, не вычисляются и не задают runtime
значение. Литерал Значение надписи задаёт её умолчание; для выражения начальное
значение адаптера — пустая строка. Собственные свойства берут YAML-умолчание
или native-умолчание типа. Контекст может явно переопределить умолчание.

Ссылки контекста формы используют native `Ууид` в Идентификатор; вход —
строка 8-4-4-4-12, UUID разных owners сохраняют различные типы.

`lifecycle.isNew` обязателен и относится к Объект текущего экземпляра.
Объект.ЭтоНовый() читает этот флаг; Номер и expected не влияют на новизну.
Жизненный цикл остаётся прежним между вызовами sequence. Смена самого Объект
требует отдельный контракт; неопределённое состояние не заменяется ложным
флагом. Техническое поле состояния не принимается во входе и не попадает в наблюдение объекта.

`ОбычнаяКоманда` и `КомандаСПараметром<Массив<T>>` принимают только `{}`.
Генерируется отдельный пассивный тип для каждой закрытой сигнатуры; API
команды не реализуется. Generic-аргумент разрешается по metadata owner.
Неподдержанные обращения, неизвестные/повторные компоненты, неверные типы
и observe-пути дают явную причину подготовки. Методы с Записать/Открыть
из формы остаются UNSUPPORTED. Проектный ЭтоНовый не подменяется адаптером.

Свойства доступны через `этот` и неявно; native область структуры сохраняет
лексическое затенение параметром/локальным именем. Проверка путей использует
AST и интервалы видимости, исходные идентификаторы не заменяются регулярным
выражением. Helper остаются исходными методами того же экземпляра.

Аргумент `{contextPath: Объект.Товары}` передаёт непосредственно объявленное
значение этого экземпляра формы. Путь разбирается как идентификаторы, его тип
должен совпасть с типом параметра. Выражения и произвольные поля не допускаются.
Для проверки отмеченных строк корпус передаёт весь подготовленный массив
этим способом и наблюдает его после вызова; изменение исходной таблицы
обнаруживается независимо от правильности текста надписи. Это fixture-связь,
а не автоматическая реализация выделения строк браузерной таблицы.

Без observe наблюдается весь поддержанный контекст. С observe результат —
словарь с точными строками путей в ключах. Возвращающее значение метода имеет
форму `{return, context}`. Sequence использует один экземпляр и сохраняет
снимок каждой операции в actions через общую сериализацию. Каждый критерий
и каждая batch-работа создают свежие значения.

## Подтверждение контракта

2 октября 2026 года в браузере прочитана официальная документация
[Элемента 9.1: тип компонента интерфейса](https://1cmycloud.com/console/help/element/9.1/docs/topics/interface-component-types/).
Компоненты даёт доступ ко всем именованным экземплярам, включая вложенные
группы. Это клиентский тип; свойство Компоненты не входит в native UI
конструктор. Наш сгенерированный конструктор служит только тестовой подготовке.
Также сверены [Надпись](https://1cmycloud.com/console/help/element/9.1/docs/topics/label-component/),
[ОбычнаяКоманда](https://1cmycloud.com/console/help/element/9.1/docs/topics/usual-command/)
и [КомандаСПараметром](https://1cmycloud.com/console/help/element/9.1/docs/topics/command-with-parameter/).
Native Значение надписи имеет тип Объект?; в №34 поддержано только Строка.
Обработчик обычной команды получает команду; параметризованной — команду
и отдельный массив. У обоих нет возвращаемого значения.

Native-пробы сохранены в `result/dvizhok-form-context/native-probes/`:
UI.sbsl подтверждает отсутствие типов UI в standalone; State.sbsl проверяет
вложенные структуры, закрытый тип команды, умолчания, затенение и изоляцию.
Объявить свою generic-структуру в этом Script не удалось, поэтому команды
генерируются как закрытые технические типы. Интерполяция числа 1.25 даёт
`1,25` на host, а Docker с локалью en-US даёт `1.25`. Адаптер форм фиксирует
JVM en-US; авторский контракт надписей использует точку без
группировки и лишних нулей. Это формат строк, не изменение числового JSON.

Приёмочное задание `assignments/dvizhok-form-context` задаёт независимо:
заголовок нового объекта, точный номер существующего; возврат редактирования
после двух переключений; тексты архивирования для обоих флагов; суммы всех
отмеченных строк с сохранением повторов; количества участников; неизменность
входных таблиц. Непустой номер нового и пустой номер существующего обязательны.
Полный UI, события, YAML привязки, запись и открытие относятся к следующим этапам.
