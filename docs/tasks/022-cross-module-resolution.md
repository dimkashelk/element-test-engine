# Межмодульные вызовы и библиотеки в runtime

Исходные XBSL-файлы остаются неизменными. Индексатор сохраняет позиции владельца
вызова в исходном методе, включая интерполяцию. Runtime обходит достижимые
методы, разрешает квалифицированные вызовы и несколько алиасов одного модуля,
заменяет только написание владельца вызова в копии метода и создаёт отдельные
SBSL-модули для внешних методов. Каждый модуль импортирует непосредственные
зависимости; цикл модулей возвращает `UNSUPPORTED/unsupported_contract` до
запуска executor.

Объявленные библиотеки добавляются в таблицу символов с префиксом
`Поставщик::Проект`. Исходник метода читается из каталога выбранной зависимости.
Метаданные `Глобально` и аннотация `@Глобально` нужны для вызова из другого
проекта; `ВПроекте` и `@Локально` закрывают такой вызов. Типы внутри библиотечного
метода разрешаются в его пространстве имён и добавляются в зависимости
сгенерированного SBSL. Граф `analyze().callGraph` теперь показывает переход из
приложения в объявленную библиотеку. Локальное имя параметра или переменной не
считается именем модуля.

Проверка: `tests/test_cross_module_runtime.py` компилирует и исполняет
квалифицированный вызов с транзитивной зависимостью и вызов библиотечного
метода в локальном Script executor. Отдельные случаи проверяют цикл, тень
имени модуля, закрытую видимость модуля и метода. Полная локальная регрессия:
114 тестов, 12 штатных opt-in пропусков.

Граница текущего решения: дерево в `indexer.py` описывает объявления и
поддержанные блоки, но не является полным AST языка XBSL. В частности,
динамические вызовы через значения и весь набор выражений/операторов платформы
не разбираются семантически. Их нельзя объявлять проверенными по одному графу
статических вызовов. Библиотечные объектные методы по-прежнему требуют
отдельного контекста; циклы импортов SBSL не исполняются.

Основание правил видимости: [документация 1С:Элемент](https://www.1cmycloud.com/console/help/esb/docs/topics/terms/scope/).
