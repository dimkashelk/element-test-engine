# Сумма стоимости товаров из `Примеры_new`

Задание выполнено на исходном `Prakticheskie-primery-2026-09-30-15-20.xdump`.
Метод `МетодыРаботыСКоллекциями::РаботаСКоллекциями.ПолучитьОбщуюСтоимость`
исполнен Script executor 10.0.2-1 в Docker с режимом совместимости **9.0**.
Сравнение результата и баллы определяет прежний SBSL-движок.

## Требование и оценка

Независимое требование взято из метода `ПостановкаЗадачи` в
`МетодыРаботыСКоллекциями/Служебное/ОписаниеПримера_ИспользованиеМетодаСумма.xbsl`:
сложить значения полей стоимости в массиве структур данных о товарах.
Количество не служит множителем или фильтром. Каждое вхождение товара вносит
свою `Стоимость`, включая товар с нулевым количеством и повторяющиеся строки.
Результат пустой суммы — 0. Поле `Стоимость` имеет тип `Число`; ограничение
на знак в постановке отсутствует, поэтому погашение отрицательного и
положительного значений проверяет арифметическую границу этого контракта.

[Задание](../../assignments/practical-total-cost/assignment.yaml) содержит
один критерий сигнатуры и восемь runtime-критериев, всего **10 баллов**:

| Критерий | Вход / независимое ожидание | Баллы |
|---|---|---:|
| Сигнатура | `Обходимое<ДанныеТовара>` → `Число`, один параметр `ДанныеТоваров` | 1 |
| Исходный пример | Стоимости 1000 + 500 + 2000 = 3500; количества 10, 0, 7 | 2 |
| Пустая коллекция | [] → 0 | 1 |
| Единственный товар | Количество 0, стоимость 500 → 500 | 1 |
| Нулевые стоимости | 0 + 0 = 0 | 1 |
| Дроби | 0.125 + 1.25 + 2.5 = 3.875 | 1 |
| Взаимное погашение | −100 + 100 = 0 | 1 |
| Повторы | Две одинаковые строки со стоимостью 7 → 14 | 1 |
| Большое значение | 1000000000000 + 1 = 1000000000001 | 1 |

## Runtime-контракт

Генератор принимает YAML-список для `Обходимое<T>` и создаёт
`новый Массив<T>([...])`. Тип элемента задаётся явно даже для пустого списка.
Сигнатура исходного метода остаётся `Обходимое<ДанныеТовара>`; преобразование
и суммирование выполняет стандартная библиотека executor, без мока коллекций.

Структура берётся из **того же исходного модуля**, а не задаётся полями задания.
Узкий контракт допускает неаннотированную `структура` с обычными полями
`пер` типов `Строка`, `Число`, `Булево`. Требуемое объявление копируется в
тестовый SBSL вместе с исходным методом; окончания строк нормализуются при чтении.
Неиспользованные структуры не включаются. Сохраняются комментарии и бизнес-логика.
Неизвестные поля, неверные типы аргументов и ввод объекта вместо списка дают
ошибку задания (`invalid_test`), а не `FAIL` студента.

Умолчания полей, аннотации, методы и другие типы полей структуры пока требуют
отдельного контракта и дают `UNSUPPORTED`. Локальная структура не подменяет
одноимённые типы другого модуля или метаданных. Структуры объектного контекста
и перенос структуры через границы модулей в этот контракт не входят.

Контролируемая ошибка внесена только в распакованную копию:
`Товар -> Товар.Стоимость` заменено на
`Товар -> Товар.Стоимость * Товар.Количество` в выражении перед `.Сумма()`.
Проверки исходного примера, единственного товара, дробей, погашения и большого
значения обнаруживают ошибку (`result_mismatch`). Пустой список, нулевые стоимости
и повторы с количеством 1 закономерно остаются успешными.

  --assignment assignments/practical-total-cost --output result/practical-total-cost/run
