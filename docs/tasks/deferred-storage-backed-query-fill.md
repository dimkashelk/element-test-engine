## Цель и приоритет

Добавить к общему query AST предложение `ЗАПОЛНИТЬ <тип>` для существующей
структуры, объявленной в YAML проекта. Строки поддержанных запросов должны
быть экземплярами разрешённого проектного типа. Исходный метод может вернуть
такую структуру, передать её зависимости и использовать поля в вычислениях.

Это следующий шаг после срезов: реальные запросы ДемоСРМ уже укладываются
в источник, границу и отбор №33, но возвращают проектную структуру, которую
нынешний `ProjectTypes.require` ещё не генерирует. Одного удаления слова
ЗАПОЛНИТЬ или переименования анонимной строки недостаточно.

Сохранить один pipeline planner → renderer → executor → SBSL для `test`,
`run`, `batch`, memory и PostgreSQL. Контракт выбирают AST, объявления,
доступность типа и типы колонок. Имена КурсВалюты, КурсыВалют, метода или
expected не выбирают реализацию. Python разрешает и проверяет типы,
генерирует инфраструктуру; выбор строк, создание значений, исходная формула
и округление исполняются Script. Сравнение и баллы остаются в SBSL.

## Проверенные реальные кандидаты

В неизменённом `Demo-SRM-dev-2026-09-28-21-38.xdump`, модуль
`Общие/КурсыВалют/КурсыВалют.xbsl`, доступны:

Точное значение `target.namespace` в модели — `Общие::КурсыВалют`,
`target.module` — `КурсыВалют`. Полная идентичность регистра для
storage.registers — `Общие::КурсыВалют::КурсыВалют`; вложенную подсистему
не сокращать до Общие при подготовке задания.

```xbsl
метод ПолучитьКурсВалюты(Валюта: Валюты.Ссылка, ДатаКурса: Дата): КурсВалюты?
    знч Запрос = Запрос{
        ВЫБРАТЬ
            КурсыВалютСрезПоследних.Валюта КАК Валюта,
            КурсыВалютСрезПоследних.Период КАК Период,
            КурсыВалютСрезПоследних.Курс КАК Курс,
            КурсыВалютСрезПоследних.Кратность КАК Кратность
        ЗАПОЛНИТЬ КурсВалюты
        ИЗ
            КурсыВалют.СрезПоследних(%ДатаКурса) КАК КурсыВалютСрезПоследних
        ГДЕ
            КурсыВалютСрезПоследних.Валюта == %Валюта
    }

    возврат Запрос.Выполнить().ЕдинственныйИлиНеопределено()
;
```

`КурсыВалют.ПересчитатьПоКурсу(Сумма: Число,
Валюта: Валюты.Ссылка, НаДату: Дата): Число` вызывает этот метод. При
найденном курсе и ненулевой кратности возвращает
`(Сумма * КурсВалюты.Курс / КурсВалюты.Кратность).Округлить(2)`, иначе — 0.
Оба корня обязательны для приёмки без правки исходника и без mocks.queries.

Регистр КурсыВалют имеет периодичность День, измерение
`Валюта: Валюты.Ссылка?`, ресурсы `Курс: Число`, `Кратность: Число`.
YAML-структура `Общие::КурсыВалют::КурсВалюты` содержит в порядке объявления:

| Поле | Тип | В проекции реального запроса |
|---|---|---|
| Валюта | Валюты.Ссылка? | Да |
| Код | Строка | Нет |
| Период | Дата? | Да |
| Курс | Число | Да |
| Кратность | Число | Да |

Порядок колонок отличается от полного порядка полей; Код должен получить
подтверждённое значение по умолчанию. Имена и схема прочитаны из архива
2 октября; это свидетельство исходника, а не доказательство платформенного
или standalone исполнения. `ПолучитьКурсыВалют` с LEFT JOIN и ЗаменитьNull
не является обязательным кандидатом этапа заполнения.

Проверка текущего planner на обоих корнях с точным namespace и пустой
teacher-историей останавливается до исполнения с причиной
`Перечисление КурсВалюты отсутствует, неоднозначно или не поддерживается`.
Это граница генерации YAML-структуры, а не отсутствие целевого метода.
После её снятия проверить и отдельную привязку ЗАПОЛНИТЬ в query AST.

## Обязательный результат

### 1. Семантика и типовой контракт

До изменения renderer проверить документацию выбранной версии и доверенные
native-пробы Script `-c 9.0`. Разделить платформенный XBQL, возможности
standalone executor и объявленный ограниченный адаптер.

На этапе подготовки найдены официальные описания
[ЗАПОЛНИТЬ в 1С:Шине](https://1cmycloud.com/console/help/esb/docs/topics/fill/) и
[структур языка 9.0](https://1cmycloud.com/console/help/lang/9.0/docs/topics/structure/).
Первое описывает подбор конструктора по именам, затем позициям, с
необязательными лишними параметрами и проверкой совместимости типов.
Второе описывает автоматический конструктор и умолчания полей.
Это не подтверждение XBQL Элемента 9.0: проверенный URL
`https://1cmycloud.com/console/help/element/9.0/docs/topics/fill/`
вернул 404. Старое описание Исполнителя 5.2 допускает создание нового типа
при отсутствии существующего; переносить это правило на текущий адаптер
без проверки нельзя.

Обязательный охват — существующая YAML-структура с автоматическим
конструктором и **именованным** сопоставлением колонок полям. Позиционный
fallback, порождение неизвестного типа и пользовательские конструкторы
отклонять явно, если они не получили отдельного подтверждённого контракта.
Не объявлять поддержку полного предложения платформы.

Проверить и зафиксировать:

- Скалярные Строка, Число, Булево, Дата, Ууид и проектная Ссылка;
  nullable-варианты этих полей. Перечисления допускаются в пределах уже
  подтверждённого генератора типов, без новой семантики преобразований.
- Присваивание T в T? и T? в T?; несовместимые ссылочные владельцы, числовое
  поле вместо строки и nullable T? в обязательное T. Не сужать nullable-тип
  по значению teacher-данных или по отбору ГДЕ. Неподдержанное потенциальное
  сужение — UNSUPPORTED, а не успешное принудительное приведение.
- Именованное заполнение независимо от порядка колонок и полей; пропущенные
  необязательные поля с неявным умолчанием типа или явным скалярным YAML
  ЗначениеПоУмолчанию. Обязательное и ТолькоЧтение должны сохранять смысл.
- Значение пропущенного Код реального типа, пустой результат, найденный
  результат с nullable-полями и поведение ЕдинственныйИлиНеопределено.
- Native округление исходной формулы на выбранных дробных значениях.
- Fresh-экземпляры структур и вложенных ссылок на каждый результат;
  допускаемую изменяемость полей определяет декларация целевого типа.
  Запросы без ЗАПОЛНИТЬ сохраняют прежние readonly-строки №31–33.

Пробы могут подтвердить создание структуры, widening, умолчания и
изменяемость в Script даже при отсутствии native Запрос. Отсутствие Запрос
не считать подтверждением полного XBQL; фиксировать границу адаптера.

### 2. Разрешение, IR и генерация YAML-структур

Разобрать предложение по токенам и проверенным диапазонам внутри текущего
AST. Разрешать краткое, квалифицированное и импортированное имя целевого
типа по тому же namespace/import/visibility, что и сигнатуры. Источник,
целевая структура и её ссылочные поля могут принадлежать разным подсистемам.
Коллизии одинаковых кратких имён разных типов не должны объединять значения.

В ExecutionPlan сохранить полную идентичность целевой структуры, диапазон
ЗАПОЛНИТЬ и имени типа, типы колонок и полей, соответствия именованного
конструктора, обязательность, readonly и выбранные умолчания. Teacher expected,
историю регистра и вычисленные ответы в query IR не включать.

Расширить общий ProjectTypes для декларации Структура, используя существующее
ленивое замыкание типов. Тот же тип должен разрешаться в возвращаемом значении,
параметрах зависимости, native-массиве, исходном `новый` и строке запроса.
Не генерировать разные номинальные типы для сигнатуры и ЗАПОЛНИТЬ.
Проверить сериализацию результата и обратную подготовку входной структуры
общим контрактом значений; не добавить специальный сериализатор курса.

Пропущенное обязательное поле, неизвестная/повторная колонка, недоступный
или неоднозначный тип, неверная схема поля, несовместимые типы и
неподдержанные аннотации/конструкторы имеют точную причину и диапазон отказа.
Если YAML объявляет неподдержанные свойства структуры, не терять их молча.
Типы вне достижимого замыкания не блокируют поддержанный корень.
Локальное затенение имени не должно превратить проектное значение в тип.

### 3. Исполнение и состояние

Использовать существующие обычные источники №31 и СрезПоследних для День
№33. Заполнение выполняется после фильтрации, сортировки и ПЕРВЫЕ текущего
контракта. Экземпляр создавать в Script через разрешённый конструктор с
исходными значениями проекций и подтверждёнными умолчаниями.

Значения параметров по-прежнему фиксируются при создании запроса; каждый
Выполнить читает текущее staging-состояние. Перестановка колонок не должна
менять captured-порядок выражений. Старый результат не изменяется после
замещения истории, записи, rollback или изменения нового результата.
Чтение не публикует SQL и не вызывает commit.

Teacher задаёт независимую начальную историю через initialRegisters и
поддержанную подготовку №32. Memory и PostgreSQL исполняют тот же Script;
доверенная инфраструктура независимо проверяет полную сохранённую историю,
периоды, ресурсы, UUID и отсутствие побочных записей. Проверить также
сценарий «запись → заполненный результат → изменение результата → повторное
чтение → rollback», включая исходную достижимую зависимость/обработчик
в уже поддержанном ациклическом графе.

### 4. Корпус и независимая оценка

Создать два переносимых проекта с другими именами структур, полей,
регистров, методов и namespace. Один источник — обычный Справочник/Документ,
другой — СрезПоследних регистра День. Использовать квалификацию и import alias,
перестановку колонок, scalar/nullable/ref-поля, пропущенное поле с умолчанием,
Обязательное и ТолькоЧтение. Показать один проектный тип в исходном новом
значении, параметре helper, возврате helper, массиве и результате запроса.

Реальный ДемоСРМ проверить в memory и SQL. Независимая история содержит
две валюты, несколько дат, строку ровно на границе, позже границы,
ненулевую кратность отличную от 1 и нулевую кратность. Нужны найденный
курс, дата до истории, отсутствующая валюта, пустая история, нулевая
кратность и дробная сумма с округлением. Expected выводить из условий
задания; не запускать проверяемый метод для подготовки правильного ответа.

Независимые мутации исходника должны давать **FAIL** через SBSL:
неверный ресурс, перепутанные Курс/Кратность, ошибочный алиас при сохранении
совместимых типов, неправильная граница/валюта, потеря деления на кратность,
изменённое округление, неверная ветка для отсутствия курса и нулевой кратности.
Ошибки типов проверять отдельно как недоступность контракта; не подменять
ими требование бизнес-FAIL. Проверить мутацию явного умолчания в fixture.

| Приёмка | Обязательное доказательство |
|---|---|
| Семантика | Версии, официальные источники, native-пробы и явные границы адаптера |
| Real | Два неизменённых корня ДемоСРМ без mocks, memory и SQL |
| Номинальный тип | Helper/сигнатура/массив/новый/ЗАПОЛНИТЬ используют один тип |
| Поля | Перестановка, умолчание, nullable widening, mandatory и readonly |
| Переносимость | Два проекта и коллизии полных идентичностей без special-case |
| Состояние | Fresh-снимки, staging, rollback и независимая история backend |
| Мутации | Достижимые бизнес-ошибки оценивает SBSL как FAIL |
| Недоступность | UNSUPPORTED не даёт бизнес-FAIL; следующий критерий PASS |
| Отказы | ERROR/TIMEOUT остаются недоступными после catch; следующий запуск успешен |
| Публичный путь | test/run/batch, повторяемость и JSON Schema пакетов |

Сохранить sticky-инфраструктурный ERROR, TIMEOUT, классификацию invalid_test,
unavailablePoints, opt-in и очистку ресурсов. Новое приложение задания
с независимыми FAIL → UNSUPPORTED → PASS должно сохранять grading-контракт.
Batch с одинаковыми UUID должен изолировать работы и давать одинаковый
результат при повторном запуске в свежий каталог; мутация второй работы
меняет только её баллы. Старые mocks остаются отдельным явным режимом.

компилируемой структуры не является выполнением задания.

## Границы

JOIN, ЗаменитьNull и другие новые NULL-операции, ПОРОДИТЬ, неизвестные
именованные типы, позиционный fallback, пользовательские конструкторы,
методы/вложенные коллекции структур, рекурсивные структуры, новые аннотации,
агрегаты и вычисляемые проекции остаются отдельными расширениями.
Для локальных XBSL-структур сохранить существующий контракт, не расширять
их грамматику ради YAML-кандидата. СрезПервых, другие периодичности,
непустые параметры записи, обработчики самого набора, циклы модулей,
именованные/вложенные ресурсы и конкурентные сессии сюда не входят.
LMS, HTTP, UI и деплой по-прежнему отложены.
