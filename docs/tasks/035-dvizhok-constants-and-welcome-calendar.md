## Подтверждённая исходная точка

Повторный read-only вызов текущего planner на исходном архиве показал:

- ПолучитьДанные обоих наборов констант и оба обработчика формы останавливаются
  на аннотации достижимой зависимости `ДоступноСКлиента`.
- ПолучитьНадписьТекущееВремя, СформироватьТекстОрганизации и ПолучитьТекстДня
  уже дают подготовленный план без context. Их фактическое исполнение и
  независимая оценка на этом архиве ещё не подтверждены.
- РассчитатьДни останавливается на неразрешённом достижимом вызове
  `ТекущаяДата.ДеньНедели`. Это отказ planner, не доказательство отсутствия
  native операции в Script.

После снятия первого отказа последовательно проверить остальные контракты.
Не считать эти причины исчерпывающим списком всех препятствий.
Основание ФормаПриветствие — `Форма`, а не `ФормаОбъекта<T.Объект>`;
№34 поддерживает только второй вариант. В YAML есть свойство Приветствие,
Надписи, ПолеВвода<Дата> ДатаНачала/ДатаКонца и Кнопка с
`ПриНажатии: КнопкаРассчитатьПриНажатии`.

## Обязательные контракты

### 1. Чтение наборов констант

Добавить явную подготовку состояния `НаборКонстант` по YAML `Константы`.
Разрешать owner через проект/namespace/import, проверять имена, типы,
дубли и значения. Непереданные константы получают объявленное YAML-умолчание
или подтверждённое умолчание типа. Fixture не добавляет произвольные поля.
Конкретный YAML-формат fixture описать в техническом контракте до реализации.

Системный `<Набор>.Получить()` возвращает типизированные данные подготовленной
сессии. Исходный ПолучитьДанные сам строит Соответствие: литералом, Вставить
и присваиванием по ключу. Не заменять этот метод готовым словарём из Python.
Проектный метод Получить или одноимённый объект другой подсистемы не
подменяется системным чтением констант.

Состояние принадлежит критерию/работе. Повторное чтение и вызовы helper
видят один объявленный набор; модификация локального Соответствия не меняет
fixture или другую работу. Проверять неизменность подготовленных констант
через независимый снимок. Запись констант, публикация и SQL-хранение
не входят в №35: достижимый неподдержанный эффект даёт точную причину,
после него выполняется поддержанный критерий.

### 2. Аннотации и native коллекции

Объявить ограниченный контракт `ДоступноСКлиента` для вызова исходного метода
в standalone executor. Сохранить аннотацию и исходный диапазон в IR;
описать, что удалённый клиент/сервер и транспорт здесь не проверяются.
Не удалять все аннотации ради компиляции. Неизвестная аннотация должна
сохранить диагностику. @Локально, @ВПодсистеме, @НаСервере и @Обработчик
разрешаются общими правилами области видимости и достижимости.

Переиспользовать уже работающие Соответствие<Строка, Строка/Булево/Число>,
их литералы, Получить, Вставить, индексирование и общую сериализацию.
Сверить native семантику отсутствующего ключа и неизменность входных словарей.
Не превращать Неопределено или ошибку отсутствующего ключа в произвольное
false/пустую строку. Закрепить это отдельными native-пробами и тестами.

### 3. Контекст обычной формы и аргументы события

Расширить декларативный адаптер №34 на `Наследует.Тип: Форма`.
Обычная форма не получает фиктивный Объект и не требует lifecycle.isNew.
Собственные свойства, defaults, рекурсивный поиск компонентов, observe,
sequence, snapshot и лексическое затенение используют общий механизм.
Чистые методы формы без context сохраняют совместимость.

Добавить только необходимый контракт `ПолеВвода<Дата>.Значение: Дата`.
Надпись.Значение остаётся строкой в поддержанном охвате. Кнопка и
СобытиеПриНажатии — типизированные пассивные аргументы `{}`; API, который
не реализован, даёт UNSUPPORTED. Настоящие нажатия, фокус, layout и рендеринг
не исполняются. Проверка YAML связывает ПриНажатии с собственным методом
и двумя параметрами правильных типов, отделяя её от runtime-вызова.

Неизвестный/повторный компонент, неверное поле/тип/observe, подмена fixture
и неоднозначный owner имеют точную причину. Компонент с именем РабочиеДни
не должен менять разрешение вызова одноимённого модуля констант.
Прочие UI-типы и выражения сохраняются в карте как NOT_CHECKED.

### 4. Дата, время, календарь и локаль

До фиксации задания сверить официальные сигнатуры текущей документации
и доверенные native-пробы Script 10.0.2-1 `-c 9.0`: Дата.Сейчас,
Время.Сейчас, сравнения, ДобавитьДни, ДеньНедели, Представление и интерполяцию
Время. Отдельно проверить переход месяца/года, 29 февраля и локаль названий
дней. Не переносить API старого Исполнителя по сходству имён.

Использовать native операции там, где они доступны. Если нужен адаптер,
объявить точную семантику и доказанное ограничение до его реализации.
Системные операции привязывать по AST и типу владельца; одноимённые
проектные методы, параметры и локальные переменные сохраняют своё значение.

Для детерминированных сценариев предусмотреть явные дату и время тестовой
сессии. Эти значения независимы от expected и доступны в IR/evidence.
Дополнительно выполнить сценарий с текущими часами, полученными внутри
Docker: фиксировать момент/часовой пояс/локаль сессии и сравнивать результат
по независимому контракту в SBSL. Host-время не заменяет Docker-время.
Определить поведение на смене суток, чтобы два вызова Сейчас не создавали
случайную несовместимость даты и времени. Конкретный формат clock fixture
и правила перехвата объявить в техническом контракте.

Названия дней должны соответствовать строковым ключам исходных настроек
на русском. Не выводить их из teacher expected. Формат Время в надписи
закрепить по native-пробе перед созданием ожидаемых строк. Не менять локаль
прежних форм №34 или исходную интерполяцию без отдельного подтверждения.

## Приёмочные сценарии

### Наборы констант и текстовые helper

- ДанныеКомпании: четыре разных заполненных строки, Unicode, кавычки,
  перенос строки и пустые/default-значения. Результат содержит ровно
  Телефон, ЮрАдрес, ПолноеНаименование, СокращенноеНаименование с правильными
  значениями; подготовленный набор не изменён.
- РабочиеДни: все false по YAML, все true, Пн–Пт и нестандартная неделя
  с рабочими субботой/воскресеньем. Все семь ключей отражают fixture.
- СформироватьТекстОрганизации: полный и пустой набор строк; точный текст,
  знаки препинания и порядок полей; входное Соответствие не изменено.
- ПолучитьТекстДня: каждый из семи дней в рабочем и нерабочем варианте;
  отсутствие ключа проверяется по подтверждённому native контракту.
- ПолучитьНадписьТекущееВремя: разные префиксы, полночь и время с секундами;
  точный формат независимо от host locale.

### ПослеСоздания

Проверить все границы приветствия: 00:00:00 и 05:59:59 — Доброй ночи;
06:00:00 и 11:59:59 — Доброе утро; 12:00:00 и 17:59:59 — Добрый день;
18:00:00 и 23:59:59 — Добрый вечер.

Наблюдать Приветствие, три надписи времени/организации/типа дня и
ДатаНачала. ДатаНачала становится датой сессии; ДатаКонца, НадписьРезультат
и константы сохраняют заранее заданные значения. Проверить рабочий и
нерабочий текущий день, разные данные компании и текущие Docker-часы.
В trace должны присутствовать исходные методы обоих наборов констант
и локальные helper; их вызов не заменяет прямых критериев.

### РассчитатьДни и обработчик кнопки

Авторский контракт — включительный диапазон и независимая классификация
каждой календарной даты по настройке соответствующего дня недели.
Обязательные результаты при рабочей неделе Пн–Пт:

| Диапазон | Календарных | Рабочих | Нерабочих |
|---|---:|---:|---:|
| 2026-10-02 .. 2026-10-02 (пятница) | 1 | 1 | 0 |
| 2026-10-04 .. 2026-10-04 (воскресенье) | 1 | 0 | 1 |
| 2026-10-02 .. 2026-10-05 | 4 | 2 | 2 |
| 2026-09-30 .. 2026-10-02 | 3 | 3 | 0 |
| 2026-12-31 .. 2027-01-01 | 2 | 2 | 0 |
| 2028-02-28 .. 2028-03-01 (с 29 февраля) | 3 | 3 | 0 |

Дополнительно: все дни рабочие/нерабочие; нестандартная рабочая неделя;
целая неделя; повторный вызов с другим диапазоном; неизменность аргументов.
Для прямого РассчитатьДни при начальной дате позже конечной ожидается
нулевой результат. Для кнопки этот диапазон даёт точный текст
«Дата начала больше даты окончания периода» без вызова РассчитатьДни.
Следующий правильный диапазон в той же sequence обновляет надпись
«Календарных: …; рабочих: …; нерабочих: …» и сохраняет оба поля дат.
Прямой helper и обработчик оцениваются отдельно.

## Общность, мутации и границы

Создать два переносимых проекта с другими именами наборов, констант, форм,
компонентов, методов и namespace. Включить одинаковые краткие имена разных
owners, import alias, вложенные компоненты и затенение параметром/локальным
именем. Подтвердить, что нет специального renderer для ФормаПриветствие.

Контролируемые мутации исходника должны давать FAIL через SBSL:
перестановка двух констант, потеря одного ключа, неверное приветствие ровно
на границе 06/12/18, неправильный текст организации/типа дня, исключение
конечной даты из диапазона, пропуск выходного, неверное накопление счётчика,
порча полей дат и потеря защиты перевёрнутого диапазона. Мутацию helper
должны обнаруживать и прямой критерий, и вызывающий метод.
Ошибка сигнатуры/компонента/неподдержанный API проверяется как отказ
подготовки, а не успешный FAIL бизнес-логики.

Проверить fresh state между критериями, sequence и двумя публичными batch
в свежие output: разные clock/константы, совпадающие UUID и одна мутированная
работа не влияют на соседние. Публичные test/run совпадают по критериям,
наблюдениям и баллам. Подготовленный план не содержит expected или готовый
текст результата. Настоящие Записать/Открыть из форм остаются вне №35.

## Отчёт о реализации

Этап добавлен в общий `ExecutionPlan → renderer → Script Docker → SBSL`.
`session_contracts.py` разрешает наборы констант по YAML/namespace/import,
проверяет поля/типы/defaults и генерирует типизированное чтение одной
подготовленной неизменяемой сессии. Исходный ПолучитьДанные сам строит
Соответствие; Python не вычисляет его результат. Проектный Получить и
затенённый owner не подменяются адаптером. Независимый снимок констант
и реальных аргументов обнаруживает порчу данных.

Общий `form_context.py` расширен обычной Формой без фиктивного Объект и
lifecycle, ПолеВвода<Дата>, пассивными Кнопка/СобытиеПриНажатии и проверкой
собственного YAML ПриНажатии. Рекурсивные компоненты, observe/contextPath,
sequence и native лексическое затенение переиспользуют механизм №34.
Системный календарь привязывается по AST и доказанному типу получателя;
исходные сравнения/циклы/ДобавитьДни/ДеньНедели исполняет native Script.
ДоступноСКлиента и её диапазон сохраняются в IR, неизвестные аннотации
дают точную диагностику. Транспорт клиент/сервер не проверяется.

[Контракт](../welcome-calendar.md) был записан до реализации. Native-пробы
подтвердили ru-RU, русские названия дней, HH:MM:SS, переход месяца/года и
29 февраля. Непереданные значения имеют native defaults. Отсутствующий ключ
не заменяется false: Получить/индекс выбрасывают Std::IllegalArgumentException,
а ПолучитьИлиНеопределено возвращает null. Пустой словарь требует типизированного
конструктора; JSON полночь — `00:00`, надпись — `00:00:00`.
Официальная документация языка сверена; разделы констант/UI Элемента 9.1
перенаправляли на вход, их API не заявляется как подтверждённый native API.

Часы fixed/docker задаются явно. Один DateTime снимок берётся внутри Docker
до исходного метода и используется всеми перехваченными нулевыми Сейчас;
смена суток не разделяет дату и время. Source transforms привязаны к AST и
незатенённым native owners. Oracle для текущих часов работает независимо в
SBSL по этому снимку, авторской неделе и границам 6/12/18; actual и helper
не определяют expected. Oracle отсутствует в плане/driver. Прежние формы
сохраняют en-US; новые сценарии явно задают ru-RU.
