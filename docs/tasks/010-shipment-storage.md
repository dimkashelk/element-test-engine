# Задание №10: отгрузка с реальным хранением и ограниченным запросом остатков

Цель: выполнить оригинальные `Отгрузка.ПередЗаписью` и `Отгрузка.ПослеЗаписи`
в Docker с реальным сохранением документов/движений и чтением остатков.
Основание: `docs/integration-environment.md`; SQL smoke подтверждает JDBC/SQL,
но пока не подтверждает платформенный объектный API и XBQL.
Завершённое задание: `docs/tasks/009-integration-environment.md`.

## Исходное состояние

- Opt-in `--integration`, PostgreSQL 17 на запуск, внутренняя сеть, tmpfs,
  ограниченная роль, preflight без fallback к mocks.
- Доверенный SQL smoke из Script executor 10.0.2-1 с совместимостью 9.0:
  INSERT/SELECT/UPDATE/DELETE, фильтрация, дроби, независимые запуски,
  очистка после ошибки; оценивание в SBSL.
- Оригинальные обработчики отгрузки работают только с mocks.
- После авторизации проверены API 9.1 с отметками применимости с 9.0:
  набор/фильтр, замещение, загрузка ссылки, запись и транзакционные обработчики
  документа, виртуальная таблица остатков. Ссылки и ограничения — в документе
  окружения; полного платформенного эталона пока нет.

## Порядок работы

1. Использовать подтверждённую документацию и проверить семантику на платформенном
   эталоне: типизированная
   ссылка, загрузка отсутствующего документа, `Объект.Записать`, `Данные`,
   `ПараметрыЗаписи`, набор/фильтр регистратора, период/вид движения,
   умолчание и замещение записи, виртуальная таблица остатков, транзакции.
   Неподтверждённые операции — UNSUPPORTED; SQL-адаптер не объявлять полной платформой.
2. Зафиксировать схему документов/движений `РегистрТовары`: тип/ID ссылки,
   дата, склад, порядок строк, номенклатура, точное количество, период и
   Приход/Расход. Поддержать загрузку свежего снимка и запись. Проверить
   конфликт типов, неизвестную ссылку, дробные значения и пустой набор.
3. Реализовать набор/фильтр по типизированному регистратору, замещение только
   его движений, очистку пустым набором, повторную запись и изоляцию документов.
   Начальные остатки создаёт доверенная fixture-инфраструктура:
   у `ПоступлениеТоваров` нет `ПослеЗаписи`, не создавать его.
4. Поддержать ровно используемый литерал XBQL `ПередЗаписью` или явно ограниченную
   трансляцию этого запроса к SQL. Отличать исходный XBQL платформы от адаптера
   подмножества. Остальные формы — UNSUPPORTED. Проверить пустой список,
   отсутствие товара, несколько складов/движений, равенство и недостаток.
   Оригинальный запрос не фильтрует склад — бизнес-логику не исправлять ради теста.
5. Выполнять студенческие методы только в Docker. Разделить admin-секрет и
   пароль ограниченной роли; не передавать студенту admin, bootstrap, Docker
   socket, хостовые данные или внешнюю сеть. Сохранить mocks-режим.
   Обеспечить атомарность записи документа/движений с обработчиками и описать
   отличия от платформенных транзакций.
6. Создать opt-in задание: успешная отгрузка, отказ, пустая ТЧ, дроби,
   повторная запись, пустое замещение, изоляция и очистка после сбоя.
   Неверные ожидания — FAIL в SBSL; ERROR/UNSUPPORTED не останавливают следующие проверки.
7. Запустить всю текущую регрессию с Docker/интеграцией; сохранить JSON/HTML
   и журнал в `result/poc-shipment-storage`. Обновить README/roadmap и следующее
   задание по фактам. Архив и бизнес-логика остаются неизменными.

## Критерии готовности

- Оригинальные обработчики исполняются с подтверждённым контрактом хранения;
  результатов подставного запроса в интеграционном режиме нет.
- Запись, замещение и остатки проверяются БД; граница SQL/XBQL документирована.
- Повторная запись не удваивает движения; отказ не оставляет частичных данных.
- Студенческий код изолирован, admin недоступен, секретов в отчётах нет.
- Баллы определяет SBSL; все существующие проверки проходят.

Полный XBQL, произвольные виртуальные таблицы, общий объектный API, workers,
кэш, LMS и расширение лексического анализа остаются за границами итерации.


## Итог итерации

Выполнен ограниченный SQL-адаптер: исходные обработчики отгрузки, хранение
документов/строк/движений, свежие снимки, типизированное замещение, откат и
независимый аудит БД. Контракт и воспроизведение —
[shipment-storage.md](../shipment-storage.md).

По прямому уточнению пользователя доступ к приложениям Элемента не будет
предоставляться. Пункт о платформенном эталоне заменён проверкой ограниченного
адаптера по исходникам и документированному API; соответствие полной платформе
не заявляется. Проекция одного товара с нескольких складов явно UNSUPPORTED.
Общий API записи загруженных объектов, произвольный XBQL, параллельные транзакции
и ограничения метаданных не реализованы; границы перечислены в документе.
