# Задание №43: Виртуальные таблицы и прочие источники

Статус: **executor расширен; полная приёмка не завершена**, обновлено 5 октября 2026 года.
44 целевых теста успешны. Локальные ограничения и платформенный остаток
перечислены отдельно; пользователь подтвердил отсутствие тестовых приложений Элемента.
Основание: [каталог](../query-contract-catalog.md) и
[общий план](../corpus-verification-plan.md). Выбор записей: nextStage
`043-virtual-tables`, операции slice-first, balance, turnover, source; связанные сочетания включаются явно.

## Контракт

СрезПервых/другие периодичности, остатки/обороты/остатки-и-обороты/изменения, табличные части и реквизиты-коллекции, контракты сущностей и системные таблицы. Полный состав полей/параметров/прав берётся из версионированных источников.

Перед реализацией сохранить список contractId/исходных диапазонов и независимые
baseline причин. По уточнению пользователя использовать справку Элемента 9.3
и актуальный установленный Script; сохранять версии исходников и явно
разделять режим executor и native/platform основания новых операций.
Review templates из tests/corpus/storage-query-fill/documented-forms требуют
исполнимых переносимых проектов и авторских expected до запуска источников.

## Приёмка

- Прямые реальные корни и переносимые проекты; независимые данные/ответы,
  корректная альтернативная реализация и исполнимые бизнес-мутации с SBSL FAIL.
- Общий AST/типы/renderer без ветвей по названию проекта и без готовых query rows.
- Memory/PostgreSQL там, где задействовано хранение: независимый SQL-аудит,
  повторные снимки, rollback, cleanup; не дублировать в SQL все чистые случаи.
- Публичные test/run, два изолированных batch, схемы/баллы/unavailablePoints,
  FAIL → UNSUPPORTED → PASS и восстановление после инфраструктурного отказа.
- Каталог получает свежую привязку только к exact sourceHash/range/критерию;
  discovery/parsed/trace не заменяют independentlyAssessed.

Локально запускать только новые и реально затронутые прежние тесты.
Полный discovery, 303 формы, 44 прежних корня и четыре validate оставлять nightly.
Архивы, прежние expected, лимиты и расписание CI не менять ради успешной приёмки.
Сохранить первичные сбои, отдельные повторы и SHA-256 архивов.

## Текущий результат

Добавлены фильтры измерений внутри источников (включая captured scalar/array,
IN и LIKE), десять календарных периодичностей итогов и Авто, способы
дополнения периодов, поля СледующийПериод и история Момент. Параметризованные
сохранённые источники используют объявления YAML, positional bindings и
сохраняют отличие SQL NULL от Неопределено, в том числе в JOIN.

Три точных внешних `.xbql` из неизменённых архивов независимо исполнены через
Query API: продажи Demo-SRM, продажи по организациям и остатки по складам.
Исходный текст, hash и range сохранены; hash добавленной обвязки записан отдельно.
Это приёмка запроса; native lifecycle отчёта не проверен. В исходном scope из
27 записей каталог теперь содержит **8/8/8/8**
parsed/planned/executed/independentlyAssessed; 19 записей сохраняют причины недоступности.

Свежая проверка: **44** различных теста (15 новых, 29 затронутых прежних),
две новые бизнес-мутации SBSL FAIL и корректная альтернатива PASS, три новых
PostgreSQL-сценария с независимым аудитом и cleanup. Public test/run — **3/3**,
два новых изолированных batch — **3/2/3**, два прежних — **3/0/3**, cacheHit=false.
Контроль доступности и **91** артефакт по JSON Schema успешны. Первичные сбои
тестовых обвязок и отдельные успешные повторы сохранены.

ОстаткиИОбороты с периодичностью Регистратор/Запись и nullable граничными
строками, периодические константы, структуры ключей регистров, коллекции
Соответствие/Множество, локали пользователей, вычисляемая периодичность,
defaults сохранённых запросов и коррелированные фильтры пока не реализованы.
Обмены, настройки, НеудаленныеОбъекты и реальные права требуют приложения
Элемента. Таблицы контрактов сущностей исключены по версии 9.3.
