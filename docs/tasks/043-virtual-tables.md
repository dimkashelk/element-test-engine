# Задание №43: Виртуальные таблицы и прочие источники

Статус: **реализовано в границах standalone executor**, обновлено 5 октября 2026 года.
39 целевых тестов успешны; платформенный остаток сохранён явно.
Основание: [каталог](../query-contract-catalog.md) и
[общий план](../corpus-verification-plan.md). Выбор записей: nextStage
`043-virtual-tables`, операции slice-first, balance, turnover, source; связанные сочетания включаются явно.

## Контракт

СрезПервых/другие периодичности, остатки/обороты/остатки-и-обороты/изменения, табличные части и реквизиты-коллекции, контракты сущностей и системные таблицы. Полный состав полей/параметров/прав берётся из версионированных источников.

Перед реализацией сохранить список contractId/исходных диапазонов и независимые
baseline причин. По уточнению пользователя использовать справку Элемента 9.3
и актуальный установленный Script; сохранять версии исходников и явно
разделять режим executor и native/platform основания новых операций.
Review templates из tests/corpus/storage-query-fill/documented-forms требуют
исполнимых переносимых проектов и авторских expected до запуска источников.

## Приёмка

- Прямые реальные корни и переносимые проекты; независимые данные/ответы,
  корректная альтернативная реализация и исполнимые бизнес-мутации с SBSL FAIL.
- Общий AST/типы/renderer без ветвей по названию проекта и без готовых query rows.
- Memory/PostgreSQL там, где задействовано хранение: независимый SQL-аудит,
  повторные снимки, rollback, cleanup; не дублировать в SQL все чистые случаи.
- Публичные test/run, два изолированных batch, схемы/баллы/unavailablePoints,
  FAIL → UNSUPPORTED → PASS и восстановление после инфраструктурного отказа.
- Каталог получает свежую привязку только к exact sourceHash/range/критерию;
  discovery/parsed/trace не заменяют independentlyAssessed.

Локально запускать только новые и реально затронутые прежние тесты.
Полный discovery, 303 формы, 44 прежних корня и четыре validate оставлять nightly.
Архивы, прежние expected, лимиты и расписание CI не менять ради успешной приёмки.
Сохранить первичные сбои, отдельные повторы и SHA-256 архивов.

## Результат

Реализованы первые/последние срезы День/Секунда, исходные регистры,
остатки/обороты/остатки-и-обороты, табличные части/массивы,
непериодические константы, явный профиль пользователей и сохранённые
источники без параметров. Прямой корень Dvizhok и четыре точных шаблона
независимо оценены. Каталог обновлён только по 27 baseline-записям:
5 parsed/planned/executed/independentlyAssessed.

39 тестов (14 новых, 25 затронутых прежних), шесть SBSL FAIL мутаций,
девять SQL-сценариев. Public test/run по 2/2; контроль FAIL → UNSUPPORTED → PASS;
два изолированных batch 3/0/3 без cacheHit; 46 schema validations.
Изменения обмена, права/настройки/cleanup платформы, расширенные параметры
итогов и внешние `&`-bindings сохраняют UNSUPPORTED с причиной.
Таблицы контрактов сущностей исключены по версии 9.3.
