# Типы промежуточных получателей вызовов

Для цепочек вызовов индексатор теперь сохраняет полный диапазон вычисляемого
получателя и выводит его тип из типизированных параметров, локальных объявлений,
конструкторов, явных приведений, свойств YAML, индексации коллекций и сигнатур
проектных методов. Для ссылки `T.Ссылка` результат `ЗагрузитьОбъект()` имеет тип
`T.Объект`. Доступ к методам объектного модуля проверяется по этому типу,
пространству имён и видимости. Вызовы на типизированных коллекциях и
платформенных объектах не превращаются в одноимённые вызовы проектных модулей.

Проверено на `autocheck-2026-09-24-16-14.xdump`: после анализа обоих проектов
диагностик `dynamic_call` нет; среди построенных рёбер —
`ЛогическаяГруппа.Объект.СоздатьКопию`,
`ЛогическаяГруппа.Объект.ПроверитьГруппу`,
`ДанныеПроверок.Объект.ПолучитьСписокПеременных` и метод формы после
приведения. Если объектный метод достигается через вычисляемый получатель,
подготовка Script executor по-прежнему требует объектный контекст и сообщает
об этом явно. Исходный архив читался во временный каталог и не изменялся.

Это вывод типов для поддержанных форм получателя, **не полный AST всех
выражений XBSL**. При неизвестном или конфликтующем типе граф не создаёт
ребро по совпадению имени; остаётся `dynamic_call` и `UNSUPPORTED` при
подготовке исполнения. Для полного закрытия пункта 2 нужен разбор операторов,
присваиваний, лямбда-тел и остальных выражений в едином дереве.
