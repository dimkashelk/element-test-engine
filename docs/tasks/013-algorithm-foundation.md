# Задание №13, этапы 1–3

## Корпус

Постоянные проекты и задание находятся в [`tests/corpus`](../../tests/corpus/README.md).
Статусы `PASS`/`FAIL` для структурных и runtime-сравнений подтверждает
SBSL-движок. Значение runtime `5` отдельно получено локальным Script executor
на доверенной фикстуре. Статусы `ERROR` и `UNSUPPORTED` подаются в SBSL как
контрактные факты окружения; их причины не приписываются студенту. Корпус
проверяет отрицательные ожидания, ложное имя метода в строке/комментарии,
интерполяцию, перегрузку, незакрытый блок, одинаковые короткие имена и импорт.
Тест сравнивает хеши файлов до и после проверки.

## Синтаксическое подмножество

`indexer.py` сначала маскирует комментарии и строковые литералы с сохранением
позиций, затем строит токены и дерево методов и вложенных блоков `если`,
`пока`, `для`, `выбор`, `попытка`. Закрывающий `;` связывается с вершиной стека.
Сигнатуры, параметры, возвращаемый тип и аннотации извлекаются из тех же
токенов. Вызовы в `${...}` видны отдельному проходу лексера. Runtime копирует
точный исходный срез метода; тело бизнес-логики не нормализуется. Незакрытый
метод или некорректная сигнатура дают `indexComplete: false` и диагностику
`invalid_xbsl`; runtime не исполняет такой срез. Перегрузка целевого метода
считается неоднозначной.

Поддержаны блочные операторы, начинающиеся с отдельной строки, и закрывающий
`;` в начале строки. Неизвестные формы XBSL не объявляются успешно
разобранными только по текстовому совпадению имени. Это не компилятор всей
платформы.

## Имена и граф вызовов

Порядок поиска: локальное пространство имён, явный импорт модуля или
пространства имён, затем доступные проектные символы. Квалифицированное имя
(включая префикс поставщика и проекта) ищется точно. Алиас `импорт ... как ...`
работает для модулей и типов. `ВПодсистеме` закрывает внешний доступ;
`@Локально` закрывает внешний вызов метода. Если краткое имя даёт нескольких
кандидатов, runtime не выбирает одного случайно. Для генерируемых SBSL-типов
сохраняется точный владелец и обнаруживается конфликт кратких имён.

`analyze()` публикует `callGraph` со связями `fromModule`/`fromMethod` →
`toModule`/`toMethod`. Runtime обходит только достижимые методы, включая
импортированные, и генерирует отдельный модуль SBSL для внешнего метода.
Прямой импорт, алиас и импорт пространства имён проверены Script executor.
Внешние объектные методы без собственного `context` и квалифицированный вызов
вида `Namespace::Module.Method()` остаются недоступными для runtime и дают
`UNSUPPORTED`; индекс при этом сохраняет исходный код и найденную связь.

CLI `test`/`run`/`batch`, JSON-схемы результата и начисление баллов в SBSL
сохранены. LMS, HTTP и формат архива не затрагивались.
