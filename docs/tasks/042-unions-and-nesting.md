# Задание №42: Объединения, вложения и временные таблицы

Статус: **доработано и проверено в executor-контракте объединений и временных таблиц**, 5 октября 2026 года.
[Семантика и остаток](../unions-and-nesting.md),

`042-unions-and-nesting`, операции union, nested, compound, temporary, index; связанные сочетания включаются явно.

## Контракт

UNION/ALL, вложенные выборки, несколько операторов, создание/индексирование/помещение/удаление временной таблицы. Подтвердить область жизни состояния и порядок captured параметров.

Перед реализацией сохранить список contractId/исходных диапазонов и независимые
baseline причин. По уточнению пользователя использовать справку Элемента 9.3
и актуальный установленный Script; сохранять версии исходников и явно
разделять режим executor и native/platform основания новых операций.
Review templates из tests/corpus/storage-query-fill/documented-forms требуют
исполнимых переносимых проектов и авторских expected до запуска источников.

## Приёмка

- Прямые реальные корни и переносимые проекты; независимые данные/ответы,
  корректная альтернативная реализация и исполнимые бизнес-мутации с SBSL FAIL.
- Общий AST/типы/renderer без ветвей по названию проекта и без готовых query rows.
- Memory/PostgreSQL там, где задействовано хранение: независимый SQL-аудит,
  повторные снимки, rollback, cleanup; не дублировать в SQL все чистые случаи.
- Публичные test/run, два изолированных batch, схемы/баллы/unavailablePoints,
  FAIL → UNSUPPORTED → PASS и восстановление после инфраструктурного отказа.
- Каталог получает свежую привязку только к exact sourceHash/range/критерию;
  discovery/parsed/trace не заменяют independentlyAssessed.

Локально запускать только новые и реально затронутые прежние тесты.
Полный discovery, 303 формы, 44 прежних корня и четыре validate оставлять nightly.
Архивы, прежние expected, лимиты и расписание CI не менять ради успешной приёмки.
Сохранить первичные сбои, отдельные повторы и SHA-256 архивов.

## Результат

UNION/ALL, вложенные источники, некоррелированный IN/NOT IN, последовательные
операторы и локальные временные таблицы работают через общий AST/renderer.
Индексы проверяются как логические подсказки; physical/native подтверждение
остаётся отдельным контрактом. Baseline содержит 46 записей, свежую независимую
оценку получили один точный реальный литерал и пять точных review templates.
Реальный ТекущееПодразделение проверен пятью критериями без изменения архива.

49 различных тестов успешны: 16 новых и 33 прежних; семь SBSL FAIL мутаций,
восемь SQL-сценариев, test/run по 5/5, два batch 3/0/3, 46 schema-артефактов.
Первичные отказы и отдельные повторы сохранены. При выборе класса FillPlanTest
по ошибке выполнен один полный read-only проход инвентаризации; это отклонение
явно записано в измерениях. Остальные полные отложенные проверки не запускались.
Четыре архива, прежние expected, лимиты и CI-расписание сохранены.
Следующее — [№43](043-virtual-tables.md).
