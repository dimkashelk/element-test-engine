# Задание №13, пункт 7: параметры запросов

Проверен доступный исходный архив `Dvizhok.xdump`: в нём один литерал
`Запрос{...}` с одним выражением `%{...}`. Действующий `parameterType` и имя
события `Параметр` сохранены. Других архивов работ для измерения числа
`UNSUPPORTED` сейчас нет.
Все 25 существующих чистых runtime-проверок из шести заданий после изменения
успешно подготовили скрипты; интеграционные проверки в этот подсчёт не входят.

Добавлен явный контракт `parameterTypes`: непустой список типов в порядке
выражений `%{...}`. Число типов должно совпадать с числом выражений. Фабрика
вычисляет каждое исходное выражение в Script executor и записывает аргументы
`Параметр1`, `Параметр2`, ... . Строковые литералы и комментарии запроса не
создают ложных параметров. Вложенные фигурные скобки пока дают
`UNSUPPORTED/unsupported_syntax`; некорректная форма контракта даёт
`UNSUPPORTED/invalid_test`. Подставные строки результата остаются явным
контрактом преподавателя: XBQL не исполняется.

Доверенная фикстура с двумя параметрами скомпилирована и выполнена локальным
Script executor. SBSL оценил два правильных сценария как `PASS`, неверное
ожидание второго параметра как `FAIL`. Разные аргументы и строки результата
проверены в отдельных запусках, исходный XBSL остался неизменным. Отдельно
проверены неправильное число типов, одновременное указание старого и нового
формата, вложенные скобки и прежняя сигнатура фабрики для реального задания.
Локальная регрессия: 95 тестов, из них 11 штатно пропущены без opt-in Docker.
Доступ к Docker API в текущем окружении запрещён (`permission denied`), поэтому
Docker-регрессия не подтверждена.

Другие кандидаты пункта 7 — семантика параметров записи, сохраняемое состояние
fake-ссылок, хранение движений и остатков в одной проверке — требуют отдельных
контрактов и остаются открытыми. Перед их реализацией нужны задания, которые
действительно используют эти операции, чтобы не приписать мокам семантику
платформы без проверяемого основания.
