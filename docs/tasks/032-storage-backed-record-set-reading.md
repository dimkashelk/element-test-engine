# Задание №32: чтение наборов регистров по фактическому состоянию хранения

Статус: **выполнено**, 2 октября 2026 года.
Основание: [результат №31](031-storage-backed-queries.md#отчёт-о-реализации),
[универсальный runtime](../universal-runtime.md) и
[контракт транзакций](../transactions-and-business-exceptions.md).
Задание №31 зафиксировано коммитом `838aa5e`: полная Docker/SQL-регрессия
192/192 без пропусков, четыре validate успешны, архивы не изменены.

## Цель и приоритет

Замкнуть общий цикл «записать набор → прочитать → изменить строки → записать
в другой фильтр → проверить сохранённое состояние». Добавить исходный API
`НаборЗаписей.Прочитать()` в существующий pipeline planner → renderer →
executor/backend → наблюдения → SBSL. Результат чтения должен происходить
из текущего состояния той же сессии, включая собственные изменения транзакции.

№29–30 уже сохраняют реальные строки наборов регистров под идентичностью
регистра и ключом фильтра, поддерживают замещение/добавление и rollback.
№31 читает сохранённые Справочники/Документы через ограниченный query AST.
Чтение набора регистра и его обход пока не обеспечены общим storage-контрактом.
Новый этап использует существующие механизмы хранения и разрешения типов.

Python связывает API, метаданные и исходные диапазоны, готовит типы и
инфраструктуру. Загрузка набора, копирование строк, обход, изменение полей,
формулы и исходные зависимости исполняются в Script executor. Ожидания,
сравнение и баллы остаются в SBSL. Имена валют, регистра или метода,
teacher expected и заранее подготовленные ответы не выбирают реализацию.

## Реальный пример приёмки

В неизменённом `Prakticheskie-primery-2026-09-30-15-20.xdump` исходный метод
`ПараметрыЗаписи::КурсыВалют.Пересчитать(Валюта: Валюты.Ссылка)`:

1. Запросом №31 получает ОсновнаяВалюта и Наценка из справочника Валюты;
   при отсутствии объекта возвращается без записи.
2. Создаёт `новый КурсыВалют.НаборЗаписей()`, устанавливает фильтр по
   ОсновнаяВалюта и вызывает `НаборЗаписей.Прочитать()`.
3. Обходит сам набор, меняет Валюта и умножает Курс на Наценка.
4. Устанавливает фильтр на входную Валюта и вызывает `Записать()`.

Схема регистра: РегистрСведений, Периодичность День, измерение
`Валюта: Валюты.Ссылка?`, ресурсы `Курс: Число`, `Кратность: Число`.
Метод не принимает ПараметрыЗаписи: название подсистемы не требует добавлять
непустые параметры записи в охват. Исходный метод, схема и архив сохраняются.

Пример должен выполняться в Docker без mocks; сравниваются действительно
сохранённые строки, включая валюту, период, курс и кратность. Начальные
данные и независимые ожидания задаёт преподаватель. Обязательны две даты,
несколько курсов, чужая валюта и прежние строки целевой валюты: сохранение
базовых/чужих данных и замещение целевого набора проверяются отдельно.
Пустой исходный набор и отсутствие объекта справочника имеют отдельные
ожидания по подтверждённому контракту.

## Обязательный результат

### 1. Подтверждённая семантика

До реализации проверить официальные сигнатуры платформы для выбранного
режима совместимости и отдельные доверенные native-пробы Script `-c 9.0`.
Различать платформенное API, возможности executor и контракт адаптера.
Отсутствующий native API оформляется явным общим адаптером. Приложения
студентов, деплой и платформенный эталон для этого этапа не требуются.

Установить и документировать:

- Сигнатуру Прочитать, заполняемую коллекцию и тип её строк; обход самого
  набора, изменение строки в цикле и сохранение изменений последующим Записать.
- Поведение повторного чтения непустого набора: обновление, замещение либо
  добавление допускаются только по подтверждённому контракту.
- Время применения фильтра; смена фильтра между чтением и записью;
  отсутствие строк, отсутствие фильтра и неподдержанный частичный фильтр.
- Независимость загруженных строк от storage и другого набора; повторное
  чтение после записи и после rollback.
- Период периодического регистра: тип, точность, нормализация и связь с
  идентичностью записи. Не сводить строки разных дат к одному измерению.
- Фильтр регистра накопления по регистратору; сохранение типа регистратора,
  периода, измерений, ресурсов и вида движения без вычисления остатков.
- Замещать = Истина/Ложь, пустую запись, соответствие строк фильтру и
  взаимодействие с действующими транзакциями/обработчиками №29–30.

Обязательный охват — полные фильтры существующего storage-контракта:
измерения регистра сведений и регистратор регистра накопления. Более широкое
чтение, произвольный/частичный фильтр и иной API допускаются только после
отдельного подтверждения; иначе дают обоснованный UNSUPPORTED.
Не воспроизводимую платформенную семантику нельзя молча заменять удобной.

### 2. Общая привязка API и типов в плане

Расширить существующие AST, ProjectTypes и capability bindings. Разрешать
НаборЗаписей, ФильтрНабора и Запись через metadata owner, namespace/import/alias.
Прочитать связывается с реальным типом получателя, в том числе локальной
переменной, параметром и результатом исходной зависимости. Одноимённый
проектный метод/тип или локальное затенение не выбирает адаптер.

В ExecutionPlan сохранить идентичность исходного символа, диапазоны вызова
и обхода, владельца/схему регистра, тип строки/фильтра, backend, контракт
и ограничения. Не добавлять expected, начальные ответы либо ветки по
КурсыВалют/Пересчитать. Если обход требует понижения в native коллекцию,
преобразование допустимо только для доказанного типа набора, по AST и
проверенным диапазонам. Переменные, порядок операций и тела зависимостей
сохраняются; замена метода готовым алгоритмом пересчёта недопустима.

### 3. Чтение и запись в одной сессии

Прочитать загружает реальные строки из актуального staging по полному
разрешённому владельцу и типизированному фильтру. Ключи должны отделять
namespace и типы ссылок с одинаковыми UUID; порядок именованных аргументов
не должен создавать разные логические фильтры. Nullable-измерение из
реальной схемы обрабатывается по отдельно описанному контракту фильтра;
это не расширяет nullable-предикаты XBQL из №31.

Загруженные значения создаются заново. Изменение поля, вложенной ссылки,
очистка набора либо смена фильтра не меняет сохранённые данные до Записать.
Повторное чтение видит актуальные данные; ранее выданные независимые
снимки не меняются вслед за storage. Не обещать порядок строк без основания:
teacher-проверки должны сравнивать множество по устойчивым ключам или
использовать сортировку в исходном коде.

Memory и PostgreSQL используют один алгоритм чтения/обхода. Прочитать
не вызывает commit или SQL-публикацию. Запись из зависимости и обработчика
видна до commit; rollback отменяет связанные изменения объектов и регистров,
сохраняя ранее завершённые операции. Для SQL независимо проверить
опубликованные строки в действующей схеме аудита, а не только возврат метода
или повторное чтение тем же адаптером.

Добавить воспроизводимое задание начального состояния регистров: общий
формат teacher fixture либо явная подготовительная sequence исходных записей.
Схема выбирается по метаданным, данные проходят общую проверку и сохраняются
до тестируемого вызова. Подготовку различать с исполнением работы в трассах.
Fixtures не задают ответы Прочитать. Проверить несовпадение типа поля,
неоднозначный owner, неизвестное измерение и некорректный период; ошибки
teacher-входа не превращаются в FAIL студента.

### 4. Переносимость, ошибки и совместимость

Включить минимум два самостоятельных проекта с иными namespace, именами,
import aliases и схемами: периодический РегистрСведений с несколькими
измерениями/ресурсами и РегистрНакопления с типизированным регистратором.
Реальный Пересчитать служит третьим примером, а не единственным контрактом.

Для каждого нового общего контракта получить независимый PASS,
контролируемый FAIL через SBSL и объяснимый UNSUPPORTED. Валидные мутации
исходного кода должны обнаруживать пропуск чтения, ошибочный фильтр/поле,
неверную формулу, потерю периода/кратности, изменение базового набора,
запись в чужой фильтр, неправильное замещение и устаревшее чтение.
Ожидания не выводятся из тестируемой реализации.

Инфраструктурный файловый/SQL-отказ сохраняет ERROR даже после общего catch
в исходном коде или rollback; timeout остаётся TIMEOUT. Эти статусы дают
unavailablePoints. После отказа следующий критерий и отдельный запуск
выполняются успешно. Две работы batch с одинаковыми UUID не делят наборы.
Контейнеры/сети/credentials очищаются, публичные планы и отчёты не раскрывают
секреты или исходные выражения в обход действующего контракта.

Сохранить прежние mocks.registers, legacy отгрузку/остатки, записи наборов,
обработчики, транзакции и запросы №31; test/run/batch используют один путь.
Основные задания и максимумы баллов не менять ради нового контракта.
Если новая поддержка устраняет прежнюю fixture недоступности, заменить её
другой реальной границей и объяснить миграцию.

отдельный доверенный код. Архивы открываются на чтение. Платформенный API,
поведение адаптера и независимый аудит различаются в документации.

Корпус и teacher assignments включить в Git. В

CLI-сопоставление и очистку. После целевых тестов выполнить полную
Docker/SQL-регрессию с opt-in и временным паролем окружения, четыре validate,
контроль SHA-256 архивов и проверку публичных пакетов по JSON Schema.

## Границы этапа

СрезПоследних/СрезПервых, остатки/обороты, агрегаты, JOIN и другие расширения
query AST остаются отдельными задачами. Общие удаление/менеджер записи,
произвольные фильтры, непустые ПараметрыЗаписи, именованные/вложенные ресурсы,
конкурентный доступ, LMS, HTTP, UI и деплой в №32 не входят. Поддержка
чтения набора не означает поддержку всех платформенных операций регистра.

## Отчёт о реализации

Выполнено 2 октября 2026 года. Реализован общий контракт
`storage-record-set-v1`; спецификация выше сохраняет исходный объём задания.

### Изменения

- `element_test/record_sets.py` связывает metadata-owner, типы набора/строки/
  фильтра и AST-диапазоны. ExecutionPlan содержит `recordSets`, backend,
  контракт и ограничения; teacher expected не входит в план. Обход
  доказанного набора понижается в native-массив без замены исходного метода.
- Script читает актуальный staging той же сессии и создаёт новую коллекцию
  свежих строк и вложенных ссылок. Повторное чтение заменяет коллекцию;
  изменение загруженного набора не меняет storage до Записать. Поддержаны
  полные фильтры измерений и регистратора, период День, замещение, добавление
  и пустая запись. Полный owner и тип union-регистратора разделяют одинаковые
  UUID. Проектные типы в операторе `это` проходят общую замену namespace.
- Запись проверяет соответствие строк фильтру и уникальность ключей
  сведений с периодом. Ошибка уникальности делает активную транзакцию
  непригодной до rollback. Существующая инфраструктурная отметка отказа
  сохраняется после catch/rollback. Memory и PostgreSQL используют один
  алгоритм; чтение не публикует SQL, отдельный SELECT проверяет публикацию.
- `storage.initialRegisters` задаёт типизированное teacher-состояние через
  тот же API записи и отдельные события `teacher:register-setup`. Ошибки
  схемы/owner/периода/значений дают invalid_test, а не FAIL студента.
- SBSL выполняет сравнение `record-sets-unordered` как мультимножество
  полных строк, с учётом повторов. Обычное сравнение и максимумы прежних
  заданий сохранены. Замыкание обработчиков записи теперь выбирается по
  достижимой записи объекта: чтение регистра не подтягивает посторонние
  обработчики с непустыми параметрами записи.
