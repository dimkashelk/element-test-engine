# Runtime-контракты запросов по исходному ДемоСРМ

## Основание и границы

В `Demo-SRM-dev-2026-09-28-21-38.xdump` методы
`Пресейл/СтадииСделок.xbsl:ПолучитьНачальнуюСтадию` и
`ПолучитьВидСтадии` используют две формы `Запрос{...}`: без параметров и с
`%Стадия`. Исходные методы исполняются в Script executor без изменения их тел.
Подставные строки `mocks.queries.rows` задаёт преподаватель; XBQL, сортировка
и выбор `ПЕРВЫЕ 1` платформой здесь не исполняются. Задание
[`demo-srm-stages`](../../assignments/demo-srm-stages/assignment.yaml) проверяет
результат методов и события создания/выполнения запроса. Исходный проект принят
как эталон поведения; отдельного учебного требования нет.

## Контракт

- Для запроса без параметров требуется `parameterTypes: []`. Фабрика
  `СоздатьЗапросN()` фиксирует событие `Создать` с `args: {}`.
- `%Имя` передаёт значение исходной переменной в Script executor. Для
  `parameterTypes` аргументы события именуются `Параметр1`, `Параметр2`, ...
  в порядке появления, как у ранее поддержанного `%{...}`.
- Число типов должно совпадать с числом параметров. Некорректный контракт
  получает `UNSUPPORTED/invalid_test`; неизвестная форма `%` получает
  `UNSUPPORTED/unsupported_syntax`. Строки и комментарии запроса не создают
  параметров.
- Ранее поддержанный `parameterType` с именем `Параметр` и `%{...}` сохранён.
  Каждый критерий создаёт собственный набор строк и не делит его с другими.

## Проверка

Оригинальный `ДемоСРМ` через публичный CLI и Docker: четыре `PASS`, 8/8,
`unavailablePoints = 0`; отчёт — `result/demo-srm-stages`. Пустой результат
возвращает `null`; непустой — ссылку на первую стадию. Два вызова `%Стадия`
передали разные ID и вернули соответствующие значения перечисления.

Контрольный пакет в `result/demo-srm-stages-negative`: `FAIL`, `PASS`,
`UNSUPPORTED/invalid_test`, `PASS`; 4/6 доступных баллов и 2 недоступных.
Неверное ожидание оценено SBSL, а ошибка контракта не стала ошибкой студента.
Тест оригинальных методов в локальном Script executor также подтвердил эту
последовательность оценивания и побайтную неизменность XBSL.

Существующее задание `poc-platform` с `%{...}` повторно прошло публичный CLI
в Docker: 5/5, отчёт `result/poc-platform-regression`. Полная локальная
регрессия: 110 тестов, 12 штатных opt-in пропусков.

Параметры записи в доступных исходниках не читаются обработчиками и по
уточнению пользователя пока не нужны. Хранение движений и состояние ссылок в
одной интеграционной проверке дополнительно подтверждены
[сценарием отгрузки](021-shipment-sequence.md).
