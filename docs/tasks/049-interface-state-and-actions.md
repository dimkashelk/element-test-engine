# Задание №49: состояние и действия интерфейса без браузера

Статус: **реализовано в ограниченном контракте**, 11 октября 2026 года. P1.
Основание: [план разработки типов](../test-type-development-plan.md).

`runtime.interface` объединяет декларативный вход, типизированные контексты
пяти базовых видов UI, ввод/пересчёт привязок, вызов выбранного исходного
обработчика, текущие/отмеченные строки и четыре команды таблицы.
Надпись создаётся исходным Script-кодом и вставляется в живое содержимое группы.
Таймеры №48 работают на том же экземпляре; запись/открытие переиспользуют
storage/formEffects. Для констант добавлена отдельная сессионная фиксация.
Структура, привязки, состояние и сохранённые эффекты наблюдаются раздельно.

[Исполняемый контракт и точный остаток](../interface-actions.md),
[измерения](../test-type-stage-049-measurements.json).
Все 19 UI-деклараций финальной выгрузки проходят план/генерацию без
искусственного исходного метода. Их бизнес-исполнение не проводилось.
Историческая карта №46 сохранена; текущий реестр указывает scoped поддержку.

Приёмка механизма: **14 различных успешных проверок**, включая Script и SQL.
Приёмка включает типы/ошибки контракта, semantic selectors и переименование
обработчика, отсутствие expected в IR, исходные позиции, запреты доступа,
живые колонки, отдельную строку и массив отмеченных, повторы строк,
динамическое дерево, callback/привязки, изоляцию и сохранение констант.
Исходный query-обработчик читает контролируемое storage.
Публичные test/run/batch проверяют независимые PASS/FAIL/UNSUPPORTED и
мутацию обработчика; веса недоступных проверок остаются в unavailablePoints.
Memory и одноразовый PostgreSQL проверяются независимым чтением сохранения.

Архивы, assignments/expected дампа, CI и исторические свидетельства не менялись.
Полная регрессия остаётся nightly. Следующий этап — P1 №50: ограничения
метаданных, lifecycle записи и сохранённые эффекты.
