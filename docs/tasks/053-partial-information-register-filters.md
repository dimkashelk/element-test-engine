# Задание №53: частичные фильтры регистров сведений

Статус: **реализовано в описанном контракте**. P0. Зависимость: №50.
Основание: [очередь](../dvizhok-final-verification-plan.md), `source-preflight.json` текущего аудита.

## Проблема и требуемый результат

`ПоступлениеТоваров.Объект.ПослеЗаписи` устанавливает фильтр регистра поставщиков
только по Номенклатуре, хотя измерения регистра — Номенклатура и Поставщик.
`bind_record_sets` отклоняет исходник: «Поддержан только полный фильтр набора».
Нужен общий контракт частичного фильтра РС с реальными чтением, замещением и добавлением
строк, сохраняющий атомарность объектной записи. Исходник приложения не исправлять ради адаптера.

## Работа

1. Зафиксировать семантику фильтра для профиля исходников 9.0: полное и частичное
   ограничение, явное nullable-значение, отсутствие ограничения, повторная установка,
   `Прочитать`, `Записать()` и `Записать(Ложь)`. Указать источник семантики и расхождения
   выбранной модели с доступной официальной справкой. Совместимость 9.3/current фиксировать отдельно.
2. Поддержать именованный непустой поднабор измерений РС. Неуказанное измерение означает
   отсутствие ограничения, явно заданный NULL — ограничение на NULL. Не смешивать эти состояния.
   Полный фильтр и прежний фильтр регистратора РН сохраняют свой контракт.
3. Разделить предикат отбора и идентичность хранимой строки. Канонический ключ строки
   включает полный owner, все измерения и период, когда он входит в ключ. Частичный
   фильтр не должен создавать отдельную копию тех же данных в другом «наборе».
4. `Прочитать` выбирает все строки, удовлетворяющие предикату. Замещение удаляет только
   выбранные прежние строки и сохраняет новые; пустой набор очищает только выбранную область.
   Добавление сохраняет прежнюю историю. Вставляемая строка обязана соответствовать фильтру;
   коллизии полных ключей обрабатываются явно, без тихой потери строки.
5. Обеспечить одинаковую модель memory/PostgreSQL, свежие чтения запросов и срезов,
   отсутствие алиасинга ссылок/строк, откат объекта и всех регистров при отказе обработчика.
   SQL-аудит читает сохранённое состояние независимо от рассчитанного runtime-ответа.
6. В IR сохранить маску заданных измерений, типизированные значения, owner, sourceHash,
   позиции вызовов и поддержанные операции. Обновить документацию и схемы только при изменении
   публичного описания; обосновать необходимость нового поля вместо добавления его по умолчанию.

## Обязательные технические сценарии

| Случай | Независимое наблюдение |
|---|---|
| Два поставщика A/B товара X и отдельный товар Y | Частичный фильтр X читает обе строки X, не читает Y |
| Замещение X одной новой строкой | Прежние выбранные X удалены; Y сохранён |
| Полный фильтр X/A | X/B и Y не изменены |
| Пустое замещение X | Очищена только область X |
| Добавление новой даты/момента | История сохранена; срез возвращает ожидаемую последнюю запись |
| NULL против незаданного измерения | Разные области отбора, проверенные сохранёнными данными |
| Пересекающиеся полные/частичные фильтры | Одна общая история, без повторного хранения одной строки |
| Строка вне фильтра или конфликт полного ключа | Явный отказ и сохранность состояния |
| Отказ после первого из нескольких связанных эффектов | Полный откат с независимым SQL-аудитом |

Исполнить переносимый fixture с другими именами/namespace и минимум тремя измерениями.
Проверить свежую загрузку, повторное замещение и период Момент; не полагаться на порядок
строк без явного требования сортировки. Неизвестное имя/неверный тип фильтра — ошибка
контракта; неподдержанная форма — точная причина недоступности.

## Приёмка и артефакты

- План и генерация точного `ПоступлениеТоваров.Объект.ПослеЗаписи` больше не блокируются
  частичным фильтром. Если обнаружен следующий независимый блокер, он фиксируется отдельно.
- Все случаи таблицы проходят memory и PostgreSQL с независимыми ожиданиями; переносимость
  исполнена, а не только запланирована. Полные фильтры и прежние наблюдения не регрессируют.
- Неверный expected даёт SBSL FAIL; неверный фильтр и недоступный backend не получают PASS.
  Проверить публичные `test/run/batch`, изоляцию двух работ и `unavailablePoints`.
- Создать контракт и измерения №53, тесты механизма, свежие планы подготовки финального
  исходника и список оставшихся границ. Бизнес-приёмка поступления относится к №56.

Пустой фильтр всей таблицы, обработчики самого регистра, подчинённый РС 10.0 и native
блокировки не входят в обязательный объём: их граница должна быть явной. Нельзя автоматически
трактовать отсутствующий фильтр как разрешённую очистку всего регистра.

## Реализация 11 октября 2026 года

[Контракт и границы](../partial-information-register-filters.md),
[технические измерения](../test-type-stage-053-measurements.json).

Поддержан непустой именованный поднабор измерений с отдельной маской заданных
полей и сохранением NULL. Чтение/замещение/добавление используют общую историю
полных ключей; запись таблицы выполняется только после проверки всех строк.
Проверены memory/PostgreSQL, независимый SQL SELECT, переносимость трёх измерений
и периода Момент, свежие запросы/срезы, коллизии, снимки ссылок и откат объекта
с двумя регистрами. Полные фильтры РС и контракт регистратора РН сохраняются.

Публичные test/run/batch подтверждают независимые PASS/FAIL/UNSUPPORTED,
недоступные баллы и изоляцию двух работ. Профиль 9.3/current проверен отдельно.
План точного ПослеЗаписи финального архива проходит; генерация проходит при
`storage.lifecycle: true`. Следующий блокер старой конфигурации без lifecycle —
цикл документ↔регистр — зафиксирован отдельно в свежем source-preflight-053.json.
Бизнес-приёмка поступления остаётся в №56; исходный архив сохранён.
