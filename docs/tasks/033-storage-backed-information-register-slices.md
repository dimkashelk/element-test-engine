# Задание №33: срез последних регистра сведений по состоянию storage

Статус: **реализовано и проверено**, 2 октября 2026 года.
Основание: [результат №32](032-storage-backed-record-set-reading.md#отчёт-о-реализации),
[контракт наборов](../storage-backed-record-sets.md) и
[query AST №31](../storage-backed-queries.md).
Результат №32 зафиксирован коммитом `abf396a`: проверены 206 различных
тестов с Docker/SQL opt-in без пропусков; два нагрузочных таймаута прошли
при отдельных повторах. Четыре validate успешны, архивы не изменены.

## Цель и приоритет

Расширить общий query AST одним источником
`РегистрСведений.СрезПоследних(...)` для периодичности День. Использовать
реально сохранённые строки наборов №32 в текущей сессии: дата границы,
группировка по всем измерениям, отбор, проекция, сортировка и ПЕРВЫЕ
исполняются в Script. Сравнение и баллы остаются в SBSL.

Python разрешает метаданные, разбирает AST и диапазоны, генерирует типы
и инфраструктуру. Он не выбирает последние строки, не вычисляет исходные
параметры и не подставляет готовую цену. Имена метода, регистра, измерений
и teacher expected не выбирают реализацию. `test`, `run`, `batch`, memory
и PostgreSQL проходят один planner → renderer → executor → SBSL.

## Проверенный реальный кандидат

В неизменённом `Prakticheskie-primery-2026-09-30-15-20.xdump` метод
`РегистрСведений::ЦеныНоменклатурыПоставщиков.ПолучитьПоследнююЦенуЗакупки`
содержит следующий исходный код:

```xbsl
метод ПолучитьПоследнююЦенуЗакупки(Товар: Номенклатура.Ссылка): Число?
    знч Запрос = Запрос{
        ВЫБРАТЬ ПЕРВЫЕ 1
            ЦеныНоменклатуры.Цена КАК Цена
        ИЗ
            ЦеныНоменклатурыПоставщиков.СрезПоследних() КАК ЦеныНоменклатуры
        ГДЕ
            Номенклатура == %Товар
        УПОРЯДОЧИТЬ ПО
            Период УБЫВ
    }

    исп РезультатЗапроса = Запрос.Выполнить()

    возврат РезультатЗапроса.ЕдинственныйИлиНеопределено()?.Цена
;
```

Схема: РегистрСведений, День; измерения
`Номенклатура: Номенклатура.Ссылка?` и
`Поставщик: Контрагенты.Ссылка?`; ресурс `Цена: Число`, реквизит
`ДокументПоставки: ЗакупкаТовара.Ссылка?`. Оба измерения входят в ключ:
нельзя свести историю всех поставщиков к одной строке товара.

Это подтверждённое чтение исходника, а не подтверждение исполнения нового
API. №31 не поддерживает виртуальный источник, nullable-предикат и
сортировку Дата. Все три границы необходимы для неизменённого метода.
Начальные строки задаёт преподаватель через `storage.initialRegisters`;
ответы строятся независимо от тестируемого исходника.

Дополнительный реальный метод ДемоСРМ `Общие::КурсыВалют.ПолучитьКурсВалюты`
требует `ЗАПОЛНИТЬ КурсВалюты`; он не является обязательным положительным
примером этого этапа. JOIN и другие расширения не добавлять ради его запуска.

## Обязательный результат

### 1. Подтверждённая семантика

Перед реализацией проверить официальные сигнатуры выбранного режима
совместимости и отдельные доверенные native-пробы Script `-c 9.0`.
Различать платформенный API, native executor и объявленный адаптер.

При подготовке задания 2 октября проверена официальная
[страница Элемента 9.1 о СрезПоследних](https://1cmycloud.com/console/help/element/9.1/docs/stdlib/element/xbql/Std/InformationRegisterName/InformationRegisterName.SliceLast_ru/):
явный Период задаёт включительную верхнюю границу; для каждой комбинации
измерений выбирается максимальный подходящий период. Документация версии
9.1 сама по себе не подтверждает standalone API в режиме 9.0.

Отдельно установить и зафиксировать:

- `СрезПоследних()`, явную Дата и явное Неопределено. Формулировка документации
  для отсутствующей даты связывает актуальность с текущим моментом; нельзя
  молча заменить её максимумом всей истории. Уточнить судьбу будущих строк,
  часовой пояс и момент фиксации границы. Если используется runtime-дата,
  фиксировать независимый снимок в Docker, не брать дату машины Python.
- Полный ключ группы, состав возвращаемых измерений/ресурсов/реквизитов
  и Период. Дубликаты ключа измерения+период сохраняют контракт записи №32.
- Применение ГДЕ к результату среза: фильтр ресурса не должен позволять
  выбрать более старую строку вместо не подошедшей последней.
- Равенство nullable-измерения заполненному параметру ссылочного типа,
  с отличием SQL NULL от XBSL Неопределено. Это обязательный охват для real.
  Nullable-параметр и другие NULL-операции разрешать лишь после отдельного
  подтверждения; иначе явно UNSUPPORTED.
- Native сравнение/сортировку Дата, точность День, равные ключи сортировки
  и отсутствие гарантии порядка без полного УПОРЯДОЧИТЬ ПО.
- Параметры даты и ГДЕ фиксируются при создании запроса, в подтверждённом
  порядке; повтор Выполнить видит новое storage, сохраняя captured-значения.

Если подтверждение выявит ограничение, описать его до реализации и
подготовить воспроизводимую границу. Не выдавать предположительную
семантику за подтверждённую. Студенческие исходники исполнять только в Docker.

### 2. Общий AST, типы и исходные диапазоны

Расширить существующий query IR, не добавлять отдельный алгоритм real-метода.
Связать источник с metadata-owner через namespace/import/alias и видимость.
В плане хранить вид виртуального источника, периодичность, все измерения
группы, типы полей/параметров, диапазоны даты/ГДЕ/литерала, backend, контракт
и ограничения. Период может участвовать в сортировке, отсутствуя в проекции.

Обязательные формы: пустой аргумент либо `%Дата`/`%{выражение}` границы,
один источник, алиас, квалифицированные и краткие поля, проекции сохранённых
полей, равенство с параметром и И, сортировка нескольких поддержанных полей
(включая Дата), ПЕРВЫЕ. Существующие обычные запросы №31 сохраняются.

Неизвестный owner/поле, неоднозначность, неподдержанная периодичность,
составной источник и конфликт параметров дают обоснованный UNSUPPORTED.
Одноимённый проектный тип/метод и локальное затенение не выбирают адаптер.
Исходные зависимости и выражения параметров исполняются без подмены.
Ни expected, ни teacher-строки, ни заранее выбранный результат не входят в IR.

### 3. Исполнение по общей storage-сессии

При каждом Выполнить читать актуальное staging всех нужных наборов
разрешённого регистра; не ограничивать выборку одним bucket текущего фильтра.
В Script отобрать допустимые периоды, сгруппировать по всем типизированным
измерениям, выбрать строку, затем применить подтверждённые ГДЕ, сортировку,
лимит и проекцию. Ключи отделяют owners и типы ссылок с одинаковыми UUID;
nullable-значение группы не должно сливаться с пропуском измерения.

Результат — свежий detached-снимок по контракту №31. Старый результат
не меняется после записи, замещения или rollback. Чтение видит собственные
записи и записи достижимых обработчиков до commit; само не делает commit.
Memory и PostgreSQL используют один алгоритм, независимый SQL SELECT
проверяет опубликованную исходную историю и изменения. При необходимости
эталонный SQL-аудит среза строится доверенной инфраструктурой независимо
от сгенерированного Script, но не заменяет исполнение метода.

Сохранить teacher-подготовку №32, trace, sticky ERROR после общего catch/
rollback, TIMEOUT, invalid_test и unavailablePoints. Следующий критерий
и отдельный запуск после отказа выполняются успешно. Credentials, сети
и контейнеры очищаются; публичные пакеты сохраняют действующий контракт.

### 4. Переносимость и независимая приёмка

Обязательны два самостоятельных проекта с другими именами/namespace:
оба с периодичностью День, один с несколькими измерениями, ресурсами и
реквизитами. Проверить import aliases, исходную зависимость, несколько
owners, одинаковые UUID разных ссылочных типов и nullable-группу.

Для нового общего контракта получить PASS, контролируемый FAIL через SBSL
и объяснимый UNSUPPORTED. Нужны независимые случаи:

- Нет строк, одна/несколько дат, даты до/на/после границы, будущая запись,
  пустая дата по подтверждённой семантике, отсутствующий искомый товар.
- Не менее двух поставщиков и двух товаров; последняя дата для каждого
  полного ключа различна, самая дорогая цена не обязательно последняя.
- Отбор ресурса после формирования среза, сохранение прочих ресурсов/
  реквизитов и nullable-поля; последний ряд не удовлетворяет условию,
  более ранний удовлетворяет — ранний ряд не становится ответом среза.
- Сортировка Дата и ПЕРВЫЕ после формирования/отбора; отсутствие скрытой
  гарантии при одинаковых ключах (точный real-ответ использует разные даты).
- Повтор Выполнить после записи/замещения и rollback; параметры с эффектом
  вычисляются один раз, прежний результат и вложенные ссылки независимы.
- Валидные мутации: пропуск измерения группы, неверная граница/строгое
  сравнение, глобальный максимум, ранняя фильтрация, неверный ресурс,
  сортировка/лимит, устаревшее чтение и смешение owners дают FAIL.

Реальный метод выполняется без изменения xdump и без mocks: сравниваются
его цена/Неопределено и независимое состояние истории. Отдельно доказать,
что чтение не изменило историю и не вызвало SQL-публикацию. В batch две
работы с одинаковыми UUID изолированы; мутация только одной меняет только
её оценку. Прежние mocks, legacy остатки, №29–32 и максимумы сохраняются.

## Отчёт о реализации

Реализовано 2 октября 2026 года. Общий `StorageQuery` расширен источником
`slice-last` и контрактом `storage-slice-last-day-v1`. Planner сохраняет owner,
периодичность, все измерения, типы, диапазоны источника/даты/параметров и backend.
Renderer генерирует общий алгоритм Script: актуальные наборы разрешённого owner,
включительная граница, максимум периода по полному ключу, затем ГДЕ, сортировка,
ПЕРВЫЕ и проекция. Teacher expected и строки истории не входят в IR.

Параметры вычисляются исходными зависимостями при создании запроса; одна дата,
используемая в границе и ГДЕ, занимает один captured slot. Nullable-ссылка
сравнивается с заполненным параметром точного типа. Старые результаты и
вложенные ссылки независимы от нового чтения, замещения и rollback. Чтение
видит записи обработчиков до commit и само не публикует SQL.

### Семантика и ограничения

Официальная страница 9.1 проверена в браузере; URL 9.0 возвращает 404.
Доверенные Docker-пробы `-c 9.0` подтвердили Дата, структурное сравнение ссылок,
nullable-равенство с заполненным параметром и порядок фиксации аргументов.
Native Запрос отсутствует. Пустой аргумент и явное Неопределено в **объявленном
адаптере** фиксируют текущую дату UTC из Docker при создании запроса; будущее
исключается. Независимые Docker-clock снимки сохранены. Платформенное поведение
будущих строк не выдаётся за native-подтверждённое.

СрезПервых, другие периодичности, дополнительные аргументы, обычный источник
регистра, JOIN, ЗАПОЛНИТЬ, агрегаты, вычисляемые поля, union-поля и прочий
NULL-API остаются UNSUPPORTED. Сохраняются ограничения универсальной компоновки
и набора №32. Полный [контракт](../storage-backed-information-register-slices.md)
разделяет документированный API, native-пробы и выбор адаптера.
