# Отчеты, навигация и панель: runtime-контракты v1

Этап №51 добавляет поля существующего `type: runtime`: `report`, `navigation`
и `panel`. Они взаимоисключающие с методным `target`, `interface`, `querySource`
и `formRequirement`. Ожидания задаются автором отдельно, сравнение и баллы остаются
в SBSL. Файлы проверяемого проекта открываются только на чтение.

## Отчет

```yaml
type: runtime
report:
  schemaVersion: 1
  report: {name: Summary, namespace: Sales}
storage: {registers: [], initial: []}
reportActions:
  - {operation: execute}
```

Селектор принимает `name`, опциональные `namespace`, `sourceHash` и
`projectSourceHash`. Устаревшие hashes и неоднозначные имена отклоняются.
`reportActions` принимает 1–40 действий `execute` или `write` с `objects` и/или
`registers`, аналогично query entry №47; обязательно хотя бы одно исполнение.
По умолчанию выполняется одно `execute`. Запись использует существующий storage;
следующее исполнение заново читает данные. Результат:

```json
{"result":{"actions":[{"data":[],"values":[],"layout":{"fields":[],"display":"СводнаяТаблица","hierarchy":[]},"cardinality":0}]},"storage":[]}
```

`data` — типизированные строки запроса до сортировки макета; `values` — значения
используемых полей макета, ключом служит исходный Ид. `layout.fields` отдельно
сохраняет выражения, типы, подписи, роли, использование и направление сортировки.
`hierarchy` перечисляет поля с ролью Иерархия, без построения дерева платформы.

`ВидИсточникаДанных: Запрос` выбирает оригинальный одноименный `.xbql`.
`queryParameters` использует типизированные входы №47. `Таблица` (также значение
по умолчанию) преобразует объявленный `ИсточникДанных` в общий query AST,
не создает фиктивный исходный метод. IR помечает такой вход `metadata-table`,
хранит исходный YAML hash/позицию и сгенерированный запрос отдельно от декларации.
Поддержаны обычные таблицы, история РС, остатки/движения РН в пределах общего query
контракта. Источники по-прежнему разрешаются в области видимости отчета; явно
указанные fixture-регистры инициализируются в области собственной декларации.

Формулы имеют **отдельный язык**, не XBSL-привязки. Поддержаны имена полей,
один член ссылки (`Recorder.Number`), числа, строки, скобки, `+ - * /`, сравнения,
`ЕСЛИ(condition, yes, no)` и платформенная `ССЫЛКА` для вида записи РН.
ЕСЛИ исполняет только выбранную ветвь; разные типы ветвей образуют union.
Конкатенация строки и числа выполняется в Script. Сравнение nullable по порядку
требует отдельного контракта; равенство nullable поддержано. Nullable-арифметика и
конкатенация возвращают Неопределено при отсутствующем операнде.

Внутренние имена Number/Date/Period/Recorder/RecordKind и суффикс Balance
сопоставляются с системными полями Номер/Дата/Период/Регистратор/ВидЗаписи/Остаток;
произвольные бизнес-имена не зашиты в код. Неоднозначный alias отклоняется.
Union-регистратор читается по конкретному типу в полном ключе набора; член ссылки
загружает свежий документ из storage. Отсутствующий документ — UNSUPPORTED.

Сортировка макета стабильная, в порядке объявления сортируемых полей.
Неопределено идет первым при возрастании и последним при убывании. Enum сортируется
по объявленному порядку, ссылка — по стабильному идентификатору. Это модельная
семантика, не сортировка по native-представлению ссылки.

## Навигация

```yaml
navigation:
  schemaVersion: 1
  navigation: {name: Menu, namespace: Sales}
navigationContext: {ShowReports: true}
navigationActions:
  - {operation: resolve}
  - operation: open
    selector: {owner: "Sales::Summary", surface: АвтоматическаяФорма}
```

Вход выбирает `ФрагментКомандногоИнтерфейса` или стандартное клиентское приложение
с разделами. Группы и ссылки `=Fragment` рекурсивно раскрываются с учетом импортов,
полного owner и области видимости; циклы и неоднозначность недоступны. Идентичность
маршрута включает конкретное вхождение ссылки, позицию команды и цепочку разделов.

Видимость/доступность наследуется от родителей. Поддержаны Булево,
Истина/Ложь и `=Name` явно заданного boolean-контекста. Более сложные выражения
недоступны. `resolve` возвращает маршруты и разделы. `open.selector` принимает
id/owner/surface/caption/name и должен выбрать один маршрут. Результат
`opened-model` или `blocked`; закрытая команда не открывает поверхность.

Поддержаны объявленные формы/приложения, автоматические списки/карточки
справочников и документов, автоматические формы отчетов и панелей, две встроенные
поверхности управления удалением и консоли запросов. Встроенные имена
не подменяют проектное объявление. Открытие модели сохраняет целевой owner и
поверхность; не запускает обработчики формы и не заявляет результат DOM.

## Панель

```yaml
panel:
  schemaVersion: 1
  panel: {name: Dashboard, namespace: Sales}
  parameters: {} # optional: qualified report owner -> queryParameters
storage: {registers: [], initial: []}
clock: {mode: fixed, date: "2026-10-11", time: "12:00:00", timezone: UTC}
executorLocale: en-US
timers: {onClose: cancel, maxEvents: 1000}
panelActions:
  - {advanceTime: 29999}
  - {advanceTime: 1}
  - {closeTimers: true}
```

Виджеты `Вид: Отчет` разрешаются по ссылке без веток по имени панели/отчета.
Ид должны быть уникальны; расположение проверяет ссылки, X/Y и размеры.
Имена устройств и исходные настройки расположения сохраняются отдельно от данных.
Один Script-контекст storage используется всеми отчетами, вместе с независимым
PostgreSQL-аудитом при выборе соответствующего backend.

После начального чтения `revision=1`. `refresh` заново читает все виджеты;
`write` меняет storage, сохраняя последний видимый снимок до обновления.
`advanceTime`, `timerEvent: next` и `closeTimers: true` используют очередь №48.
Включенное автоматическое обновление требует фиксированные часы, locale и timers.
Интервал берется из декларации; поддержаны миллисекунда, секунда и минута.
Для 30 секунд первое событие наступает ровно на 30000 мс. Политика fixed-rate
исполняет все наступившие события в порядке очереди, с общим maxEvents.
Завершение отменяет таймеры. Наблюдения actions/events сохраняют revision,
данные каждого виджета, часы и состояние таймеров на каждой границе.

## Границы

Макет поддерживает поля вида Измерение и роли Строки/Колонки/Иерархия.
Сводный DOM, группировка/агрегация native pivot, развертывание иерархии,
визуальное расположение и платформенное поведение встроенных форм — внешняя
граница. Неизвестные функции/источники, union-сортировка, сложные условия
навигации и внешняя транзакция панели возвращают UNSUPPORTED. Принятие схемы,
план, генерация и фактическое исполнение имеют раздельные статусы в IR.

Схемы: [report](report-options-v1.schema.json),
[navigation](navigation-options-v1.schema.json), [panel](panel-options-v1.schema.json).
Новые публичные значения YAML `type`, бизнес-задания и expected дампа не добавлены.
