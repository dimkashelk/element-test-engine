# Ночные тесты форм всех дампов

Зафиксированы 303 UI-декларации пяти проектов из четырёх предоставленных
архивов, включая отдельный проект библиотеки `e1c::БазаЗнаний`. Manifest хранит
выбор проекта, SHA-256 архива, sourceHash и полный список форм. Добавленная или
исчезнувшая форма, отсутствующий дамп и несовпадение эталона дают ошибку.

Для каждой формы unittest discovery создаёт отдельный именованный тест.
Архив извлекается один раз на проект; временные исходники очищаются через
class cleanup. Docker запускает значения YAML-привязок; SBSL сравнивает
наблюдения и начисляет баллы. Непредусмотренный ERROR/UNSUPPORTED/FAIL делает
ночной тест неуспешным, следующий тест продолжает работу.

| Проект | Формы / снимки деклараций | Сценарии runtime значений | Дополнительные структурные критерии |
|---|---:|---:|---:|
| ДемоСРМ | 28 | 3 | 0 |
| Движок | 16 | 159 | 326 |
| Примеры_new | 177 | 100 | 0 |
| check | 24 | 46 | 0 |
| БазаЗнаний | 58 | 4 | 0 |
| Всего | 303 | 312 | 326 |

Каждый тест сравнивает полный замороженный снимок YAML-декларации и сигнатуры
собственного модуля. Таким образом проверяются поля, типы, defaults, компоненты,
размещение, текст привязок, ссылки команд и обработчиков. Это регрессия
фиксированных эталонов: точное совпадение дерева/имён здесь намеренно. Такой
снимок нельзя использовать как универсальный критерий для студенческой формы,
в которой описание разрешает другие имена, порядок или эквивалентное выражение.

Для Движка повторно используются независимые требования №38 целиком — 485
критериев. Для остальных проектов заранее составлены 153 сценария исполнения
135 привязок к собственным полям или строкам ближайшей таблицы. Fixtures
содержат пустые/непустые строки и массивы, разные маркеры однотипных полей,
булевы состояния, дроби, nullable/enum и повторные строки. Ожидаемые значения
выведены из отдельного требования к пути данных; исходная форма не исполняется
для получения expected. Контекст меняется между снимками в живой Script-сессии;
read-only записи констант проверяются отдельными fixtures.

Остальные 1799 вхождений выражений вне Движка зафиксированы только в снимке
декларации, с индивидуальным `NOT_CHECKED` и причиной в `unavailable`. Среди них
встроенные команды, стили, динамические списки/деревья, свойства и методы
платформы, вызовы исходных обработчиков и другие неподдержанные этим адаптером
вычисления. Декларативный PASS не означает проверки их поведения или browser UI.
Полная функциональная оценка всех 303 форм остаётся расширением адаптеров.

`build.py` — офлайн authoring, читает неизменные эталоны и замораживает fixtures.
При запуске nightly генератор не вызывается и baseline не обновляется. После
изменения требований их нужно пересмотреть отдельно; подмена ответов фактом
упавшего запуска запрещена. Отрицательный тест подтверждает SBSL FAIL для
изменённой декларации. Другой тест готовит все 153 новых типизированных плана.

Существующее ночное `unittest discover` автоматически включает
`test_all_dump_forms.py` с `ELEMENT_TEST_DOCKER_TESTS=1`. Оно выполняет 303
проверки форм, 3 проверки авторинга/подключения; суммарно формы дают 941 критерия
SBSL (снимки + критерии структуры + runtime). При выключенном Docker ночные
формы явно skipped; строгий nightly runner не считает такой прогон зелёным.
Расписание и лимиты не менялись.

Результаты каждой формы: `result/all-dump-forms/nightly/<project>/<form>/`:
`result.json`, `coverage.json`, наблюдения и execution plans. Утренняя сводка
показывает число завершённых/прошедших/упавших форм и границы runtime-покрытия.
`result/all-dump-forms/prepared-coverage.json` — подготовленное покрытие,
не доказательство исполнения всего набора.

Локально проверены авторинг/CI и пять выбранных форм — по одной на проект.
Все 303 формы локально не исполнялись; полный запуск выполняет nightly на
отправленном в основную ветку коммите.
